# Frontend журнала сделок (SPA)

SPA нового интерфейса журнала: React 19 + TypeScript на Vite, Tailwind CSS 4,
shadcn/ui (lucide-react), react-router, TanStack Query. Стек зафиксирован в
[ADR-0010](../docs/adr/0010-frontend-spa-react-stack.md).

## Команды

- `npm run dev` — dev-сервер Vite (порт 5173, префикс `/spa/`).
- `npm run build` — сборка в `dist/` (проверка типов + Vite).
- `npm test` — юнит-тесты vitest (однократный прогон).
- `npm run preview` — локальный просмотр собранного `dist/`.

## Запуск в Rider

Общие конфигурации запуска хранятся в `.run/` в корне репозитория.
Откройте `TransactionJournal.sln`, выберите **Transaction Journal (API + React)**
и нажмите **Run**. Конфигурация собирает .NET-решение и запускает два процесса:
**Backend API** (профиль `spa`, HTTP `http://localhost:5019`, без отдельного окна
браузера) и **Frontend React** (`npm run dev -- --open /spa/`).
Vite открывает приложение в браузере по адресу `http://localhost:5173/spa/`.
Оба процесса доступны в отдельных вкладках Run; останавливайте оба при завершении.

Для первого запуска необходимы .NET SDK 9 и Node.js версии не ниже 22.12.
В настройках Rider выберите установленный Node.js как интерпретатор проекта.
Если зависимости frontend ещё не установлены, выполните `npm ci` в `frontend`.

Dev-сервер проксирует `/api/*` в backend на порту 5019 без изменения пути:
React использует тот же относительный API `/api/v1`, что и в собранном приложении,
включая потоковые ответы SSE. Порт Vite фиксирован на 5173; если он занят,
запуск завершается ошибкой вместо незаметного перехода на другой адрес.
Профили `http` и `https` по-прежнему запускают только .NET-хост.

## Раздача статики

Собранный `dist/` раздаёт существующий .NET-хост (`src/TransactionJournal`) по
префиксу `/spa`, пока Blazor-UI продолжает работать в корне. Сборка:

```powershell
npm run build          # здесь: обновляет frontend/dist
dotnet build ..\TransactionJournal.sln
```

## Каркас

Раскладка — «тонкий топбар + сворачиваемая левая панель» с пятью разделами
(Конструкции, Входящие, Подсказки, Агент, Синхронизация) по концепции
[concept.md §2](../.wf-research/ui-concept/concept.md). Разделы пока
заглушки-роуты; единый конфиг разделов — `src/config/sections.ts`.

## Слой форматирования

Единые форматы и контракты показа величин для всех разделов —
`src/lib/format/`:

- `plural.ts` — русские формы числительных (`pluralForm`, `formatCount`):
  «1 конструкция / 2 конструкции / 5 конструкций», «открыта / открыты / открыто».
- `quantity.ts` — величины: знаковые суммы USDT («+214.32» / «-58.2» / «0»),
  проценты («+8.6%»), абсолютные суммы («3000»).
- `degradation.ts` — сквозной паттерн сбоя котировок: `degrade(...)` возвращает
  текст величины либо прочерк «—» с причиной «сбой котировок»; контракт
  «нет данных ≠ ноль» — ноль остаётся нулём.
- `display-time.ts` — моменты в зоне браузера: «2026-06-20 14:30» и
  календарный день «2026-06-20»; отсутствующее значение — прочерк.
