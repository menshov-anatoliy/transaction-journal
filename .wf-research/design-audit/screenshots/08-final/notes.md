# Финальная сверка 8.3 — reconcile-frontend-with-design

## Повторная попытка MCP-приёмки 09.10.2026 после 10:54

Настоящий backend подготовлен владельцем и доступен через Vite.
MCP Browser сначала восстановился: выполнен живой просмотр каркаса,
карточки конструкции 16 (шапка, позиции/сделки, закрывающие записи
и пустая таблица корректировок), наполненных подсказок, синхронизации
и каталога правил с выбранной правой карточкой. Макеты этих экранов
повторно просмотрены через `TakeScreenshot` MCP Pen.

В настоящих шести чатах API возвращает только пользовательское
сообщение, без ответа ассистента и следа источников. Входящие пусты
даже при расширении периода до 2020 года. Владелец отдельно разрешил
синтетические ответы чата и тестовые входящие сделки исключительно
для визуальной сверки в браузере, без изменения backend или БД.
Другие экраны используют настоящие данные.

При повторной съёмке списка конструкций после горизонтальной
прокрутки MCP Browser снова заблокировался: `return-screenshot`
вернул timeout, следующая попытка — `A capture is already running`.
Поддержанный `Page.captureScreenshot` через MCP CDP тоже вернул
тот же lock. Поэтому MCP-просмотр согласованных синтетических
состояний чата и входящих не выполнен и задача **8.3 не закрыта**.
Локальные пары не заменяют обязательную MCP-приёмку.

Команды синхронизации, отправки сообщений, привязки сделок,
пересбора и удаления не нажимались. Для дальнейшего просмотра
карточки включалась браузерная блокировка не-GET запросов, включая
автоматическую отметку первого показа подсказки; серверный код
и настройки приложения не изменялись. Маскированный ключ в UI
синхронизации не раскрывался.

## Результаты трёх исправлений

### Компактный индикатор

`00-layout` и `01-constructions`: **все четыре** `[data-slot="fin-result-compact"]`
имеют computed `width="132px"` и `rect.width=132`, класс
`relative w-[132px]`. Состояние 112px больше не присутствует.
01 отдельно показывает положительный, нулевой, отрицательный и
вышецелевой результат. Отрицательный нереализованный сегмент:
**#EFB6AE** (`rgb(239,182,174)`).

### Статусы конструкций

В таблице 00/01 и шапке 02 реально присутствует `data-slot="status-chip"`,
а не отдельный plain-text статус. Открыта: фон **#E2F4EB**, текст
**#167853** (pos); закрыта: фон **#EFEFEA**, текст **#66666E** (neutral).
Точечное чтение нового `ConstructionStatusChip` подтверждает единый
mapping open/closed/archived → pos/neutral/muted. В этих desktop fixtures
архивная конструкция и мобильный список не показаны; runtime-подтверждение
для них не заявляется.

### След источников и кэш

На **обоих** экранах 03/04 при той же ширине 1440 CSS px:

| Объект | clientWidth | scrollWidth / фактическая ширина |
|---|---:|---:|
| Панель источников | 278 | 278 |
| Список инструментов | 254 | 254 |
| Список ссылок | 254 | 254 |
| Рыночный SourceChip | 252 | scrollWidth 252; border-box 254 при available 254 |
| Чип правила | 164 | border-box 165,5625 при available 166 |

`кэш`: **entirelyVisible=true**; bounds около x=809,625…840,594 внутри
панели x=665…943; текст полностью виден в PNG. Risk/riskSoft:
**#DFA23B / #F9EFD9**. `li` — `min-w-0 max-w-full`, SourceChip —
`max-w-full whitespace-normal`, внутренний span —
`min-w-0 [overflow-wrap:anywhere]`. Исходный дефект 278/394 устранён.

Это не утверждение об отсутствии любого overflow во всём DOM:
в computed 03/04 техническая обёртка `overflow-hidden` имеет 342/346
(4px). Она не создаёт горизонтальную прокрутку панели источников и не
скрывает «кэш»; видимый дефект прежней съёмки не воспроизводится.
Горизонтальная прокрутка широких доменных таблиц 00/01/02/05 ожидаема.

## Единственный сохраняющийся блокер: MCP Browser

После `get_app_state` выполнена поддержанная повторная `load-page`
на `/spa/` — успешно. `return-screenshot` по query `#root` снова
вернул `MCP error -32603: A capture is already running`.
Немутирующий CDP `Runtime.evaluate(document.title)` через MCP тоже
вернул тот же capture lock. Доступного поддержанного reset/cancel
интерфейса в инструментах нет; скрытого убийства чужих процессов,
правок `.pen` и бесконечных повторов не было.

Дизайн читается через MCP Pen, но обязательный live MCP Browser
просмотр всех страниц **не выполнен**. Локальные Chrome/CDP снимки
служат свежим evidence исправлений, а не заменой этого acceptance
criterion. Поэтому 8.3 не закрыта.

**Адрес `/spa/constructions` не является блокером change.** Штатный
маршрут списка — индекс `/spa/`; именно он снят в 00/01. Добавление
несуществующего alias не требуется и в этой проверке не предлагалось.

## Допустимые различия и границы проверки

Критерий сверки — token/component parity, не pixel-perfect macro layout.
Названия, суммы, даты, статусы, состав и ширины доменных колонок исходят
из API, не копируются из статичного мастера. Новый чат, текущая лента и
история отображаются одновременно; у правил сохраняется правая панель.
В синхронизации сохраняются reset linear/option, нативный backup checkbox,
доменные колонки и предупреждения запуска. Это не новые расхождения.
Активный NavItem и badge сохраняют ранее подтверждённые MCP пары цветов.
`journal/ETH` — **Inter 11px**; h1 — **Inter 21px/600**.
Исключение подписи сверхприбыли **#8a6a1f** остаётся backlog **issue:#73**.

`openspec validate reconcile-frontend-with-design --strict` — **exit 0**,
`Change 'reconcile-frontend-with-design' is valid`, сохранено в
`validation.txt`. CLI проверяет артефакты, не визуальную приёмку.
4 file / 28 tests и build — предоставленный владельцем успешный контекст;
эта evidence-сессия их не запускала и не выдаёт за собственный результат.
Исходные specs и их IDs не редактировались; traceability применена только
к смыслу доказательств ниже.
