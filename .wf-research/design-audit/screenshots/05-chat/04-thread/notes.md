# Скриншот-сверка 5.2 — Body #4: ToolStatus в ленте и след источников (SourceChip)

Приёмка задачи 5.2 change `reconcile-frontend-with-design` по процессу
design.md D3: пара «макет/страница» для Body #4 «Лента чата» (LYsBg,
1600×1066) по расхождениям §3.5:4 (Tool-статус) и §3.5:5 (след источников)
аудита. Сообщения и композер (§3.5:1–3) приняты парой задачи 5.1
(`screenshots/05-chat/` — корень).

Процесс: макет — экспорт ноды `LYsBg` из design.pen через MCP pen
(`Export` png 2×) + `Get` по нодам ix8ma/tMmi0/bUrOy/peflp/fYadZ; страница —
Vite dev-сервер (5173, прокси /api/v1 → 5019) с мок-бэкендом (история
U1/A1 со следом: 2 инструмента + карточка правила + запись журнала),
headless Chrome 1600×1066 через CDP: ввод в композер нативным сеттером,
отправка (мок-SSE держит канал открытым — ход «выполняется»), снятие
computed-стилей зон сверки и PNG. Объективная проверка — пиксельный
сэмплинг точных цветов токенов.

Отклонение от текста аудита §3.5:5: прямой чит мастера показывает след
источников панелью со строками «иконка + зелёный текст», а не набором
чипов; «чипы pill 999» аудита — применим к вызванным инструментам, у
мастера bUrOy статично не отображаемым. Решение: контейнер и строки —
по мастеру bUrOy; инструменты — SourceChip (fYadZ) как задача и требовала.

## Решение по ToolStatus (§3.5:4): где и почему

Транспорт SSE (задача 2.3) несёт только start/token/done/error — live-событий
прогресса tool-вызовов нет, отдельных мест индикации tool-вызова в коде
не существует (греп по tool в ленте давал только статичный след). Поэтому
пилюля интегрирована в ленту (`agent-chat-thread.tsx`) на весь ход
генерации `chat.isRunning` с единым текстом «источники — собираю данные
для ответа…»: по макету Tool2 стоит в потоке сообщений во время хода —
место и состояние совпадают; имя конкретного инструмента займёт текст
пилюли с появлением tool-прогресса в SSE. Статичных состояний «готово/
ошибка» у мастера нет — примитив их не имеет (2.3).
