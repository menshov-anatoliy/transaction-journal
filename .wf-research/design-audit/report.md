# Инвентаризация расхождений: дизайн design.pen ↔ frontend SPA

Дата: 2026-10-08. Назначение: фактовая база для grill-сессии и OpenSpec-change с пер-страничными тасками (карта #50 «Концептуально новый frontend журнала сделок»).

## 1. Методология и ограничения

**Источник истины по дизайну** — только `design-extract.json` (90 КБ), извлечённый из `design.pen` через MCP pen (execute). Файл `design.pen` напрямую не парсился (JSON-парсинг .pen запрещён; MCP pen в этой сессии недоступен). Экстракт содержит:

- `variables` — 24 дизайн-токена: 23 цвета + шрифт Inter (см. §4);
- `topLevelNodes` — дерево верхнего уровня (46 нод): каркас, 8 пар «Топбар (ref) + Body», библиотечные фреймы;
- `topLevelReusableComponents` — 8 топ-уровневых reusable-компонентов (всего в файле заявлено 26);
- `screens` — по каждому экрану: используемые refs-компоненты с числом вхождений, агрегатная статистика fills/textFills/fonts/gaps/paddings/radii со ссылками на токены `$...`, счётчики нод по типам.

**Ограничения метода**:

1. Экстракт даёт только агрегаты по экрану — внутренности reusable-компонентов (Нав-пункт, Кнопка/*, Чип/*, Метрика, Карточка подсказки, Сообщение/*, Композер/Агент, Панель чатов, Топбар) недоступны; для них сравнение — по контексту вхождениям, точная геометрия требует скриншот-проверки (§7).
2. Frontend анализировался статически по `frontend/src` (код не запускался, скриншотов кода нет). Сравнение стилей — по именам Tailwind-классов и CSS-переменных; численные соответствия oklch↔hex проверены только для блока `--fin-*` (там значения hex скопированы 1:1).
3. Карта «экран → маршрут» построена по составу refs и решениям `.wf-research/ui-concept/concept.md` (разделы §2–§10) и `.wf-research/ui-inventory/inventory.md` (карта переноса №1–№29).
4. Стек frontend: React 19 + Vite + Tailwind CSS 4 (CSS-first, `frontend/src/index.css`), shadcn/ui new-york (`frontend/components.json`), lucide-иконки. Отдельного `tailwind.config.*` нет — тема целиком в `index.css`.
5. В отчёте «экран Body N» означает пару «Топбар (ref id) + Body (id)» из `topLevelNodes`.

## 3. Пер-страничные расхождения

Формат: пункт расхождения; ссылка на код (`файл:строка`); ссылка на дизайн (имя экрана/фрейма из экстракта).

### 3.1 Каркас → `AppLayout.tsx`

1. **Высота топбара**: `h-14` = 56px, `px-4` = 16 (`AppLayout.tsx:71`) — дизайн «Каркас» g0z20: паддинг топбара `[0,24]`, фрейм TopBar IdwN5 h=52, `[0,16]`; бренд 14/600. В коде бренд `text-base` (16px) — в дизайне 14/600 (шрифт «Каркас»: `$font 14/600 ×1`).
2. **Нав-пункт**: `text-sm` (14px), `rounded-lg` (12px), `h-10`, `px-3`, hover `bg-accent` — индиго-оттенок (`AppLayout.tsx:41-49`; `--accent: oklch(0.945 0.018 263)`, `index.css:24`) — дизайн: Нав-пункт с паддингом `[8,10]`, шрифт 11.5/normal, радиус 8; активный пункт — `$accentSoft`/`$accentStrong` (тёплая зелёная пара #E2F4EB/#167853), в `fills` «Каркаса»: `$accentSoft 1`, `$accentStrong 1`.
3. **Ширина панели**: развёрнутая `w-64` (256px) / свёрнутая `w-[4.25rem]` (68px) (`AppLayout.tsx:35`) — в экстракте ширина Панель/Навигация не содержится; сверяемость — визуальная проверка.
4. **Бейдж «Входящие»**: `bg-primary/15 text-primary` — индиго (`AppLayout.tsx:58`) — в дизайне счётчики/чипы строятся на зелёной паре `accentSoft`/`accentStrong` (токены `$accentSoft`, `$accentStrong`; «Карточки» sUDDX: `$accentStrong ×2` в textFills).
5. Мобильные оверлеи `bg-black/40` (`AppLayout.tsx:96` и др.) — в дизайне тёмных оверлеев нет (дизайн статичен, 1440×620).

### 3.2 Body #1 «Конструкции» (X2ic2p) → `constructions-page.tsx` + таблица

## 6. Корневая причина и порядок исправления

**Корневая причина**: frontend строился по текстовой концепции (`ui-concept/concept.md` §1: «светлая воздушная… сдержанный акцент») до появления `design.pen`-системы. Тема `index.css` — самостоятельная shadcn-палитра (индиго, oklch), а не перенос `variables`; библиотека примитивов не создавалась, общие элементы пишутся инлайн на страницах. Единственный блок, писавшийся с открытым макетом, — индикатор финрезультата (`--fin-*` 1:1, пресеты с id дизайн-нод) — он и совпадает с дизайном лучше всего. Это подтверждает: расхождения не «точечные огрехи переноса», а **отсутствие механики переноса вообще** (нет токен-слоя → нет компонентного слоя → каждая страница дрейфует сама).

**Число страниц с расхождениями: 9 из 9** (каркас + 8 маршрутов); страница `/Error` вне дизайна и не считалась.

**Рекомендуемый порядок (каждый уровень блокирует следующий):**

1. **Токены** — перенести 24 `variables` в `index.css` (`@theme`/CSS-переменные: фоновая триада, границы, 3 текстовых, зелёный акцент ×4, risk/neg/info пары) и подключить Inter (+JetBrains Mono для редактора). Блокирует всё: пока акцент индиго, любой компонент будет расходиться.

3. **Каркас** — `AppLayout`: топбар 52px/px-24, бренд 14/600, активный пункт accentSoft/accentStrong, бейдж на токенах.
4. **Таблицы** — общий слой таблиц с дизайн-геометрией ячеек (поэкранные паддинги 9/10, 7/12, 8/10, 6/12; шрифт 12/11.5); заменить сырую таблицу `inbox-page.tsx:316` на общий компонент.

## 8. Сводка

- **Корневая причина**: перенос дизайна не был механизмом — тема и компоненты писались из текстовой концепции до фиксации `design.pen`; токен-слой (24 переменные) не перенесён (7/24, все внутри фининдикатора), компонентная библиотека (26 reusable) не создана (5 отсутствуют, ~10 инлайн).
- **Страниц с расхождениями: 9 из 9** сопоставленных экранов; при этом функциональный состав (маршруты, данные, состояния) соответствует концепции — расхождения сосредоточены в стилевом/примитивном слое.
- **Топ-5 системных проблем**:
  1. Нет дизайн-токенов: основная тема — shadcn oklch с индиго-акцентом (hue 263) вместо зелёного `accent #1FA36B` + тёплой серой гаммы; risk/info/negSoft/accentSoft пары отсутствуют.
  2. Не подключён Inter (и JetBrains Mono): системный шрифт; базовый кегль 14px против дизайн-диапазона 10–13.5px, титулы 24 vs 21.
  3. Нет библиотеки примитивов: Чип/Статус, Чип/Источник, Метрика, Сессия/пункт, Tool-статус отсутствуют; общие сущности дублируются инлайн по страницам.
  4. Чужеродные стили: `@uiw/react-md-editor` (свой CSS) в MD-редакторе, Tailwind-`amber` вместо risk-пары, индиго-пузырь пользовательского сообщения вместо surface2, шадсн-красный destructive вместо `$neg`.
  5. Геометрия не перенесена: ячейки таблиц p-2/8px против поэкранных [9,10]/[8,10]/[7,12]/[6,12]; радиусы чата 16px против 7–12; кнопки 10px против 8; топбар 56/px-16 против 52/px-24.
