Статус: согласовывается с владельцем.

## 1. Рамка и принципы

- SPA (React 19 + TypeScript, Vite; shadcn/ui + Tailwind CSS 4; assistant-ui для чата; TanStack Query/Table; react-markdown + remark-gfm; Recharts) поверх нового HTTP API существующего .NET-приложения. ADR фиксируется в тикете декомпозиции (#57).
- **Один контур frontend** для desktop и mobile: адаптив через брейкпоинты и варианты компонентов, без отдельного мобильного бандла.
- **Мобильная стратегия — «просмотр + лёгкие действия»**: мониторинг (списки, карточка чтение), чат, подсказки, сводки доступны с телефона; тяжёлые операции (разбор входящих, пересбор, сброс категории, правки пометок/корректировок) — desktop.
- **Живость данных**: списки и панели обновляются автоматически после мутаций и фоновых изменений (единый серверный канал событий; транспорт фиксирует API-контракт). Ручное «Обновите экран» уходит.
- **Светлая тема единственная** (референс: светлый воздушный agents-space, сдержанный акцент, крупные отступы). Тёмная — после паритета, если потребуется.
- Времена отображаются в часовом поясе **браузера**.
- Даты/время во всех формах — нативные пикеры (не текстовый ввод формата).
- Состояние экранов: фильтры и выбор — в URL/query (переживают перезагрузку и ссылку); геометрия панелей каркаса (ширины, свёрнутость) — локальное состояние браузера.

  1. **Конструкции**
  2. **Входящие** — бейдж числа непривязанных сделок (пустой/ошибка — бейджа нет)
  3. **Подсказки**
  4. **Агент** (подтабы «Чаты», «Правила»; резерв «Сводки» — change add-summary-channels)

## 4. Карточка конструкции (маршрут `/constructions/{id}`)

Полная информация и всё управление (паритет функций №3–№9). Отдельный маршрут — открывается вкладкой или новым окном.

- **Шапка**: имя, статус, меню **«Параметры»** (капитал / риск / профит; пустое сохранение капитала убирает, 0 легитимен; риск/профит — одна единица, эхо-пересчёт второй, оба пустых = убрать), действия — переименовать, закрыть/открыть, архив/возврат из архива (возврат восстанавливает «закрыта»), удалить пустую (подтверждение + флажок бэкапа, включён). Отказы домена — причиной у действия. Под заголовком — **Meta-строка** введённых значений: плановый риск · плановый профит · реальный риск со статусом · капитал · дата открытия.

## 5. Раздел «Входящие» — страница разбора (маршрут `/inbox`)

Отдельная страница; список конструкций не затрагивает. Основной сценарий — наглядное распределение непривязанных сделок между существующими конструкциями.

- **Фильтры**: диапазон дат (пикеры; дефолт — скользящий последний месяц), инструменты (панель чекбоксов, «N из M», «Выбрать все», закрытие по клику вне), направление (два чекбокса). Состояние фильтров — в URL.
- **Таблица непривязанных сделок**: выбор чекбоксами (в т. ч. массовый по видимым); скрытое фильтрами исключается из выбора.
- **Список конструкций-целей** (компактный: имя, статус, итог) — подсветка при drag-надаче.
- **Действия**: «Привязать N → [конструкция]» (клик по цели или кнопка; массовая привязка атомарна) и **drag&drop** выбранных сделок на цель как ускоритель поверх кнопок; «Создать конструкцию из выбранного» (имя обязательно, капитал опционально; стартует «открыта»).
- Кнопка **«Собрать из "Входящих"»** (безопасная инкрементная сборка, без подтверждения).
- Состояния: чтение / недоступен / «Входящие пусты» / «по фильтрам ничего не найдено».
- Mobile: просмотр списка без действий распределения (desktop-операция).

## 6. Раздел «Подсказки» (маршрут `/hints`)

Журнал всех подсказок всех субъектов, read-only: фильтры статус/группа/характер (группа сужает характеры), сброс фильтров; карточки без кнопок мутации; различает «записей нет» и «по фильтру записей нет».

## 7. Раздел «Агент» (маршрут `/agent`)

Единый центр работы с контекстом ИИ-помощника. Подтабы: **«Чаты»**, **«Правила»**; резерв — «Сводки» (появится с change add-summary-channels).

### Чаты (по референсу agents-space)
- Список сессий: **«Активные» / «Завершённые»**, «+ Новый чат».
- **Форма нового чата**: ИИ-модель (дефолт `GLM-5.3`), конструкция (опционально, фиксируется при создании), источники данных — закрытый справочник «журнал / корпус правил / рынок Bybit» (дефолт — все три). Чат создаётся первым сообщением.
- **Чат**: стриминг ответа с tool-статусами и отменой генерации; MD-рендер сообщений; смена модели на лету (новые сообщения — выбранной модели); продолжение завершённого возвращает в активные; удаление целиком с подтверждением.
- **След источников** в ответе: использованные инструменты, ссылки на карточки правил и данные журнала с as-of; рендер ссылок.
- **Пустое состояние**: карточки-подсказки (что спросить, как подключить источники) по референсу.

### Правила (каталог корпуса, только чтение)
- Фильтры: характер действия, чёткость, субъект; поиск.
- Карточка правила: полный состав; попап краткой карточки при наведении на источник из чата; клик — полная карточка в правой панели рядом с чатом (чат временно сужается); открытие каталога с карточкой в новом окне.
- Редактирование правил в UI отсутствует: корпус — файлы `rules/`.

## 8. Раздел «Синхронизация» (маршрут `/sync-settings`)

- **Подключение Bybit**: маска ключа, описание аккаунта, место хранения секрета (секрет не возвращается ответом); при незастроенном ключе — инструкция по `appsettings.Local.json`.
- **Синхронизация**: «Синхронизировать сейчас»; переключатель «делать резервную копию перед синхронизацией» (персистентный, дефолт включён); результат последнего запуска (режим, счётчики, причина прерывания); журнал запусков таблицей; предупреждения сверки экспираций; заметки о пропущенных областях / неразрешённых инструментах / непокрытых базовых активах; ошибка проекции отдельным алертом.
- **Опасная зона**: «Собрать конструкции» — полный пересбор с подтверждением перечня безвозвратных потерь и автобэкапом; сброс состояния linear/option с подтверждением.
- **Настройки LLM-провайдера в UI не выводятся** — управление только через `appsettings.Local.json`.

## 9. Индикатор финансового результата конструкции

Контроль в сетке списка (компактный: полоса и бейдж состояния риска), в превью (средний) и в карточке (полный). Эволюция RiskProfitHint (функция №19).

### Семантика
- Шкала строится из плановых показателей конструкции: **зона планового риска** (от −Риск до 0) и **зона планового профита** (от 0 до +Профит); числовые подписи границ шкалы сохраняются.
- **Реальный риск** — наихудший результат открытых остатков на экспирации: совместный минимум платежа ног в группе одной экспирации, группы разных экспираций суммируются консервативно. Величина выводится из структуры ног и средней цены открытых остатков, от текущих марок не зависит; без открытых остатков — ноль (`finite`). Неограниченный худший случай (`unbounded`) и нехватка исходных данных (`unavailable`) возвращаются без величины и различаются статусом.
  <!-- Три состояния риска: конечный (число), неограниченный и нерассчитанный (без числа), подмена плановым риском отменена. -->
  <!-- Traceability: openspec:analytics/performance#requirement-real-risk-worst-at-expiry -->
  <!-- Traceability: openspec:ui/screens#scenario-finresult-real-risk-fallback-planned -->
- **Граница реального риска** — позиция «реализованный результат − реальный риск»: где конструкция оказалась бы при худшем исходе открытых остатков с учётом уже реализованной прибыли. Насечка стоит только при конечном (`finite`) реальном риске — свежая позиция естественным образом даёт «−реальный риск» без отдельного спец-случая; при `unbounded`/`unavailable` насечки и её числовой подписи нет.
  <!-- Насечка худшего исхода только для конечного риска; в остальных состояниях план не выдаётся за реальный. -->
  <!-- Traceability: openspec:ui/screens#scenario-finresult-real-risk-fallback-planned -->
- **Риск не ограничен** — состояние `unbounded`: чистая нетто-короткая позиция по коллам делает худший исход неограниченным при росте цены базового актива. Числа нет; полный и средний индикаторы показывают текстовый статус «риск не ограничен» отдельно от шкалы, без «Риск USDT · N%»; отметка −Риск остаётся подписанной плановым риском; текущий итог, заливка и сверхприбыль сохраняются.
  <!-- Неограниченный хвост не изображается конечной насечкой и не показывает процент риска. -->
  <!-- Traceability: openspec:analytics/performance#scenario-real-risk-unbounded-is-null -->
  <!-- Traceability: openspec:ui/screens#scenario-finresult-unbounded-risk -->
- **Не удалось рассчитать** — состояние `unavailable`: исходные данные открытых остатков неполны (неразобранный символ, нет средней цены) — расчёт не выполняется. Числа нет; полный и средний индикаторы показывают статус «не удалось рассчитать», −Риск остаётся плановой границей. Сбой котировок этот статус не меняет.
  <!-- Нехватка данных различена с неограниченным хвостом и не маскируется выводом о конструкции. -->
  <!-- Traceability: openspec:analytics/performance#scenario-real-risk-missing-open-price-unavailable -->
  <!-- Traceability: openspec:ui/screens#scenario-finresult-unavailable-risk -->
- **Маркер итога** — позиция **итога** (realized + unrealized) от нулевой отметки; подписывается самим итогом, а не нереализованной частью; зелёный тон при положительном итоге, красный при неположительном.
- **Заливка итога** — единый цветовой участок от нулевой отметки до маркера: при неположительном итоге красный тон поверх фона плановой зоны риска, при положительном — зелёный участок до планового профита. Реализованная и нереализованная части не кодируются оттенками полосы — их значения остаются числовыми метриками над индикатором.
  <!-- Единая красная заливка неположительного итога, без разложения на реализованную и нереализованную части. -->
  <!-- Traceability: openspec:ui/screens#scenario-finresult-negative-total-single-fill -->
- **Сверхприбыль** — золотой участок от +Профит до маркера итога: возникает только при выходе маркера за плановый профит; отдельной подписи у края зоны нет — значение даёт подпись маркера итога.

### Геометрия
Горизонтальная полоса: деления −Риск / 0 / +Профит; зоны тонируются (риск — тёплым, профит — зелёным, сверхприбыль — золотым, контраст зон повышен); зелёная заливка итога и золотой участок сверхприбыли не пересекаются — зелёный заканчивается на плановом профите, золотой идёт от +Профит до маркера; при выходе маркера итога за +Профит шкала удлиняется до маркера, без капа длины, а насечка границы реального риска правее шкалы клипуется её краем. Насечка границы — под полосой, с подписью реального риска («риск есть» / «риска нет» · N USDT · N%; процент — только при заданном плановом риске); маркер итога — с подписью итога. Каждая метка получает сторону (над/под полосой), вертикальный уровень и выравнивание: коллизии разрешаются переносом на противоположную сторону, затем следующим вертикальным уровнем; крайние метки прижимаются к краям изнутри и не расширяют габариты индикатора. Метки — только в полном и среднем видах.
Состояние не конечного риска выводится вне координатной геометрии: в полном и среднем — текстовым статусом «риск не ограничен»/«не удалось рассчитать» отдельной строкой, в компактном — различимым бейджем «∞»/«?» поверх полосы; геометрия полосы и отметка −Риск при этом не меняются, а плановое деление подписывается как плановый риск.

### Состояния
1. Риск/профит не заданы → нейтральная полоса без зон, насечки и маркера.
2. Задан только один параметр → единственная зона.
3. Граница левее −Риск → насечка клипуется по левому краю, в подписи истинное число реального риска.
4. Реальный риск конечный (`finite`) → насечка границы «реализованный − реальный риск» с подписью величины; без открытых остатков риск нулевой, граница совпадает с итогом («риска нет»).
   <!-- Конечный риск — единственное состояние с числовой насечкой худшего исхода. -->
   <!-- Traceability: openspec:analytics/performance#scenario-real-risk-zero-without-open-residuals -->
5. Риск не ограничен (`unbounded`) → текстовый статус «риск не ограничен» (компакт — бейдж «∞») вне шкалы; насечки и числовой подписи реального риска нет, отметка −Риск остаётся подписанной плановым риском, итог и сверхприбыль сохраняются.
   <!-- Неограниченный хвост не подменяется плановым риском и не рисуется конечной насечкой. -->
   <!-- Traceability: openspec:ui/screens#scenario-finresult-unbounded-risk -->
6. Не удалось рассчитать (`unavailable`) → статус «не удалось рассчитать» (компакт — бейдж «?»); насечки нет, различено с `unbounded`, −Риск остаётся плановой границей.
   <!-- Нехватка исходных данных не маскируется выводом о конструкции. -->
   <!-- Traceability: openspec:analytics/performance#scenario-real-risk-unknown-group-takes-precedence -->
7. Итог за +Профит → золотой участок от +Профит до маркера, шкала удлиняется до маркера; граница за +Профит золотой зоны не создаёт, её насечка клипуется правым краем шкалы; маркер подписан итогом.
8. Сбой котировок → «неполный»: нереализованная часть скрыта, состояние риска и его обозначения сохраняются, при конечном риске граница остаётся на шкале.
   <!-- Сбой марок не смешивается со состояниями риска: unbounded не становится unavailable. -->
   <!-- Traceability: openspec:analytics/performance#scenario-real-risk-marks-failure-independent -->
9. Закрытая конструкция → реальный риск нулевой, граница совпадает с реализованным результатом, подпись «риска нет».

## 10. Markdown-политика

- **Рендер — везде, где есть журнальный текст**: комментарии (конструкция/позиция/сделка), сообщения чатов (включая стрим), текст и факты подсказок, карточки правил.
