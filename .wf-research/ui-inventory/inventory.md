# Инвентаризация функционала текущего Blazor-UI журнала сделок

Research-тикет #52 (карта #50). Источник истины для концепции нового SPA-frontend и карты переноса.
Терминология — по CONTEXT.md (Конструкция, Входящие, Сборка/Пересбор, Синхронизация, Консультация/Диалог, Сводка, Подсказка, Корпус правил и т.д.).

## 1. Обзор текущего UI

**Стек**: Blazor Server (Interactive Server), один circuit на пользователя, тёмная тема «Терминал» (прототип #6, вариант A), без JS-фреймворков.

**Маршруты** (`src/TransactionJournal/Components/Routes.razor`, `App.razor` — интерактивность включена на всё дерево):

| Маршрут | Файл | Назначение |
|---|---|---|
| `/` | `Components/Pages/Constructions.razor` (559 строк) | Список конструкций + сводка журнала + портфельные подсказки |
| `/constructions/{id}` | `Components/Pages/ConstructionDetail.razor` (~2164 строки) | Карточка конструкции: все данные и всё управление |
| `/inbox` | `Components/Pages/Inbox.razor` (678 строк) | Входящие: непривязанные сделки, фильтры, разбор |
| `/hints` | `Components/Pages/Hints.razor` (221 строка) | Общий журнал подсказок (read-only) |
| `/sync` | `Components/Pages/Sync.razor` (310 строк) | Синхронизация Bybit + обслуживание состояния. **Не Linked из навигации** — доступен только прямым URL |
| `/settings` | `Components/Pages/Settings.razor` (408 строк) | Подключение, синхронизация + журнал запусков, опасная зона (сборка/пересбор) |
| `/Error` | `Components/Pages/Error.razor` | Шаблонная страница ошибки ASP.NET (не переведена на русский) |

**Каркас**: `Components/Layout/MainLayout.razor` (+ `MainLayout.razor.css`, `JournalChangeSignal.cs`), стили — `wwwroot/app.css` (21 КБ).

**Переиспользуемые компоненты**: `ConsultationsPanel.razor` (чат ИИ), `HintsPanel.razor` (панель подсказок субъекта), `RiskProfitHint.razor` (шкала «риск — итог — профит»).
**Вспомогательные**: `CommentMarkdown.cs` (MD-рендер), `DisplayTime.cs` (локальное время), `ConsultationStreamThrottle.cs` (троттлинг стрима ~150 мс).

## 3. Экран «Конструкции» (`/`)

### 3.1 Тулбар списка
- **«Синхронизировать»** — единственная ручная команда синхронизации (режим backfill/инкремент выбирает система). На время работы кнопки блокируются; результат одной строкой: режим + счётчики «новых записей исполнения N, delivery-записей N, инструментов N»; ошибка биржи — текстом под тулбаром; после завершения экран перечитывает данные и счётчик «Входящих». Зависимость: `IJournalSyncService.SyncAsync()`.
- **«Разобрать входящие (N)»** → `/inbox`; N — счётчик непривязанных (`IFrameReadModel.CountInboxAsync`), при сбое счётчика кнопка без числа.

### 3.2 Сводка журнала (kstrip над таблицей)
Итог по журналу (±USDT, при сбое марок — «неполный (сбой котировок)»), реализованный, нереализованный (сбой → «сбой котировок»), «котировки на» (время марок / сбой), «конструкций N (M открыта/открыты/открыто)» — с русскими формами слова.
Источник: `IConstructionListReadModel.ReadAsync()` → `ConstructionListData` (TotalPnL/RealizedPnL/UnrealizedPnL/MarksAsOf/HasMarkFailure/ConstructionCount/OpenCount/Items).

### 3.3 Секция подсказок журнала
- Кнопка **«Запустить проход подсказок»** (`IHintPassRunner.RunAsync()`, фоново): исходы — Completed («создано N, погашено M»), SkippedMarketUnavailable («котировки недоступны» + диагностика), CorpusInvalid (агрегированный список проблем карточек корпуса правил).
- **`<HintsPanel />` без ConstructionId** — портфельная панель субъекта «журнал» (живые сверху по группам, история свёрнута).

### 3.4 Таблица конструкций (13 колонок)
Конструкция (имя) · Подсказки (бейдж числа живых подсказок — `IHintDisplayReadModel.ReadLiveCountsByConstructionAsync()`; нет живых — нет бейджа) · Статус (открыта/закрыта/архив, цвет) · Капитал · Стоимость (mark value открытых остатков; сбой → «сбой котировок», нет остатков → «—», кредитовая — отрицательная) · Реализов. · Нереализов. (сбой → признак) · Коррект. (сумма корректировок) · Итог (полный/«неполный») + **RiskProfitHint Compact** (тонкая шкала с tooltip) · % капитала · Занято капитала % · Открыта · Закрыта.
Клик по строке → `/constructions/{id}`. Архивные конструкции скрыты из списка и счётчика.
Состояния: «Чтение журнала…», «Журнал недоступен: … Обновите экран.», «конструкций нет».

## 4. Экран «Детали конструкции» (`/constructions/{id}`)

Самый большой экран (~2164 строки). Состояния: недоступен / не найдена (`ConstructionNotFoundException`) / чтение.

### 4.1 Тулбар действий над конструкцией
| Действие | Поведение |
|---|---|
| Переименовать | Форма, maxlength 200, свободная правка (`IConstructionService.RenameAsync`) |
| Закрыть / Открыть | Свободный переход статуса между «открыта» и «закрыта» (`ChangeStatusAsync`) |
| В архив / Вернуть из архива | Архивация; возврат восстанавливает статус «закрыта» (не «открыта» — осознанное решение, статус до архивации не хранится) |
| Изменить капитал | USDT; пустое поле при сохранении **убирает** капитал (0 — легитимное значение, «не задан» ≠ 0) |
| Риск… / Профит… | Значение ровно в одной единице (% или USDT); при заданном капитале вторая единица — readonly-эхо (пересчёт при вводе); оба пустых = «Убрать»; оба заполненных — ошибка «Введите значение только в одной единице» |
| Удалить… | Только у конструкции без сделок и корректировок (кнопки у непустой нет + отказ домена причиной); подтверждение отдельным шагом; флажок «сделать резервную копию базы перед удалением» (включён по умолчанию, `IJournalBackupService.CreateBackupAsync("delete-construction")`, неудача копии отменяет удаление); после успеха — возврат к списку |

Отказы домена (`ConstructionDeletionRefusedException`, `ConstructionNotFoundException`, `ArgumentException`) показываются причиной под тулбаром; после каждого действия — полный перезачит снимка + `JournalChangeSignal.RaiseAsync()`.

### 4.2 Сводка метрик (kstrip)
Общий P&L (полный/«неполный (сбой котировок)») · % капитала (только при заданном капитале) · Стоимость · Занято капитала % · Реализ. P&L · Нереализ. P&L (сбой → признак) · корректировки · «котировки на» (время / сбой / «не нужны» без остатков) · период (открыта—закрыта с длительностью; открытая — до сих пор).
Под сводкой — **RiskProfitHint** полный вид: подписи границ обеими единицами («5% / 150»), полоса с заполнением от нуля до итога, признак пробоя границы.
Источник: `IConstructionDetailReadModel.ReadAsync(id)` → `ConstructionDetailData` (Name/Status/AllocatedCapitalUsdt/Risk*/Profit*/Metrics/Positions/Trades/ClosingEntries/ClosingWarnings/Adjustments/Comment/MarksAsOf/HasMarkFailure/HasOpenResidual).

### 4.3 Комментарий конструкции
Inline-правка в шапке: textarea rows=4, привязка `oninput`, **Ctrl+Enter сохраняет**, кнопки «Сохранить»/«Отмена»; отображение — Markdown через `CommentMarkdown.Render` + `(MarkupString)`. `ICommentService.SetConstructionCommentAsync`.

### 4.4 Панель подсказок конструкции
`<HintsPanel ConstructionId="…">` — см. §8.

### 4.5 Панель консультаций
`<ConsultationsPanel ConstructionId IsConstructionClosed>` — см. §9. Закрытая/архивная конструкция переводит панель в режим пост-мортема.

### 4.6 Таблица позиций (15 колонок)
Инструмент · Остаток · Сред. цена входа · Сред. цена закрытия · Стоимость (открытой; сбой → признак) · Изм. цены % (приведено к направлению позиции: плюс = «в прибыль») · Реализ. P&L (+% капитала) · Нереализ. P&L (закрытая → «—», сбой → признак) · Общий P&L (сбой → признак) · Всего комиссий · Время открытия · Время закрытия · Статус (открыта/закрыта) · Комментарий (inline MD-правка) · Действия: **«закрыть пометкой…»** (только открытая).
Ручная пометка закрытия (`IManualCloseMarkService.AddAsync`): форма над таблицей — цена (дефолт — последняя известная марка из кэша `IInstrumentMarkSource.GetLastMarkAsync`; пусто → домен подставит марку при чтении), время (дефолт — текущее, формат `yyyy-MM-dd HH:mm`).

### 4.7 Таблица сделок (10 колонок)
Время · execId · Инструмент · Направление (покупка/продажа) · Кол-во · Цена · Сумма · Комиссия · Комментарий (inline MD-правка) · Действия: **«Во "Входящие"»** (`ITradeBindingService.UnbindAsync`, без подтверждения — обратимо) и **«Перенести…»** (выбор целевой из активных конструкций без текущей; `Bindings.BindAsync`).

### 4.8 Закрывающие записи
- Предупреждения об **избыточных закрывающих записях** (пометка к нулевому остатку / конкуренция с delivery) — красные notes поверх таблицы.
- Таблица (6 колонок): Время · Тип (delivery / экспирация OTM / ручная пометка) · Инструмент · Детали · Сумма (марка неизвестна → прочерк) · Действия — **удалить** и **править** (только для ручных пометок; правка цены и времени, пустая цена → к последней марке при чтении). `Marks.EditAsync`, `Marks.DeleteAsync`.

### 4.9 Корректировки PnL
- Кнопка «Добавить корректировку…»: дата (дефолт сегодня, `yyyy-MM-dd`), источник («ручная»/«робот»), знаковая сумма USDT (`+87.4` / `-12`), описание (необязательно). `IPnLAdjustmentService.AddAsync`.
- Таблица (5 колонок) с **inline-правкой** строки (дата/описание/источник/сумма) и удалением без подтверждения. Удаление корректировки — `DeleteAsync`.

## 5. Экран «Входящие» (`/inbox`)

### 5.1 Тулбар разбора выбранных
- **«Привязать к конструкции…»** — форма выбора активной конструкции (первая — по умолчанию; нет активных — предупреждение «сначала создайте целевую»); массовая привязка атомарна (`Bindings.BindBatchAsync`), выбор очищается.
- **«Создать конструкцию из выбранных…»** — форма: имя (обязательно) + капитал (необязательно; пусто = без капитала); создание + привязка одним действием (`Constructions.CreateAsync` + `BindBatchAsync`), новая конструкция стартует «открыта».
Обе кнопки заблокированы при пустом выборе. Успех оповещает каркас (`JournalChangeSignal`) — бейдж «Входящих» уменьшается.

### 5.2 Фильтры (fieldset над таблицей; circuit-состояние)
- Диапазон дат «с»/«по» (input type=date; **дефолт — скользящий последний месяц**; пустое поле снимает границу).
- Инструменты: раскрывающаяся панель с чекбоксами по уникальным символам текущих «Входящих», счётчик «N из M», «Выбрать все» all-or-nothing. Закрытие по клику вне — **не реализовано** (JS-интероп не вводился).
- Направление: два независимых чекбокса (покупка/продажа); оба сняты → пустой список с явным сообщением.
Фильтрация выполняется при отрисовке (контракт read-модели не расширен). Скрытые фильтрами сделки исключаются из выбора.

### 5.3 Таблица непривязанных сделок
Чекбокс выбора · «Выбрать всё» (все-or-nothing по видимым) · Время · execId · Инструмент · Направление · Кол-во (знаковое) · Цена · Сумма · Комиссия.
Источник: `InboxReadModel.ListAsync()` → `MaterializedTrade[]` (конкретный класс Infrastructure инжектится напрямую — заметка для API-контракта).
Состояния: недоступен / чтение / «Входящие пусты: непривязанных сделок нет» / «По заданным фильтрам ничего не найдено…».

## 6. Экран «Синхронизация Bybit» (`/sync`, вне навигации)

- Кнопка «Синхронизировать» (дубль той же команды `IJournalSyncService.SyncAsync`).
- Блок «Результат» (и по свежему итогу, и при загрузке страницы — из последней завершённой строки `ISyncJournalReadModel.ReadLastCompletedAsync()`): статус, режим (backfill/инкремент), счётчики новых записей; прерванный запуск — причина; заметки: **пропущенные области** (биржа отказала в истории), **неразрешённые инструменты** (спецификация не получена, сделки отложены), **непокрытые базовые активы доски** (с подсказкой про `Sync:ExtraOptionBaseCoins` и сброс категории option).
- Ошибка построения проекции журнала — отдельным alert.
- **Предупреждения сверки экспираций с биржей**: список «символ (время доставки): расхождение N».
- **Обслуживание**: «Сбросить состояние linear/option» — с подтверждением (alertdialog); удаляет водяные знаки категории → следующий запуск = первичный backfill категории; сырьё не трогает. `IExecutionSyncStateStore.ResetAsync`.

## 7. Экран «Настройки» (`/settings`)

### 7.1 Подключение
- Ключ настроен: маска ключа, описание аккаунта, место хранения секрета. **Секрет никогда не доходит до UI** (`SettingsReadModel` отдаёт только маску).
- Ключ не настроен: инструкция «заполните Bybit:ApiKey/Bybit:ApiSecret в appsettings.Local.json и перезапустите журнал».

### 7.2 Синхронизация
- «Синхронизировать сейчас» (та же команда; режим выбирает система).
- Переключатель **«делать резервную копию базы перед синхронизацией»** — персистится в БД (таблица AppSetting, `IBackupPolicyStore`), включён по умолчанию; неудача записи откатывает флажок с сообщением.
- **Журнал синхронизаций** — таблица: Время · Режим · Результат · Статус (`ISyncJournalReadModel.ReadAsync`).
- Предупреждения сверки последнего запуска + ошибка проекции.

### 7.3 Опасная зона — сборка конструкций (ADR-0004)
- **«Собрать из "Входящих"»** — безопасная инкрементная сборка, без подтверждения (`IConstructionAssemblyService.AssembleInboxAsync`).
- **«Собрать конструкции»** — полный пересбор: подтверждение с перечнем безвозвратных потерь (все конструкции, привязки, капитал, риск/профит, комментарии, корректировки, пометки) и автоматической резервной копией до пересбора (`RebuildAsync`; неудача копии блокирует).
- Итог любой команды: «конструкций N · привязано сделок M · во "Входящих" K» + оповещение каркаса.
Служба переразбора сырья (`JournalReparseService`) зарегистрирована в DI, но команда снята с экрана.

## 8. Подсказки (HintsPanel + Hints + движок)

### 8.1 Панель субъекта (`HintsPanel.razor`)
- Субъект: конструкция (`ConstructionId` задан) или «журнал» (портфельная, на `/`).
- Живые подсказки сверху, сгруппированы по **справочнику групп v1** (`HintSectionGroups`): «Риск-режим», «Управление конструкцией», «Фьючерерсная нога» — пустые группы не показываются.
- **Карточка полного состава**: текст, характер (подпись из `HintCharacterLabels`), чёткость, правило (ruleId), as-of, статус, факты триггера (ключ-значение), источники (тег + файл + цитаты-доказательства).
- Кнопки **«Применено» / «Отклонено»** — только у живых (New); терминальные статусы Applied/Dismissed/Expired — без кнопок.
- Терминальная **история свёрнута** — toggle «История (N)».
- **Автопометка первого показа** живых подсказок (`MarkSeenAsync`, firstSeenAt) — побочный эффект рендера.
- Зависимости: `IHintDisplayReadModel` (`ReadConstructionPanelAsync`/`ReadJournalPanelAsync`/`ApplyAsync`/`DismissAsync`/`MarkSeenAsync`/`ReadLiveCountsByConstructionAsync`/`ReadLogAsync`) — проект TransactionJournal.Hints.

### 8.2 Журнал подсказок (`/hints`)
Read-only список всех записей всех субъектов: фильтры **статус / группа / характер** (группа сужает набор характеров; характер вне группы сбрасывается), кнопка «Сбросить фильтры»; карточки без кнопок мутации; различает «записей нет» и «по фильтру записей нет».
Характеры (справочник, 10): risk-mode, profit-target, profit-protection, risk-reduction, rolling, entry, exit, futures-leg, rebuild-dismantle, other (`HintCharacterLabels.cs`).

### 8.3 Запуск прохода
Кнопка на `/`: `IHintPassRunner.RunAsync()` (проект Hints, `HintAgentPass`) — тот же код, что плановые проходы. Невалидный корпус правил → агрегированный список проблем без создания записей. Прочие исходы: см. §3.3.

## 9. Консультации (ConsultationsPanel + проект Consultations)

### 9.1 UI-поведение панели
- **Список диалогов** конструкции («Диалог N (время создания)»), выбор показывает переписку; удаление диалога целиком с подтверждением (hard delete, без корзины).
- **Переписка**: сообщения с ролью («Вы»/«Помощник») и as-of; текст — **плоский текст с pre-wrap, без Markdown-рендера**.
- **Ввод**: textarea rows=3; «Отправить»; во время генерации ввод заблокирован, кнопка **«Отмена»** (CancellationTokenSource); после отмены — заметка «вопрос остался в диалоге без ответа»; кнопка **«новый вопрос»** — сбросить выбранный диалог (следующее сообщение создаст новый).
- **Стриминг**: сегменты текста + **статусные строки tool-вызовов** («вызов инструмента name(args)… / — готово»); сами tool-call фрагменты не рендерятся; перерисовка не чаще ~150 мс (`ConsultationStreamThrottle`); статусные строки tool-кадров — без троттлинга.
- **Пост-мортем**: закрытая/архивная конструкция — тот же конвейер, но с заметкой режима разбора работы над ошибками.
- Сообщение без выбранного диалога создаёт новый диалог (первое сообщение).

### 9.2 Конвейер (проект TransactionJournal.Consultations)
`ConsultationChatService.AppendUserMessageAsync` (фиксация вопроса, создание диалога) → `StreamAssistantAnswerAsync` (история только этого диалога; снимок контекста; стрим; по завершении фиксация ответа с as-of и **рыночным следом** — какие инструменты вызывались и с какими as-of). Зависимости UI: `IConsultationStore` (Ports), `ConsultationChatService`.
- **Инструменты агента** (`ConsultationTools.cs`): `read_rule_card` (карточка корпуса правил по id), `get_market_snapshot` (марка, бид-аск, OI, фандинг фьючерса), `get_option_board` (доска опционов: страйки с IV, греками, OI, бид-аск). При сбое биржи рыночный читатель деградирует в кэш марок с явным as-of.
- **Снимок контекста** (`ConsultationContextReader`): markdown-документ — конструкция (статус, капитал, даты, комментарий), позиции таблицей, портфельные агрегаты, корпус правил (индекс карточек через `RulesCorpusConsultationAdapter`).
- **Хранилище**: SQLite per construction в `App_Data/consultations` — пересбор конструкции стирает файл базы целиком.
- **Инструкции агента**: `consultation-prompt.md` (корень репо, путь — `Consultations:InstructionsPath`).

## 10. Markdown: где рендерится и где редактируется

**Рендер** (`src/TransactionJournal/Components/CommentMarkdown.cs`, 83 строки):
- Markdig-пайплайн: `UseSoftlineBreakAsHardlineBreak` (одиночный перенос = `<br>`), `UseAutoLinks`, **`DisableHtml`** (сырой HTML экранируется).
- Небезопасные ссылки (не http/https/mailto, control-символы) вырезаются с сохранением текста подписи.
- null/пустой вход → null.

**Использования — ровно 3, все в `ConstructionDetail.razor`**:
1. комментарий конструкции (шапка, `:323`);
2. комментарий позиции (строка таблицы позиций, `:497`);
3. комментарий сделки (строка таблицы сделок, `:576`).
Везде паттерн: `@((MarkupString)(CommentMarkdown.Render(x.Comment) ?? "—"))`.

**Редактирование**: inline в месте отображения — textarea rows=4, `@bind:event="oninput"` (черновик актуален к моменту Ctrl+Enter), **Ctrl+Enter = сохранить** (`HandleCommentKeyDown`), Enter без Ctrl — перенос строки; кнопки «Сохранить»/«Отмена»; одновременно редактируется один комментарий (`CommentTarget`: Construction/Trade/Position + ключ).

**Где Markdown НЕ рендерится (важно для нового UI)**:
- текст сообщений консультаций (в т.ч. ответы помощника, которые модель пишет как markdown) — `<p>@message.Text</p>`, pre-wrap (`ConsultationsPanel.razor:78-84`);
- стрим-сегменты ответа — аналогично;
- текст подсказок — `<p class="hint-text">@hint.Text</p>` (`HintsPanel.razor`, `Hints.razor`);
- факты/цитаты источников подсказок — плоский текст.
Карта #50 требует «корректный рендер всего журнального текста» и редактирование «тулбар + live-превью (split-view), без WYSIWYG».

## 12. Болевые точки текущего UX (по коду, без домыслов)

1. **Нет адаптивности вообще**: в `wwwroot/app.css` (21 КБ) — ни одного `@media`; `.screen { max-width: 1280px }`; таблицы 13–15 колонок с `white-space: nowrap`; только горизонтальный overflow. Мобильный браузер фактически не поддержан.
2. **Перегруженный экран деталей**: ConstructionDetail.razor ~2164 строк — на одной странице действия + сводка + комментарий + подсказки + консультации + 4 таблицы; все формы — inline-блоки над таблицами (одна форма за раз), длинная прокрутка.
3. **Ручная актуализация данных**: экраны перечитывают read-модель при каждом открытии и после каждого действия (полный `ReloadAsync`); при недоступности — «Обновите экран» (F5). Живая панель — только топбар/бейдж через сигнал; списки сами не обновляются.
4. **Синхронизация без прогресса**: кнопки блокируются, статус — «Синхронизация выполняется…» до конца; нет индикатора этапов/прогресса, нет фоновой автоматической догрузки.
5. **Скрытый экран `/sync`**: неLinked из навигации (нет ни одной ссылки; только прямой URL), при этом дублирует кнопку и результат синка с `/` и `/settings` — три точки одной команды с разной подачей.
6. **Markdown не рендерится в консультациях и подсказках** — ответы ИИ видны сырым markdown-текстом (pre-wrap).
7. **Circuit-состояние теряется**: выбор строк и фильтры «Входящих», раскрытость панели инструментов, свёрнутость истории подсказок — живут в circuit; обрыв/reload теряет их.
8. **Ручной ввод дат текстом**: все формы (пометки, корректировки) требуют формат `yyyy-MM-dd HH:mm` строкой, ошибки — текстом под полем; нет date/time-picker.
9. **Нет поиска/сортировки/пагинации** ни в одной таблице (конструкции, сделки, позиции, журнал запусков, журнал подсказок) — весь список сразу.
10. **Одна транзитная вкладка** и одна inline-правка одновременно; транзит — эрзац «открыть в новом окне».
11. **Тёмная тема зафиксирована** (`color-scheme: dark`, «Терминал») — нет светлой/переключения; новый дизайн-референс карты #50 — светлый.
12. **Время конвертируется в зону процесса** (`DisplayTime.FormatMoment` → `ToLocalTime()`), а не браузера — нет JS-интеропа зоны; корректно только при локальном развертывании.
13. **Дублирование форматтеров**: `FormatPnL` и подписи статусов скопированы между `Constructions.razor`, `ConstructionDetail.razor` и `MainLayout.razor`.
14. **Стриминг привязан к SignalR-перерисовкам**: троттлинг ~150 мс обязателен, иначе канал забивается; долгая генерация держит circuit.
15. **Консультации привязаны к конструкции**: нет чата вне контекста конструкции, нет выбора модели/источников в UI (всё в конфиге), нет списка всех чатов — только внутри карточки конструкции.

## 13. Конфигурация, которую новый UI должен покрывать

### LLM-провайдер (`LlmProviderSettings.cs`, `Program.cs:340-380`)
Секция **`Llm`** (общая для всех потребителей: чат консультаций + изложение сводок):
- `Llm:Provider` — дефолт `zai`; провайдер ≠ zai **обязан** указать явный `BaseUrl` (иначе `InvalidOperationException`).
- `Llm:BaseUrl` — OpenAI-совместимый эндпоинт; дефолт `https://api.z.ai/api/paas/v4`; нормализация trailing slash.
- `Llm:ApiKey` — ключ; **обнаруживается лениво** в момент первого обращения к модели (пустой ключ не мешает остальному журналу; ошибка — при первом вопросе).
- `Llm:Chat:Model` — модель чата консультаций, дефолт **`glm-5.3`** (`ConsultationChatModelOptions`).
- `Llm:Hint:Model` — модель изложения сводок, дефолт **`glm-5.3-flash`** (`HintChatModelOptions`); потребитель появится в change add-summary-channels.

Сейчас **редактирования LLM-настроек в UI нет** — только файл. Карта #50: «настройки LLM-провайдера — в "Синхронизации"/настройках» нового UI; «Агент» — параметры: модель (дефолт GLM-5.3), конструкция (опционально), источники данных (tools).

### Прочая конфигурация (`Program.cs`)
- `appsettings.Local.json` — последний провайдер конфигурации, перекрывает всё (`config/local-secrets`): `Bybit:ApiKey/ApiSecret` (синхронизация), `Telegram:BotToken/ChatId` (заготовка канала сводок), секция `Llm`.
- `Bybit:BaseUrl` — эндпоинт биржи (дефолт из `BybitClientOptions`).
- `Sync:MaxBackfillDepthDays` (дефолт 730), `Sync:ExtraOptionBaseCoins` (делистнутые доски).
- `Backup:Directory` (дефолт `App_Data/backups`), `Backup:RetentionLimit` (дефолт 15).
- `Hints:RulesPath` (дефолт `rules/` рядом с exe — корпус правил), `Consultations:InstructionsPath` (дефолт `consultation-prompt.md`).
- `ConnectionStrings:Journal` — SQLite `App_Data/journal.db`, WAL, миграции при старте.
- Настройка в БД (AppSetting): переключатель «копия перед синхронизацией».
