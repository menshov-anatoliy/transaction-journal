# Индикатор финрезультата: маркеры изменения результата вместо насечки худшего исхода

Насечка худшего исхода (ADR-0015) и метрика `worstCaseUsdt` признаны неинформативными по опыту использования: трейдеру важна не оценка дожития остатков до экспирации, а история зафиксированного результата — как конструкция пришла к текущему состоянию. Решено (грилл-сессия по переработке концепции индикатора, 03.11.2026): насечка, её подпись и `worstCaseUsdt` удаляются полностью — из UI, API и спек; вместо них на шкалу наносятся номерные маркеры изменения результата, а плавающий маркер текущего результата (реализованный + нереализованный + корректировки) остаётся без изменений.

Значение маркера — накопленный зафиксированный денежный результат на момент события: сводная «С учётом зафиксированного синтетикой» плюс внешние корректировки PnL минус входная стоимость ещё открытых остатков (решение владельца при имплементации: премия открытия фиксируется сразу — покупка стреддла за 100 USDT даёт первый маркер −100; при закрытии всех остатков значение совпадает со сводной). От котировок значение не зависит, нереализованный PnL в него не входит; фьючерсные сделки уже входят в FIFO-результат конструкции. Триггеры события: окно опционных исполнений по правилам сборки v5 (ролл — единое окно и одна метка, существующая эвристика переиспользуется), каждая фьючерсная сделка робота, изменение набора действующих связок синтетического закрытия, внешняя корректировка PnL, закрывающая запись (delivery, экспирация OTM, ручная пометка). Маркеры не хранятся — вычисляются из журнала на лету, при изменении распознавания связок история пересчитывается задним числом.

Отображение: суммы маркеров — над полосой, подпись текущего результата — под полосой; коллизии номерных бейджей разносятся вертикально; шкала охватывает план, текущий маркер и все метки без клипа. Промежуточная метка выводится только при отличии от последней отображённой не менее чем на 5% планового риска (первая и последняя метки безусловны, нумерация сквозная по отображённым; без планового риска порога нет). Область описания маркеров (номер, дата, тип операции, изменение, накопленный итог, скролл при переполнении) — только у полного вида; средний и компактный виды показывают последний маркер без номера.

## Considered Options

- Метка на каждое исполнение, а не на окно сборки: отвергнуто — двухногое открытие и роллы дробили бы историю на бессмысленные шаги; атомарность окна уже правило домена.
- Хранить маркеры как сущность: отвергнуто — журнальная истина расходилась бы с производной историей при спорах связок; маркер — вычислимая величина.
- Включать в значение метки нереализованный PnL: отвергнуто — история плыла бы с котировками; зафиксированный результат от котировок не зависит.
- Оставить `worstCaseUsdt` метрикой вне индикатора: отвергнуто — самостоятельного применения не нашлось, а дублирующая сущность «на всякий случай» противоречит чистоте контрактов.
- Показывать все события без порога: отвергнуто — длинные серии роботных сделок засоряют шкалу близкими значениями в одном месте.

## Consequences

- Breaking: из API и read-моделей уходит `worstCaseUsdt`; `realRiskUsdt`/`realRiskStatus` остаются — бейджи «∞»/«?» и предупреждения ими питаются.
- ADR-0015 помечен заменённым; сценарии насечки в спеке `ui/screens` переписываются в OpenSpec change вместе с design.pen (правка макета — первой, по правилу design-first) и кодом.
- Список и превью конструкции не меняют геометрию: один последний маркер без номера умещается в существующие 132px компактного вида.
- Подпись планового риска при `unbounded`/`unavailable` («плановый риск −400») сохраняется — план остаётся плановым.
