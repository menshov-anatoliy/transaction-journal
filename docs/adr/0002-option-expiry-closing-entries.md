# Экспирация опционов — закрывающие записи, а не спец-сущности

Позиция — чистый остаток по инструменту внутри конструкции, без специальных сущностей «ролл»/«экспирация». Решено: delivery ITM-опциона порождает закрывающую запись с количеством, равным журнальной позиции, и эффективной ценой, равной внутренней стоимости на расчётной цене экспирации (`max(0, deliveryPrice − strike)` для колла, зеркально для пута); если инструмент есть в нескольких конструкциях, аккаунтовая delivery-запись делится между ними пропорционально их остаткам. OTM-экспирация (биржевая запись отсутствует) закрывает позицию автоматически по нулевой цене в момент deliveryTime инструмента. Ручная пометка закрытия — только fallback для инструментов без биржевых записей (делистинг). Реализованный PnL всегда считается собственным расчётом (FIFO); биржевой `deliveryRpl` используется только для предупреждающей сверки, расхождения не блокируют и не переписывают результат. Решение принято в #5.

## Considered Options

- Брать `deliveryRpl` биржи как готовый результат — отклонено: биржа считает от entryPrice всего аккаунта, а не от сделок журнала, и не делится по конструкциям.
- Спец-сущность «экспирация»/«ролл» — отклонено при чартинге карты: роллирование — обычные сделки, модель остаётся единой.
