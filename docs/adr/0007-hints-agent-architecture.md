# Архитектура агента подсказок — детерминированный движок в отдельном проекте окружения, LLM только для изложения сводки

Агент подсказок живёт в том же exe, что весь журнал ([ADR-0003](0003-stack-single-exe-dotnet-sqlite.md)), но выделяется в отдельный проект окружения `src/TransactionJournal.Hints`: детерминированный движок правил на каждом проходе агента читает журнал (SQLite через EF), рыночные марки Bybit (существующий Bybit-слой, публичный эндпоинт tickers — [исследование](../research/bybit-api.md)) и снимок корпуса правил `rules/` ([#26](https://github.com/menshov-anatoliy/transaction-journal/issues/26)), сам отбирает сработавшие подсказки и пишет их в SQLite как записи окружения; LLM вызывается один раз за проход через `Microsoft.Extensions.AI` (`IChatClient`), получает только уже отобранные факты и лишь излагает сводку — JSON-режим провайдера с валидацией схемы, при нарушении retry, затем шаблонный текст. Выбор подсказок делает код, а не модель, поэтому правило «Никаких прогнозов, только действия по факту совершившихся событий» гарантировано структурно, а не промптом. Дефолтный провайдер — z.ai по OpenAI-совместимому base URL, модель GLM-5.3-Flash; провайдер и модель сменяются конфигурацией без кода. Запуск в v1 — hosted BackgroundService: три автоматических прохода в настраиваемом окне дня ([#21](https://github.com/menshov-anatoliy/transaction-journal/issues/21)), пропущенные слоты не догоняются, ручной запуск — кнопка в UI и Telegram `/summary`; подсказки дедуплицируются по «правило×конструкция×окно», хранятся всей историей и показываются в UI у конструкции — домен их не видит. Решение принято на карте [#19](https://github.com/menshov-anatoliy/transaction-journal/issues/19) по итогам сравнения архитектур ([#22](https://github.com/menshov-anatoliy/transaction-journal/issues/22), [исследование](../research/hints-agent-architectures.md)).

## Considered Options

- Внешний CLI-агент по расписанию поверх read-only MCP из ADR-0003 — отклонён как целевой: read-only контракт не пишет подсказки в журнал, агентский цикл не тянет интрадей по стоимости, гарантия «только факты» держится промптом; остаётся дешёвым запасным путём до готовности движка.
- Чистый in-app вариант, где LLM сам отбирает подсказки, — отклонён: структурно слабее по правилу «никаких прогнозов» и дороже.
- GitHub Actions cron и Copilot automations — отклонены: раннер не видит локальную SQLite, выгрузка торговых данных в облако недопустима.
- n8n self-hosted как оркестратор — отклонён: второй рантайм, дублирует функцию движка окружения.
- Hangfire — отклонён: официального SQLite-стора нет, отдельная СУБД ради таймера противоречит ADR-0003.
- Планировщик ОС с флагом `--hints-once` — отложен как предусмотренный резерв: тот же движок сможет запускаться вне живого exe без изменений кода.

## Fixed Mechanics

- Снимок корпуса: в начале прохода каталог `rules/` (YAML, файл = карточка) читается целиком в неизменяемый снимок; правки корпуса действуют со следующего прохода.
- Валидность корпуса — предусловие прохода: карточка, которая не парсится или не соответствует схеме, как и отсутствующий или пустой каталог `rules/`, ломает проход целиком ещё до построения снимка и любых чтений журнала и рынка. Движок за одно чтение собирает все проблемы всех карточек и поднимает одну агрегированную ошибку с полным списком — владелец обязан привести корпус в надлежащий вид до запуска агента. Ни подсказки, ни записи, ни сводка не производятся; хост приложения продолжает работать, ошибка видна на каждом входе запуска: лог планового прохода, UI ручного запуска, ответ Telegram `/summary`.
- Неизвестный движку ключ триггера — сознательно не «битость»: правило валидно, отстаёт код; правило не порождает подсказку — уходит в статический чек-лист сводки и лог «непокрытых кодом», проход продолжается.
- Инструкции агента: редактируемый файл (отдельный настраиваемый путь, по умолчанию `agent-prompt.md` рядом с `rules/`), меняется без пересборки; переопределяет встроенный в код минимальный дефолт с обязательным правилом; отсутствие или битость файла проход не ломают.
- Бюджет LLM: менее $1/мес на каденции 3 прохода/день (~90 проходов, ~3K входных и ~0.7K выходных токенов на проход; GLM-5.3-Flash — $0.15/$0.50 за 1M, прайс z.ai на 2026-09-30).
- Задел R3: интерактивная ad-hoc LLM-сессия над тем же read-only контрактом чтения, что MCP из ADR-0003 (единый контракт, два потребителя), — допустимое будущее расширение, вне v1 и вне карты.

## Consequences

- Основной объём разработки — сам движок; смена корпуса правил — работа с данными без пересборки и перезапуска приложения.
- Битый, пустой или отсутствующий корпус ломает проход fail-fast: агрегированная ошибка со списком всех проблем требует привести документацию в порядок до запуска агента; приложение при этом не падает. Снисходительная деградация «пропустить карточку и продолжить» отклонена: сводка по неполному канону молча искажала бы картину правил.
- Недоступность LLM деградирует только текст сводки (шаблон вместо изложения); подсказки продолжают фиксироваться — функция не теряется.
- Наружу уходит только выжимка сработавших правил, не весь журнал; провайдер работает под юрисдикцией КНР, локальная Ollama подключается сменой конфигурации.
- Домен не знает про ИИ: `TransactionJournal.Hints` — окружение с зависимостями только внутрь Domain; read-only MCP-контракт ADR-0003 остаётся единственным внешним контрактом чтения.
