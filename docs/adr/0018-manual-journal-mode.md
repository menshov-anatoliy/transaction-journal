# Ручной режим журнала — полноценные сделки с признаком источника

Журнал может вестись целиком без синхронизации с Bybit: пользователь вносит сделки вручную, и каждая ручная сделка является полноправной сделкой журнала с признаком источника «ручной ввод» — участвует в остатках, FIFO и сборке наравне с биржевыми. Ручные записи доступны полному CRUD (создание, правка, удаление с детерминированным пересчётом); синхронизированные записи неизменяемы, потому что источник истины — биржа и воспроизводимость сверки важнее удобства точечной правки. Символ инструмента при ручном вводе проверяется и обогащается публичным эндпоинтом `instruments-info` без API-ключей; разбор строки символа источником метаданных не является. Решение принято в grill-сессии по ручному управлению журналом.

## Considered Options

- Отдельный тип записи для ручных сделок со своей логикой — отклонено: параллельный конвейер расчётов удваивает модель без выгоды.
- Правка/удаление синхронизированных сделок — отклонено: ломает воспроизводимость сверки с биржей.
- Разбор строки символа для оффлайн-ввода — отклонено: принцип канонических данных биржи, уже заложенный в пополнение справочника.
- Автодедупликация ручной и биржевой записи одного исполнения — отклонено: у ручных записей нет биржевого `execId`, дедупликация неизбежно даст ложные срабатывания; дубликат разрешает пользователь.

## Consequences

- Ввод нового инструмента требует сети: справочник пополняется публичным эндпоинтом.
- Полный пересбор сохраняет ручные сделки как сырьё журнала; привязки и оспаривания связок обрабатываются общей семантикой пересбора.
- Ручная пометка закрытия повышена с fallback до штатного способа закрытия в ручном режиме, получает опциональное количество; закрывающие записи и внешние корректировки PnL сохраняются — их назначение (закрытие вне биржевых сделок; результат без инструментной позиции) не покрывается ручными сделками.
