# Архитектура чата консультаций — интерактивный read-only агент в отдельном проекте окружения, рынок только через инструменты

Чат консультаций живёт в отдельном проекте окружения `src/TransactionJournal.Consultations` по образцу агента подсказок ([ADR-0007](0007-hints-agent-architecture.md), [ADR-0008](0008-ddd-solution-structure.md)): домен о нём не знает, зависимости направлены только внутрь Domain, порты объявлены в самом проекте, адаптеры — в Infrastructure и composition root. Базовый контекст собирается кодом детерминированно в markdown с as-of через порт `IConsultationContextReader` (адаптер поверх существующих read-моделей ConstructionDetail/JournalMetrics): конструкция с позициями и результатами, портфельные агрегаты и компактный индекс корпуса правил; доступ к корпусу — через порт `IRuleCorpusReader` с адаптером в composition root поверх `RulesCorpusLoader` из Hints, без связи между проектами окружений. Полная карточка правила и рыночные данные — только через read-only инструменты: `read_rule_card(cardId)`, `get_market_snapshot(baseCoin)` (спот/фьючерс и фандинг) и `get_option_board(baseCoin)` (компактная проекция доски с IV/OI/греками). Агентный цикл — `Microsoft.Extensions.AI` `IChatClient` с `UseFunctionInvocation` и `MaximumIterationsPerRequest = 6`; рыночные тулы ходят исключительно через расширяемый `BybitTickersClient` (DTO `BybitTicker` дополняется греками/IV/OI/бид-аск/фандингом тем же эндпоинтом `/v5/market/tickers`) с его троттлером и resilience, один вызов тула равен одному HTTP-запросу — максимум ~6 биржевых запросов на сообщение без отдельных счётчиков. При недоступности Bybit тул возвращает структурированный ответ «недоступно + последняя кэшированная проекция с явным as-of» из кэша марок `InstrumentMarkProvider`; инструкции агента (отдельный редактируемый `consultation-prompt.md` по паттерну [ADR-0007](0007-hints-agent-architecture.md): настраиваемый путь, дефолт рядом с `rules/`, встроенный дефолт в коде, битость не ломает чат) обязывают модель помечать устаревшие as-of и отказываться от рыночно-зависимых рекомендаций. Модель чата — отдельный keyed `IChatClient` со своей секцией конфигурации: дефолт z.ai, полный GLM-5.3, бюджет <$5/мес удерживается компактным контекстом и сменой модели конфигурацией без кода. Ответ стримится в Blazor Server поверх `IAsyncEnumerable<ChatResponseUpdate>`: троттлинг перерисовок ~150 мс через `InvokeAsync(StateHasChanged)`, отмена кнопкой через `CancellationToken`, между текстовыми сегментами — статусные строки tool-вызовов, сами tool-call фрагменты не рендерятся. История диалогов — SQLite per construction как запись окружения (порт `IConsultationStore`, адаптер в Infrastructure по образцу `HintStore`), рыночный след ответа ассистента сохраняется в сообщении; пересбор стирает консультации. Решение принято на карте [#45](https://github.com/menshov-anatoliy/transaction-journal/issues/45) в тикете [#48](https://github.com/menshov-anatoliy/transaction-journal/issues/48) по итогам исследования ([#46](https://github.com/menshov-anatoliy/transaction-journal/issues/46)) и доменной модели ([#47](https://github.com/menshov-anatoliy/transaction-journal/issues/47)).

## Considered Options

- Чат внутри `TransactionJournal.Hints` — отклонён: смешение агентов разной природы (детерминированный движок с одним LLM-вызовом за проход против интерактивного агента с function calling); общим остаётся только конфигурация провайдера, которая и так живёт в composition root.
- Чат в `TransactionJournal.Application` — отклонён: тянет зависимости ME.AI в оркестрационный слой и нарушает принцип «домен и приложение не знают про ИИ» из ADR-0007.
- Прямая зависимость Consultations → Hints ради корпуса — отклонена: связывает два окружения; порт `IRuleCorpusReader` с адаптером в composition root даёт то же без новой связи проектов.
- Read-only MCP-контракт ADR-0003 как транспорт инструментов — отклонён для v1: чат живёт в том же exe, межпроцессная граница не нужна; задел R3 сохраняется.
- Отдельный `BybitOptionBoardClient` для доски — отклонён: данные приходят тем же эндпоинтом; второй клиент означал бы второй троттлер и дубль resilience.
- Явный пер-запросный счётчик рыночных тулов и pre-flight ping доступности — отклонены: структурных мер достаточно (потолок итераций + один запрос на вызов), кэш as-of закрывает деградацию без лишних механизмов.

## Consequences

- Расширение `BybitTicker` добавляет только опциональные поля: существующие потребители (провайдер марок, оценка нереализованного PnL) не меняют поведения.
- Потолок `MaximumIterationsPerRequest = 6` ограничивает глубину агентного рассуждения — достаточно в v1, потому что база (журнал, агрегаты, индекс корпуса) уже в промпте, тулам остаётся только рынок и детали карточек.
- Рыночный след в сообщении ассистента (какие инструменты вызывались и с какими as-of) делает происхождение рекомендаций проверяемым постфактум.
- Полный GLM-5.3 дороже Flash: бюджет <$5/мес держится короткими диалогами и компактным снимком контекста; при превышении — переход на Air/Flash конфигурацией.
- Стриминг только текстовых чанков упрощает рендер: частичные tool-call фрагменты не показываются, вместо них статусные строки.
