# Собранный SPA раздаётся из корня .NET-хоста

Cutover журнала на новый интерфейс ([#53](https://github.com/menshov-anatoliy/transaction-journal/issues/53), коммит `f878c92`, PR #74) удалил Blazor-UI и переключил .NET-хост на раздачу `frontend/dist` из корня приложения, но Vite продолжал собирать SPA с `base: "/spa/"`: `index.html` запрашивал `/spa/assets/index-*.js`, а хост раздавал те же файлы по `/assets/index-*.js` — собранное приложение из хоста получало белый экран (живьём: `/spa/assets/*` → 404, `/assets/*` → 200). Рассинхрон маскировал дев-плагин-редирект `/` → `/spa/` (решение D8 архивного change `rework-spa-shell-and-screens`), поэтому на dev-сервере дефект не проявлялся. Решение: Vite собирает SPA с `base: "/"`, префикс `/spa` упразднён, собранные ассеты и страницы приложения раздаёт корень .NET-хоста.

## Considered Options

- Оставить `base: "/spa/"` и научить хост раздавать статику по префиксу — отклонено: префикс был компромиссом совместного существования с Blazor-UI в корне, который cutover удалил; удержание префикса требует лишнего перехвата маршрутов и расхождения схем dev-сервера и собранного приложения.
- Оборачивать сборку в `/spa/` на стороне хоста (переписывание путей при раздаче) — отклонено: двойное обслуживание base-пути, логика рерайта в Program.cs без выигрыша для локального инструмента.
- `base: "/"` из корня хоста — принято: совпадает с уже реализованной раздачей `frontend/dist` в Program.cs, устраняет дрейф cutover'а, дев-сервер и собранное приложение работают по одной схеме.

## Fixed Mechanics

- `frontend/vite.config.ts`: `base: "/"`; плагин `spa-root-redirect` и файл `spa-root-redirect.ts` удалены; его тесты (`vite.config.test.ts`) удалены вместе с плагином.
- Внутренние ссылки и маршрутизация фронтенда — корне-относительные: ссылки (`/agent?rule=...`, `/constructions/...`) без префикса, константа монтажного префикса `SPA_BASE_PATH` удалена, `createBrowserRouter` работает с базовым путём по умолчанию (корень).
- `.run/Frontend React.run.xml` открывает `http://localhost:5173/` без префикса.
- `src/TransactionJournal/Program.cs` не меняется: статика раздаётся из корня, SPA-fallback `/{**path:nonfile}` возвращает `index.html` для маршрутов приложения.
- Живой spec `http-api/transport` не фиксирует base path SPA — нарушение спецификации отсутствует; ADR отменяет решение D8 архивного change.

## Consequences

- Собранный SPA загружается и работает по `http://localhost:5019/` без префикса; дев-сервер отвечает на `/` напрямую.
- Маршруты приложения стали короче (`/agent`, `/constructions/...`); закладки вида `/spa/...` перестают работать — для локального персонального инструмента допустимо.
- Возврат префикса (например, при реверс-проксировании) потребует нового явного решения — отдельного ADR.
