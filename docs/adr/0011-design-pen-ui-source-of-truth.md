# UI-дизайн: design.pen — единственный источник истины; критерий переноса — токенно-компонентное соответствие

Перенос дизайна из design.pen в React SPA при работе карты «Концептуально новый frontend журнала сделок» ([#50](https://github.com/menshov-anatoliy/transaction-journal/issues/50)) выполнен с дрейфом. Решено: на время сверки design.pen заморожен, правится только код; соответствие считается достигнутым при совпадении дизайн-токенов, типографики, отступов/радиусов и состава-структуры компонентов per-экран (токенно-компонентное соответствие, попиксельный перфект не преследуется); приёмка каждого экрана — скриншот-сверка живой страницы с макетом через MCP pen; порядок работ — сначала UI-шов (токены и общие компоненты), затем страницы. Осознанные отклонения от дизайна допускаются только через явное решение, зафиксированное в change-артефакте. Чтение design.pen выполняется исключительно через MCP pen; прямой парсинг JSON-файла запрещён.

## Considered Options

- **Пиксель-перфект** — отклонён: несоразмерная стоимость при токенно-компонентной эквивалентности.
- **Свободная интерпретация «на глаз»** — отклонена: именно она породила дрейф после #50.

## Consequences

- Изменение дизайна после сверки требует правки design.pen и повторной сверки затронутых экранов.
- Отклонение от дизайна без записи в change-артефакте считается дефектом сверки.
- Инвентарь дизайна для аудита извлекается через MCP pen в машиночитаемый экстракт (`.wf-research/design-audit/design-extract.json`), а не парсингом файла.
