# Трассировка агентского харнеса — единый OTel-механизм поверх ActivitySource с локальным JSONL-sink, metadata-only, всегда включена

Обе агентские поверхности журнала — чат консультаций (`TransactionJournal.Chats`, [ADR-0009](0009-consultation-chat-architecture.md)) и проход подсказок (`TransactionJournal.Hints`, [ADR-0007](0007-hints-agent-architecture.md)) — покрываются единым механизмом операционной трассы агента (термин отличен от доменного «следа источников», GLOSSARY.md) поверх OpenTelemetry-совместимых `ActivitySource` — `TransactionJournal.Chats` и `TransactionJournal.Hints` — без обязательного внешнего backend ([ADR-0003](0003-stack-single-exe-dotnet-sqlite.md)). Модель спанов чата двухслойная: встроенная инструментация Microsoft.Extensions.AI (источник `Experimental.Microsoft.Extensions.AI`, подключается `UseOpenTelemetry` в конвейере `IChatClient` строго под `UseFunctionInvocation`) используется как есть, без своих дубликатов — `chat {model}` на каждый запрос модели, `orchestrate_tools` на агентный цикл, `execute_tool {name}` на вызов тула с метриками `gen_ai.*` (токены, задержки, `gen_ai.request.model`, `error.type`); свой корневой спан `chat_turn` на весь ход (от вопроса владельца до конца стрима, `ChatService.StreamAssistantAnswerAsync`) несёт `tj.chat.iterations` (число запросов модели в ходе), `tj.chat.cancelled=true` при отмене (статус спана остаётся не-ошибкой) и обратную связь `tj.chat.id`/`tj.chat.message.id`; проход подсказок — корневой `hint_pass` с исходом и счётчиками `HintPassResult` и дочерними спанами фаз (снимок корпуса, гашение выведенных правил, снимок журнала, гашение закрытых субъектов, котировки, оценка триггеров), детерминированный проход без LLM не несёт `gen_ai.*`; собственные атрибуты — с префиксом `tj.*`, имена semconv `gen_ai.*` не переименовываются. Sink — OTel SDK с собственным `BaseExporter<Activity>` (~30–40 строк), пишущим плоский JSONL span-per-line в `App_Data/traces/traces.jsonl` поверх `BatchActivityExportProcessor`: одна строка — один спан и самодостаточна для grep (ts/service/source/name/kind/trace_id/span_id/parent_span_id/duration_ms/status/status_desc/attrs/events; `events` — массив `{ts, name, attrs}`), запись фоновая и стриминг ответа не задевает; ротация по размеру при 10 МБ в `traces-{timestamp}.jsonl` с хранением 5 архивов. Захват metadata-only: `EnableSensitiveData` всегда `false` — полные тексты prompt/completion не пишутся никогда, записываются метаданные и метрики; аргументы тулов — компактно: обёртка над `AIFunction` в момент исполнения добавляет событие `tj.tool.args` на встроенный спан `execute_tool` — JSON аргументов, обрезанный до 2 КБ с маркером усечения, только на уровне `detailed`. Режим — всегда включено, без сэмплирования; уровень детализации из секции конфигурации `Tracing`: `Detail` (`basic` — имена, длительности, статусы, метрики `gen_ai.*`, корневые спаны; `detailed` — плюс события `tj.tool.args`; дефолт `detailed` — однопользовательский трафик, объём мизерный), `Dir`, `MaxFileBytes`, `KeepFiles`; отдельных событий итераций нет — задержки итераций читаются из длительностей встроенных `chat {model}`. Корреляция трасс с доменными записями — W3C TraceId корневого спана (32 hex, тот же идентификатор, что поле `trace_id` в JSONL и во вьюере): ответ помощника получает nullable `messages.trace_id` в момент фиксации (база чатов разворачивается EnsureCreated — колонка на новой базе, существующая пересоздаётся как одноразовый store окружения), созданные подсказки — nullable `hints.trace_id` (EF-миграция журнала), все записи одного прохода несут один id, гашение в `expired` id не получает; обратная связь «трасса → чат» — атрибуты `tj.chat.id`/`tj.chat.message.id` на `chat_turn`, покрывающие и отменённые ходы без записи-носителя; поля контрактов (`POST /api/hints/pass`, сообщение чата) — опциональные, null у записей до внедрения; колонки — метаданные отладки, ни одно доменное правило их не читает, отдельной таблицы проходов нет — журналом проходов остаётся файл трасс. Просмотр трасс — опция разработки, не обязанность приложения: именованная dev-опция — Arize Phoenix (один контейнер, OTLP gRPC :4317, автоматическая конвертация `gen_ai.*` в LLM-семантику UI на приёме; ELv2 допустима для внутреннего dev), запасная «нулевая» альтернатива — .NET Aspire Dashboard (MIT, без LLM-семантики); включение — конфигурацией, по умолчанию выключено; прод-режим и артефакт истины (JSONL) от Phoenix не зависят. Метрики трассы — per-trace; агрегированные сводки — вне этой карты.

## Considered Options

- Полные тексты prompt/completion (`EnableSensitiveData = true`) — отклонено: приватный контент владельца в файле и вьюере; standing-решение карты #79 запрещает; для диагностики хватает компактных аргументов тулов с капом 2 КБ.
- Готовый file-exporter OpenTelemetry — отклонён за отсутствием зрелого пакета (research #81): собственный `BaseExporter<Activity>` поверх `BatchActivityExportProcessor` — десятки строк, ротация своя.
- OTLP-батч (`ExportTraceServiceRequest`) в файле — отклонён: спан построчно не грепается, строка не самодостаточна; плоский span-per-line читается grep'ом и любым редактором.
- Обязательный внешний observability-backend — отклонён: против ADR-0003 (single-exe без обязательной инфраструктуры); Langfuse v4 — самый богатый LLM-UI, но 6 контейнеров (research #85); Phoenix — только dev-опция, Aspire Dashboard — запасная (#86).
- Сэмплирование или выключение трассировки по умолчанию — отклонено: однопользовательский локальный трафик даёт мизерный объём, а диагностика нужна в момент инцидента — трасса, которой нет, бесполезна.
- Отдельная таблица проходов подсказок в БД — отклонена (#83): журнал проходов — сам файл трасс, спаны `hint_pass` уже несут исход и счётчики; таблица дублировала бы файл.
- Свои дубликаты встроенных спанов M.E.AI — отклонены (#80): двойной учёт задержек и токенов; встроенная инструментация уже покрывает вызовы модели, стриминг и тулы.
- События по итерациям агентного цикла — отклонены (#82): задержки итераций читаются из длительностей встроенных `chat {model}`; лишние спаны шумят водопад.
- Переименование `gen_ai.*` в `tj.*` — отклонено: на semconv опирается LLM-семантика Phoenix; свои атрибуты только с префиксом `tj.*`.
