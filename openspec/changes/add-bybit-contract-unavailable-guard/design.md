# Design

## Context

См. proposal.md — Why. Технические факты, определяющие подход:

- `BybitResilience` ретраит только сеть/5xx, retCode 10006 и HTTP 403; отказ 110023 доходит до движка категории после одной попытки — конвейер повторов менять не нужно.
- Защита перебора уже существует для пограничного отказа: `RunWindowWithBoundaryGuardAsync` в обоих движках возвращает результат прохода либо `null` (пограничное исчерпание перебора); исход «область недоступна» — третий исход того же защитного контура.
- `BybitApiException` хранит `RetCode` и `RetMsg`, прецедент хелпера распознавания — `IsHistoryBoundaryError`.
- `ExecutionCategorySync` для option строит области по базовым активам (справочник биржи + `Sync:ExtraOptionBaseCoins` для делистнутых досок); linear и delivery-проход — единственная область без фильтра.
- `JournalSyncResult` уже несёт результаты обеих движков каждой категории до страницы `Sync.razor`; `SyncRun` хранит только счётчики новых записей.

## Goals / Non-Goals

**Goals:**

- Запуск с недоступной областью завершается успешно: отказ 110023 не прерывает перебор остальных областей и категорий, водяной знак фиксируется штатно.
- Пропуск области наблюдаем: перечень пропущенных областей возвращается в результатах движков и показывается пользователю.
- Детект отказа изолирован в одном месте рядом с прецедентом пограничного хелпера.

**Non-Goals:**

- Ретраи или бэкофф для 110023 — отказ детерминированный (свойство контракта, а не нагрузки), повтор запроса не меняет ответ.
- Изменение схемы `SyncRun` и хранилища состояния — факты пропуска живут в результатах запуска, страницы синка им достаточно.
- Изменение перечисления областей (`OptionBaseCoinSource`, конфиг делистнутых досок) — недоступные доски продолжают запрашиваться, чтобы подхватить их историю, когда биржа откроет доступ.
- Обработка отказов публичного `instruments-info` (пополнение справочника, сбор активов доски) — это market-data эндпоинт: по неизвестному символу он возвращает пустой список, а не отказ торговли.

## Decisions

### D1. Детект отказа — только по коду 110023

`BybitApiException` получает статический хелпер `IsContractUnavailableError`: `RetCode == 110023`, без анализа `RetMsg`. Биржа переиспользует код с разными текстами (в официальной таблице «Currently you can only reduce your position on this contract», фактически при отказе истории приходит «The contract is not available for trades»), поэтому текст в матч включать нельзя: хрупко в обе стороны. Код принадлежит семейству «контракт ограничен для торговли», и для обоих значений реакция одна — область недоступна для запроса.

*Альтернатива:* код плюс подстрока, как в `IsHistoryBoundaryError`, — отвергнуто: там код 10001 общий для всех ошибок параметров и подстрока различает смысл; здесь код самодостаточен, а требование совпадения текста вернуло бы падение запуска при смене формулировки биржей.

### D2. Третий исход защищённого прохода окна

`RunWindowWithBoundaryGuardAsync` обоих движков вместо пары «результат/`null`» возвращает исход прохода: успешный результат, пограничное исчерпание перебора, область недоступна. Отказ 110023 не ретраится и не зажимается — окно этой области больше не запрашивается. Частный случай: если 110023 придёт на курсорной странице уже начавшейся пагинации, ранее полученные страницы области остаются сохранёнными (пачки пишутся по окнам), оставшиеся окна области не запрашиваются.

*Альтернатива:* отдельный catch в цикле областей мимо guard-метода — отвергнуто: две точки перехвата ошибок биржи в одном цикле разъезжаются при правках; guard-метод — единственное место трансляции отказов биржи в исходы перебора.

### D3. Пропуск области обрабатывает цикл областей движка

На исходе «область недоступна» цикл областей помечает область пропущенной (метка: категория плюс базовый актив; для безфильтровой области — только категория) и завершает её обход: внутренний цикл окон области останавливается, внешний цикл переходит к следующей области. Для единственной области без фильтра (linear, delivery) пропуск означает завершение прохода категории — та же ветка кода, специального пути нет. Остальные области и категории догружаются как раньше; `HistoryExhausted` сохраняет смысл «перебор дошёл до пола глубины» и не отмечает пропуск.

*Альтернатива:* считать пропуск единственной области исчерпанием истории (`historyExhausted = true`) — отвергнуто: смешивает два разных факта — биржа отказала в доступе, а не история закончилась.

### D4. Водяной знак фиксируется штатно

Как в защитном контуре границы хранения: запуск с пропущенными областями успешен, монотонный водяной знак категории фиксируется. Обоснование: реальный триггер отказа — делистнутая доска, которая не создаёт записей в хвосте перебора, поэтому фиксация знака не теряет данные; отказ по живому контракту виден в перечне пропусков и повторяется каждым следующим запуском (хвост области перезапрашивается от водяного знака). Удержание знака при постоянном отказе навсегда деградировало бы инкремент всех областей категории.

*Альтернатива:* не фиксировать знак, пока есть пропуски, — отвергнуто: вечный перечит хвоста растущей ширины ради области, у которой биржа отказывает детерминированно; потерянный хвост транзиентного отказа в живой области догоняется ручным сбросом состояния категории (`requirement-manual-category-state-reset`).

### D5. Факты пропуска — в результатах движков, показ на странице синка

`ExecutionCategorySyncResult` и `DeliveryCategorySyncResult` получают перечень меток пропущенных областей (пустой, когда пропусков нет). `JournalSyncResult` уже доставляет результаты обеих движков до страницы `Sync.razor` — она показывает перечень отдельной заметкой рядом с результатом запуска. Схема БД, `SyncRun` и журнал запусков не меняются.

*Альтернатива:* колонка в `SyncRun` — отвергнуто: миграция и хранилищная обвязка ради факта, который и так доходит до пользователя в результате запуска; другие страницы ошибку синка и так показывают, а перечень пропусков — факт результата, место которому на странице синка.

## Risks / Trade-offs

- [Транзиентный отказ по живой области] → хвост области перезапрашивается каждым следующим запуском; при упорном отказе — ручной сброс состояния категории возвращает backfill.
- [Биржа переиспользует 110023 с другим смыслом] → эффект локализован пропуском одной области вместо падения всего запуска; в перечне пропусков видно, какая область отказывает, и поведенческая регрессия заметна сразу.
- [Пропуск единственной области выглядит как «синк без новых записей»] → заметка о пропущенных областях показывается рядом с результатом запуска, в том числе когда счётчики нулевые.
- [Отказ в середине пагинации области] → сохранённые страницы остаются, дедуп по `execId`/`symbol + deliveryTime` исключает дубли при повторных проходах.

## Migration Plan

Миграций схемы и конфигурации нет. После релиза запуск, падавший на 110023, завершается успешно с заметкой о пропущенных областях. Откат — revert изменения: поведение возвращается к падению запуска.
