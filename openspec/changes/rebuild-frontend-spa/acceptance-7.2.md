# Acceptance protocol 7.2 — cutover root→SPA

Цель: живая приёмка владельцем после переключения журнала на SPA в корне.

## 0) Подготовка

1. Запустить приложение в конфигурации приёмки.
2. Убедиться, что frontend собран (`frontend/dist` актуален).
3. Открыть чистое окно браузера (без старого кэша приложения).

## 1) Smoke маршрутизации хоста

1. Открыть `/` — должен загрузиться SPA index.
2. Открыть прямыми URL (без предварительного захода на `/`):
   - `/constructions/7` (или существующий id),
   - `/agent`,
   - `/sync-settings`.
   Для каждого маршрута должен загрузиться SPA index (клиентский роутер дорисует экран).
3. Проверить, что API остаётся доступным:
   - `GET /api/v1/meta` → `200` + JSON с `apiVersion`,
   - `GET /openapi/v1.json` → `200` + OpenAPI JSON.
4. Проверить, что безверсионный API не открылся:
   - `GET /api/meta` → `404`.

## 2) Smoke основных экранов SPA

1. На `/` проверить отрисовку раздела «Конструкции».
2. На `/agent` проверить загрузку списка чатов и каталога правил.
3. На `/sync-settings` проверить загрузку настроек и журнала синхронизаций.
4. На `/inbox` и `/hints` проверить, что экраны открываются и не падают.

## 3) Проверка удаления legacy Blazor-UI

1. Убедиться, что старые Blazor-страницы не используются в боевом пути.
2. Проверить, что корень не рендерит Blazor layout/табы.

## 4) Проверка удаления legacy consultation DB support

1. Выполнить «Собрать конструкции» из `/sync-settings`.
2. Убедиться, что операция проходит без логики обслуживания per-construction consultation SQLite.
3. Подтвердить решение: миграция legacy consultation DB **не выполняется**.

## 5) Критерии приёмки владельцем

- Root и клиентские SPA-маршруты стабильно открываются напрямую.
- `/api/v1/*`, OpenAPI и SSE-контракты не деградировали.
- Legacy Blazor-UI исключён из основного пользовательского потока.
- Legacy per-construction consultation DB support удалён без миграции.
