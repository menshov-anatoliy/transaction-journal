# Design

## Context

См. proposal.md — Why. Технические факты, определяющие подход:

- Пол backfill вычисляется в `ExecutionCategorySync`/`DeliveryCategorySync` как `startedAtMs - MaxBackfillDepthMs` (дефолт 730 дней) от `TimeProvider` — локальных часов.
- `BybitResilience` ретраит только сеть/5xx, retCode 10006 и HTTP 403; пограничный retCode 10001 доходит до движка после одной попытки — перехват на уровне движка не добавляет задержек.
- `BybitApiClient` уже поддерживает сверку серверного времени (`SyncTimeAsync`, `ServerTimeOffsetMs`) и отвечает за смещение часов подписанных запросов; шлюз `IBybitHistoryGateway` — единственная сеть-развязка движков, фиктивные шлюзы в тестах его реализуют.
- `BybitApiException` хранит `RetCode` и тело ответа, но не хранит `retMsg` отдельно; сообщение об ошибке попадает только в текст исключения.
- Граница хранения биржи («2 года») не задокументирована точно: сравнение выполняет биржа по своему серверному времени, календарные «2 года» дают 730–731 день в зависимости от високосности периода.

## Goals / Non-Goals

**Goals:**

- Backfill и инкрементальная догрузка завершаются успешно при любой конфигурированной глубине: запросы не заходят за границу хранения биржи.
- Пограничный отказ биржи — защитный контур второго уровня: ретрай зажатого окна, затем исчерпание истории вместо неуспешного запуска.
- Рассинхрон локальных часов перестаёт влиять на положение границы перебора.

**Non-Goals:**

- Уточнение точной семантики границы биржи (календарные месяцы против 730 дней) — запас делает расхождение несущественным.
- Догрузка истории глубже границы хранения биржи — её не отдаёт сама биржа.
- Изменение конвейера повторов `BybitResilience` — пограничная ошибка не ретраится и сегодня.
- Изменение семантики `Sync:MaxBackfillDepthDays` и `BackfillBoundaryMs`.

## Decisions

### D1. Граница хранения биржи — константа с запасом, clamp пола

Глубина хранения биржи — константа `ExchangeStorageDepthMs` = 730 дней, запас `BoundarySafetyMarginMs` = 7 дней (ширина одного execution-окна). Самая ранняя запрашиваемая дата: `allowedEarliestMs = serverNowMs - ExchangeStorageDepthMs + BoundarySafetyMarginMs`. Пол перебора: `floorMs = Math.Max(configuredFloorMs, allowedEarliestMs)` — «позднейший из двух», глубина из конфигурации не может пробить границу. Эффективный дефолт глубины становится 723 дня: потеря максимум недели истории относительно идеала — принятая цена гарантии успеха запуска.

*Альтернативы:* снизить дефолт `MaxBackfillDepthDays` до 720 — отвергнуто: два независимых источника истины о границе, конфиг перестаёт выражать желаемую глубину; считать границу по локальному времени — отвергнуто: рассинхрон часов — часть проблемы.

### D2. Серверное время — через шлюз истории

`IBybitHistoryGateway` расширяется методом `GetServerTimeMsAsync(CancellationToken)`; реальный шлюз читает серверное время через клиент (`SyncTimeAsync` возвращает время биржи, смещение уже поддерживается для подписи запросов). Движок запрашивает серверное время один раз на запуск категории и хранит его в локальной переменной прохода. Если запрос серверного времени не удался — используется локальное время `TimeProvider` как запасной вариант: clamp D1 всё равно защищает от выхода за границу, а запас 7 дней покрывает остаточный дрейф.

*Альтернатива:* прокинуть `BybitApiClient` в движки напрямую мимо шлюза — отвергнуто: ломает единственный сетевой порт движков и проверяемость на фиктивных шлюзах.

### D3. Детект пограничной ошибки — по коду и подстроке

`BybitApiException` получает свойство `RetMsg` (конструктор его уже принимает) и статический хелпер `IsHistoryBoundaryError`: `RetCode == 10001` и `retMsg` содержит `earlier than 2 years` (сравнение без учёта регистра). Биржа не выделяет пограничному отказу собственный retCode — текст единственный различающий сигнал. Хелпер изолирует хрупкий матч в одном месте; ложное срабатывание на другую ошибку параметров маловероятно (нужны и код, и подстрока), ложное не-срабатывание при изменении текста биржей возвращает поведение к статус-кво — clamp D1 остаётся основным контуром.

*Альтернатива:* трактовать любой 10001 в переборе как исчерпание — отвергнуто: замаскирует реальные ошибки параметров запроса.

### D4. Ретрай с зажимом на уровне движка, затем исчерпание

Окно запрашивает `ExecutionWindowPass`/`DeliveryWindowPass`; перехват ошибки выполняет движок категории, не проход: исключение от `RunAsync` окна проверяется хелпером D3; при совпадении и неуспешном ретрае — проход окна повторяется один раз с `windowStartMs = allowedEarliestMs` (граница из D1/D2 этого же запуска). Повторный пограничный отказ означает, что запаса не хватило: перебор истории категории считается исчерпанным — оставшиеся окна и области (граница времени, не актива: отказ неизбежен для всех областей одинаково) не запрашиваются, `historyExhausted = true`, движок завершается успехом, водяной знак фиксируется штатно. После успешного зажатого окна цикл завершается естественно: следующий пол совпадает с границей, условие `while windowEndMs > floorMs` выполняться перестаёт. В инкрементальном режиме нижняя граница `targetStartMs` зажимается тем же clamp-ом, пограничный отказ обрабатывается так же — исчерпанием хвоста.

*Альтернатива:* ретрай внутри прохода окна — отвергнуто: проход не знает о границе запуска и семантике исчерпания категории; дублировать её туда — размывать ответственность.

### D5. Общий расчёт границы — один маленький хелпер

Арифметика границы (константы D1 + вычисление `allowedEarliestMs` и clamp пола) выносится в общий статический хелпер в `Sync`, используемый обоими движками: execution- и delivery-движки не должны разъехаться в константах. Модульные тесты фиксируют арифметику (глубина из конфига больше границы — пол зажат; меньше — пол не тронут).

## Risks / Trade-offs

- [Текст retMsg изменится на бирже] → детект изолирован в хелпере D3; основной контур — clamp D1, ошибочный путь остаётся редким; при изменении текста поведение деградирует к текущему (падение запуска), не хуже статус-кво.
- [Потеря до 7 дней истории у границы] → принятый trade-off запаса; `BackfillBoundaryMs` продолжает фиксировать фактическую самую раннюю запись.
- [Серверное время недоступно при запуске] → fallback на локальное время (D2): clamp всё равно держит запросы в разрешённой зоне за счёт запаса.
- [Расхождение календарных «2 лет» (730–731 день) с константой] → запас 7 дней покрывает максимум расхождения (1 день) плюс дрейф времени между замером и запросами.
- [Пограничный отказ в середине пагинации окна (не на первой странице)] → на практике биржа валидирует startTime на первом запросе; если отказ случится на курсорной странице, ретрай окна с начала зажатым диапазоном всё равно корректен: дедупликация по `execId`/`symbol + deliveryTime` исключает дубли.

## Migration Plan

Миграций схемы и конфигурации нет. После релиза просто запустить «Синхронизировать»: backfill завершится у границы, водяной знак зафиксируется. Откат — revert изменения; конфиг-воркараунд `Sync:MaxBackfillDepthDays=720` остаётся доступным независимо.

## Open Questions

- Точная семантика границы биржи (календарные 24 месяца против 730 дней, строгость сравнения) может быть уточнена запросом в поддержку Bybit; на выбранный подход с запасом ответ не влияет.
