# Proposal

## Why

Первый backfill не может завершиться: пол глубины по умолчанию равен ровно 730 дням и вычисляется по локальным часам, поэтому последнее окно уходит с `startTime` на границе хранения истории Bybit (≈2 года) или раньше неё. Биржа отбраковывает запрос с `retCode=10001` («Can't query order earlier than 2 years»), запуск помечается неуспешным, водяной знак не фиксируется — и каждый повторный запуск заново листает весь backfill, чтобы упасть на том же окне. Практика первого бэкфилла закрыла открытый вопрос №1 из `docs/research/bybit-api.md`: глубина хранения ограничена, и граница строже, чем «730 локальных дней».

## What Changes

- Clamp пола глубины по границе хранения биржи: пол backfill и нижняя граница инкрементального перебора не заходят за самую раннюю запрашиваемую дату биржи, вычисленную по серверному времени Bybit с фиксированным запасом. Конфигурируемая глубина `Sync:MaxBackfillDepthDays` сохраняется, но не может пробить границу биржи.
- Расчёт границы по серверному времени биржи: шлюз истории отдаёт серверное время Bybit (клиент уже поддерживает сверку смещения по `/v5/market/time`), устраняя влияние рассинхрона локальных часов.
- Graceful-обработка пограничной ошибки: отказ биржи «раньше двух лет» во время перебора истории не прерывает запуск. Окно, пересекающее границу, один раз повторяется с `startTime`, зажатым до границы; если и этот запрос отклонён, перебор истории категории считается исчерпанным, и запуск завершается успешно с фиксацией водяного знака.
- До внедрения изменения доступен временный конфиг-воркараунд `Sync:MaxBackfillDepthDays=720`, но решение в коде его не требует: граница соблюдается автоматически.

## Capabilities

### New Capabilities

_Нет._

### Modified Capabilities

- `sync/bybit-history`: изменяется требование `requirement-backfill-full-history` (пол перебора clamp-ится к границе хранения биржи по серверному времени; пограничный отказ биржи завершает перебор, а не запуск). Добавляется требование `requirement-history-boundary-guard` о защите перебора истории от границы хранения: clamp по серверному времени, ретрай зажатого окна, трактовка пограничного отказа как исчерпание истории.

## Impact

- `src/TransactionJournal/Sync`: `ExecutionCategorySync` и `DeliveryCategorySync` — вычисление пола через границу биржи, перехват пограничной ошибки в backfill-цикле, ретрай с зажатым окном, семантика исчерпания; `IBybitHistoryGateway` — новый метод серверного времени; фиктивные шлюзы в тестах.
- `src/TransactionJournal/Bybit`: `BybitApiClient` — проброс серверного времени (уже есть `SyncTimeAsync`/`ServerTimeOffsetMs`); `BybitApiException` — хранение `retMsg` и хелпер распознавания пограничной ошибки (прецедент: `FromAccessBlocked`); `BybitResilience` пограничную ошибку не ретраит — изменений конвейера не требуется.
- Конфигурация: без новых ключей; запас до границы — константа в коде.
- Тесты: `tests/TransactionJournal.Tests/Sync` (clamp пола, ретрай, исчерпание), `tests/TransactionJournal.Tests/Bybit` (детект ошибки, серверное время шлюза).
- Документация: `docs/research/bybit-api.md` — закрыть открытый вопрос №1 фактом границы и поведения API.
