## 1. Превью в списковом контракте (бэкенд)

- [ ] 1.1 Порт и конвейер чатов: при перечислении чатов (активные и завершённые) списковая запись дополняется текстом первого сообщения владельца — берётся из истории чата, первое по порядку, а не последнее; пустая/битая история даёт пустое превью без ошибки. Юнит-тесты хранилища: превью первого сообщения владельца у обоих статусов, отличие от последнего сообщения, толерантность к пустой истории. Проверить: `scenario-chat-list-preview-of-first-owner-message`, `scenario-chat-list-preview-uses-first-message`.
- [ ] 1.2 API: `AgentChatDto` списка `GET /api/v1/chats?status=` дополняется полем превью; `BuildChatDtoAsync` берёт его из того же чтения истории, что и `lastMessageAt` (новых запросов к БД на пункт нет); текст не обрезается на сервере. Юнит-тесты эндпоинта: поле присутствует в обоих списках, полный текст первого сообщения владельца. Проверить: `scenario-chat-list-preview-of-first-owner-message`.
