# Proposal

## Why

Сборка конструкций сегодня существует только как полный пересбор, стирающий все ручные данные, поэтому её нельзя безопасно запускать после очередной синхронизации. Правила группировки расходятся с фактической практикой трейдера (ноги одной конструкции собираются днями, при нескольких живых конструкциях одного актива усреднение не работает, имена не отражают «смысл опционной основы» — акцент, ratio, направление), а конструкции с исчезнувшим опционным прикрытием остаются в статусе «открыта». Источник правил — Excel «Сделки Bybit» (дневные кластеры, многодневные ноги, роллы) и протоколы сделок в Obsidian (лексика «стреддл с акцентом вверх», «прикрытый интродэй»); явной группировки в Excel нет — правила выведены из данных и зафиксированы в ADR-0004 и ADR-0005.

## What Changes

- Новый режим **«Сборка из „Входящих"»**: детерминированная сборка только из нераспределённых записей «Входящих»; запуск вручную кнопкой, без диалога подтверждения; существующие конструкции читаются как контекст остатков, а их капитал, комментарии, корректировки PnL, риск/профит и ручные привязки не затрагиваются (ADR-0004).
- Полный пересбор остаётся отдельным аварийным режимом для чистой базы — с подтверждением и стиранием, как сейчас.
- **Эвристика доски**: при нескольких живых конструкциях актива одноногое окно усредняется в единственного живого кандидата с ногой той же экспирации; при отсутствии или неоднозначности кандидата окно открывает новую конструкцию.
- **Статус следует за прикрытием**: сборка переводит конструкцию в «закрыта», когда все её опционные ноги обнулены сделками или экспирацией, и возвращает «открыта» при повторном появлении ненулевой опционной ноги; «архив» — строго ручной статус, сборкой не трогается.
- **Производный нейминг**: имя пересчитывается из текущего состава живых опционных ног по лексике трейдера («стреддл с акцентом вверх 2:1», «симметричный стреддл», «стренгл», «колл-спред/пут-спред» c ratio, «направленная CALL/PUT»); ручное переименование фиксирует имя — признак в базе отключает автогенерацию для конструкции (ADR-0005).
- Принятое расхождение режимов: ролл, разрезанный границей синхронизации, в инкременте откроет новую конструкцию, пересбор соединил бы ролл; исправление — ручная привязка (ADR-0004).
- Фьючерсные сделки робота привязываются по активу и периоду опционного прикрытия, как сейчас; вне периода — остаются во «Входящих».

## Capabilities

### New Capabilities

_(нет — все изменения ложатся в существующие capability)_

### Modified Capabilities

- `domain/construction-assembly`: новый requirement инкрементной сборки из «Входящих»; расширение правила усреднения эвристикой доски; новый requirement статуса, следующего за прикрытием; новый requirement производного нейминга; уточнение пересбора — имена и статусы строятся по тем же правилам.
- `domain/constructions`: управление статусом — «открыта»/«закрыта» автоматических конструкций управляются сборкой по факту прикрытия, «архив» строго ручной; переименование дополнительно фиксирует имя и отключает автогенерацию.
- `ui/screens`: экран «Настройки» получает команду «Собрать из „Входящих"» без подтверждения с итогами; команда полного пересбора сохраняет подтверждение и перечень потерь.

## Impact

- `src/TransactionJournal/Domain/ConstructionAssembly/`: `ConstructionAssembler` (эвристика доски, пересчёт имени и статуса при изменении ног), `ConstructionAssemblyService` (инкрементный use-case, чтение существующих конструкций из базы как контекста), `ConstructionNameBuilder` (лексика трейдера, акцент, ratio, направление).
- `src/TransactionJournal/Data/`: `Construction` — признак «имя зафиксировано вручную» (миграция SQLite).
- `src/TransactionJournal/Components/Pages/Settings.razor`: новая команда сборки и итоги.
- `tests/TransactionJournal.Tests/`: `Domain/ConstructionAssembly/*`, `Domain/ConstructionServiceTests`, `Ui/SettingsScreenTests`; контрольная сверка истории обновляется под производные имена.
