# Proposal

## Why

Бэкенд оспаривания синтетических связок готов целиком: команды `synthetic-closes/dispute` и `/revert` работают, признак `disputed` приходит в `syntheticCloses[]` карточки. Но в UI действие отсутствует — пользователь не может оспорить ложное срабатывание распознавателя из интерфейса, хотя design change `synthetic-close-logical-layer` называет оспаривание штатным выходом при ложной связке (хедж-сделка совпала с опционом по доске и количеству). Сейчас спор возможен только прямым POST-запросом.

## What Changes

- Под строкой «зафиксировано синтетикой» в сводке деталей появляется раскрывающийся список распознанных связок: закрываемая нога, количество, лок к экспирации, признак спора.
- Каждая неоспоренная связка получает действие «Оспорить», каждая оспоренная — «Вернуть»; после действия карточка перечитывается, логический слой обновляется ближайшим чтением.
- Оспоренная связка остаётся видимой в списке с признаком спора и не участвует в локе и логическом размере ноги.
- API-клиент frontend дополняется функциями `disputeSyntheticClose` / `revertSyntheticClose` к существующим эндпоинтам.
- design.pen пополняется мастером раскрывающегося списка связок.

## Capabilities

### New Capabilities

_None_ — поведение принадлежит существующему экрану деталей.

### Modified Capabilities

- `ui/screens`: в экран деталей добавляется требование о списке связок с ручным оспариванием и возвратом — расширение синтетической строки, введённой change `synthetic-close-logical-layer`.

## Impact

- `frontend/src/lib/api/construction-card.ts` — две новые клиентские функции к готовым эндпоинтам.
- `frontend/src/components/constructions/card/` — раскрывающийся список связок в сводке (metric-strip или новый компонент), команды спора в `use-card-commands`, компонентные тесты.
- Контракт карточки дополняется аддитивно: строка `syntheticCloses[]` получает пару `linearExecId`/`counterOptionExecId` — без неё UI не может вызвать готовые эндпоинты `dispute`/`revert`; read-model уже держит эти идентификаторы в руках. Обновляется OpenAPI-описание.
- `design.pen` — мастер списка связок; скриншот-сверка.
- Бэкенд-команды и их семантика не меняются: эндпоинты dispute/revert и признак `disputed` развёрнуты change `synthetic-close-logical-layer`.
