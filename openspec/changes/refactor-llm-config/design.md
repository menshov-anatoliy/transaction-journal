# Design

## Context

Сейчас модель чата консультаций конфигурируется секцией `Consultations:ChatModel` (`ConsultationChatModelOptions.Resolve`: дефолты z.ai/GLM-5.3, правило «сторонний провайдер — явный эндпоинт», тримминг), а секция `Llm` читается только как запасной источник ключа (`Program.cs`: `Consultations:ChatModel:ApiKey ?? Llm:ApiKey`). Приложение собирает OpenAI-совместимый клиент лениво (`CreateConsultationChatClient`), незастроенный ключ обнаруживается в момент первого вопроса. Схема проектов (ADR-0008): проекты окружений (`Consultations`, `Hints`) не ссылаются друг на друга и на Web — общие типы между ними возможны только через composition root. Потребитель `Llm:Hint` — изложение сводок — появится в change `add-summary-channels` (задача 4.3).

## Goals / Non-Goals

**Goals:**

- Единственная точка правды для параметров провайдера: резолв `Llm:Provider`/`BaseUrl`/`ApiKey` и правило стороннего провайдера живут в одном месте composition root.
- Подсекции `Llm:Chat:Model` и `Llm:Hint:Model` задают только рабочие модели, с дефолтами в коде.
- Контракт `Llm:Hint` исполним и покрыт тестами до появления потребителя.

**Non-Goals:**

- Переопределение эндпоинта или ключа на уровне подсекции — только модель (решение владельца).
- Реализация изложения сводок — только контракт и резолв; код изложения приходит с `add-summary-channels`.
- Правка артефактов `add-summary-channels`: его спека не фиксирует путь конфига, задача 4.3 просто потребляет `Llm:Hint`.

## Decisions

### D1. Общий резолв провайдера — в composition root, потребительские записи — в проектах окружений

Новый статический резолвер в Web (`LlmProviderSettings.Resolve`) один раз читает `Llm:Provider`, `Llm:BaseUrl`, `Llm:ApiKey`: применяет дефолты (`zai`, `https://api.z.ai/api/paas/v4`), проверяет правило «провайдер ≠ `zai` → явный `BaseUrl`» и нормализует слэш. `ConsultationChatModelOptions` (Consultations) и новый `HintChatModelOptions` (Hints) остаются records с дефолтами моделей (`glm-5.3`, `glm-5.3-flash`) и собираются из общих настроек плюс своей подсекции.

Альтернатива — оставить полный `Resolve` с правилом в каждом проекте окружения: отклонена, потому что проекты не ссылаются друг на друга и правило «сторонний провайдер требует эндпоинт» пришлось бы дублировать вместе с тестами; вынос в composition root даёт одну точку правды. Вторая альтернатива — общий тип в Domain/Application: отклонена, конфигурация провайдера не домен.

### D2. Нормализация trailing slash в резолвере

`BaseUrl` без завершающего слэша дополняется им. OpenAI .NET SDK строит URL запроса от эндпоинта, и его документированные примеры задают базу со слэшем; нормализация делает обе формы конфига эквивалентными независимо от склейки путей внутри SDK. Альтернатива — требовать слэш в конфиге: отклонена, ошибка настройки была бы немой (запросы уходили бы не туда без явного сбоя).

### D3. `HintChatModelOptions` регистрируется в DI до появления потребителя

Composition root регистрирует singleton `HintChatModelOptions` сразу: контракт исполним, покрыт тестами, изложение из `add-summary-channels` внедряет готовую зависимость без правки конфигурации или резолва. Альтернатива — отложить тип до потребителя: отклонена по явному решению владельца (подсекции задаются этим change'ом, изложение только потребляет).

### D4. Единый эндпоинт для всех потребителей

Чат консультанта переходит с coding-эндпоинта (`/api/coding/paas/v4/`) на общий `https://api.z.ai/api/paas/v4`, заданный владельцем. Возможность per-consumer эндпоинтов не сохраняется: она и породила рассинхрон (чат на coding-тарифе, «общая» секция указывала на общий адрес и читалась наполовину). При проблемах с тарифом адрес меняется `Llm:BaseUrl` без правки кода.

## Risks / Trade-offs

- [Смена эндпоинта меняет тариф/квоты z.ai для чата] → осознанное решение владельца; откат — правка `Llm:BaseUrl` в конфиге.
- [`Llm:Hint` временно никем не читается] → контракт зафиксирован спекой `config/llm-provider` и резолвером с тестами; период простоя ограничен change `add-summary-channels`.
- [Ломающая смена конфига: старая `Consultations:ChatModel` молча игнорируется] → ключ владельца уже лежит в `Llm:ApiKey`, миграция локального файла сводится к переносу модели и удалению старой секции; при незастроенном ключе ошибка ленивая, журнал работает.
- [Шаблон `appsettings.Local.json.example` уже рассинхронизирован (`Llm:ZaiApiKey` никогда не читался)] → чинится этим change'ом.

## Migration Plan

1. Код и шаблон обновляются одним change'ом; приложение после обновления читает только новую схему.
2. Владелец правит локальный `appsettings.Local.json`: секция `Llm` получает `Provider`/`BaseUrl`/`ApiKey` и подсекции `Chat`/`Hint`, секция `Consultations:ChatModel` удаляется.
3. Откат: git revert кода и возврат прежних секций в локальном файле; локальный файл вне репозитория, при пустой секции `Llm` приложение запускается, а потребитель сообщает о незастроенном ключе лениво.

## Open Questions

Нет: эндпоинт и имена подсекций заданы владельцем.
