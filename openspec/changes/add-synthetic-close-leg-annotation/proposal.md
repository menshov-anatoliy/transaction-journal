# Proposal

## Why

Действующая синтетическая связка (распознанная без спора или ручная) закрывает часть длинной опционной ноги, но на строке самой опционной ноги в таблице позиций карточки деталей это никак не видно: распад остатка с синтетическим содержимым показывает только линейная нога («синтетика X · прочее Y»), а опционная нога выглядит нетронутой — факт закрытия приходится искать в сводной строке синтетики и списке связок.

## What Changes

- В таблице позиций карточки деталей опционная нога с действующими синтетическими связками получает признак закрытия синтетикой: под инструментальным остатком вторичная строка «закрыто синтетикой X · открыто Y» — зеркально распаду остатка линейной ноги; инструментальный остаток в главной строке не меняется.
- X — сумма количеств действующих связок по символу закрываемой ноги, без клэмпа остатком; Y = остаток − X показывается как есть, включая отрицательные значения (частичное закрытие ноги «ручной пометкой закрытия» после связки).
- Признак показывается при любых действующих связках, включая строки инструментально закрытых позиций (`isOpen=false`).
- Тултип на ячейке остатка поясняет состав признака и неизменность инструментального остатка.
- Значения считаются на бэкенде в строках позиций карточки (пара полей, `null`/`null` без действующих связок по ноге); фронт только рендерит.
- В `GLOSSARY.md` фиксируется термин «Признак закрытия синтетикой», отделённый от «ручной пометки закрытия».

## Capabilities

### New Capabilities

(нет — изменение живёт в существующих capability)

### Modified Capabilities

- `domain/synthetic-close`: логический слой публикует по каждой опционной ноге величины признака закрытия синтетикой — сумму количеств действующих связок по символу ноги и остаток после вычета, без изменения инструментальных метрик.
- `ui/screens`: таблица позиций карточки деталей показывает на опционной ноге признак закрытия синтетикой (вторичная строка и тултип) при действующих связках ноги.

## Impact

- `design.pen` — правка вносится в макет до frontend-влияния: новый мастер-паттерн признака на опционной ноге по образцу распада остатка линейной ноги, оба состояния (есть/нет действующих связок); затем перенос во frontend и скриншот-сверка.
- Бэкенд: строки позиций карточки (`ConstructionDetailRows`, read model построения деталей) — новые поля `syntheticClosedQuantity`/`syntheticOpenQuantity`; источники — уже определённые действующие связки (распознанные минус оспоренные плюс ручные).
- Frontend: типы ответа карточки (`construction-card.ts`), таблица позиций (`positions-table.tsx`) — рендер пары полей и тултип.
- Тесты: read model (значения и `null`-семантика), тесты таблицы позиций, миграций нет — поля вычисляются при чтении.
- `GLOSSARY.md` — новый термин.
- Инструментальные метрики, остатки, P&L, `isOpen`/`closedAt`, статус, предупреждения, список конструкций и сводная величина «с учётом зафиксированного синтетикой» не меняются.
