# Proposal

## Why

Журналу нечем принимать данные, поступление которых уже спекфицировано: change `add-bybit-sync` (тикет [#8](https://github.com/menshov-anatoliy/transaction-journal/issues/8)) кладёт новые сделки во «Входящие» и выводит закрывающие записи экспираций, но в журнале пока нет конструкций, привязок, корректировок и пометок. Семантика домена зафиксирована решениями карты ([#1](https://github.com/menshov-anatoliy/transaction-journal/issues/1)), гриллингом edge-cases ([#5](https://github.com/menshov-anatoliy/transaction-journal/issues/5)), глоссарием CONTEXT.md и ADR-0001/ADR-0002; этот change переносит её в формальную спеку.

## What Changes

- Управление конструкциями: создание с именем и выделенным капиталом, свободное переименование, ручной статус («открыта» по умолчанию; архивация скрывает из активных списков, оставляя конструкцию в аналитике), удаление только без сделок и внешних корректировок PnL.
- Выделенный капитал — текущее значение в USDT без истории изменений; база для процентов результата.
- Привязка сделок: каждая сделка принадлежит ровно одной конструкции или находится во «Входящих»; перенос и возврат во «Входящие» в любой момент; позиции и результаты — производные, пересчитываются при чтении.
- Позиция — производный чистый остаток по инструменту внутри конструкции, агрегат сделок и закрывающих записей; напрямую не редактируется.
- Закрытие позиции — обнуление остатка: встречными сделками, закрывающими записями delivery/OTM из синхронизации (ADR-0002) или ручной пометкой — fallback для инструментов без биржевых записей; цена задаётся пользователем, по умолчанию последняя марка; пометка свободно правится и удаляется.
- Внешние корректировки PnL — слагаемые результата конструкции без сделки (PnL робота, ручные поправки); свободная правка и удаление, без журнала аудита в MVP.
- Комментарии трёх уровней — на сделке, позиции и конструкции; комментарий позиции хранится по ключу «конструкция × инструмент» и переживает пересчёты.

## Capabilities

### New Capabilities

- `domain/constructions`: управление доменом журнала — конструкции, выделенный капитал, привязка сделок через «Входящие», производные позиции и их закрытие, внешние корректировки PnL, комментарии.

## Impact

- Новые таблицы SQLite/EF Core: конструкция, пользовательские данные сделок (привязка, комментарий), комментарии позиций, ручные пометки закрытия, внешние корректировки PnL.
- Слой доменных use-case сервисов и read-модель позиций — точка потребления для UI (тикет [#12](https://github.com/menshov-anatoliy/transaction-journal/issues/12)) и MCP-сервера (тикет [#11](https://github.com/menshov-anatoliy/transaction-journal/issues/11), только чтение).
- Расчёт реализованного/нереализованного PnL и метрик не входит — capability аналитики (тикет [#10](https://github.com/menshov-anatoliy/transaction-journal/issues/10)).
- Опирается на CONTEXT.md и ADR-0001/ADR-0002; изменений глоссария не требует.
