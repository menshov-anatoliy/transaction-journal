# Proposal

## Why

Реальный прогон синхронизации и разбор журнала выявили два дефекта устойчивости к делистнутым инструментам. Первый: пополнение справочника запрашивает спецификацию по символу у биржи, и по делистнутому опциону биржа отвечает отказом 110023 «The contract is not available for trades» — отказ не защищён существующим guard-контуром (он покрывает только окна перебора истории), поэтому запуск падает целиком уже после сохранения сырых записей; именно так упал единственный реальный запуск журнала (статус Failed, 1727 сохранённых исполнений при неполном справочнике). Второй: базовый актив делистнутой опционной доски отсутствует в живом справочнике биржи, область перебора не строится вовсе — исполнения этого актива не загружаются безмолвно (в реальном журнале 6 delivery-записей ETH-опционов при нуле исполнений ETH), и никакой факт дыры покрытия пользователю не виден.

## What Changes

- Пополнение справочника инструментов обрабатывает отказ биржи 110023 «контракт недоступен» как локальную некритичную ошибку: спецификация символа пропускается без ретрая, факт пропуска фиксируется перечнем неразрешённых символов, запуск продолжается и завершается успешно.
- Материализация журнала деградирует по неразрешённым символам вместо полного отказа: сделки и закрывающие записи строятся из разрешимых записей, символы без спецификации собираются в предупреждение (по прецеденту предупреждений сверки `deliveryRpl`), экран синхронизации показывает перечень неразрешённых символов.
- Видимость дыры покрытия: запуск сравнивает базовые активы delivery-записей и исполнений категории option с фактически пройденными областями доски и сообщает о активах, чья история не обходится, с подсказкой про конфигурацию дополнительных активов доски и сброс состояния категории.
- Документация исследования Bybit API пополняется фактом отказа 110023 на эндпоинте спецификаций.

## Capabilities

### New Capabilities

_Нет._

### Modified Capabilities

- `sync/bybit-history`: модифицируется требование `requirement-instrument-reference` — пополнение справочника пропускает спецификации недоступных инструментов с фиксацией факта; добавляются требования деградации материализации по неразрешённым символам и видимости непокрытых базовых активов доски.

## Impact

- `src/TransactionJournal/Sync/InstrumentReferenceSync.cs` — перехват отказа «контракт недоступен» при запросе спецификации, пропуск символа, перечень пропущенных спецификаций в результате.
- `src/TransactionJournal/Sync/JournalSyncService.cs`, `JournalSyncResult.cs` — проведение перечня неразрешённых символов и непокрытых активов доски в итог запуска.
- `src/TransactionJournal/Materialization/JournalMaterializer.cs`, `TradeMaterializer.cs`, `ExpiryMaterializer.cs`, `JournalMaterializationResult.cs` — сбор неразрешённых символов в предупреждение вместо исключения при отсутствии символа в справочнике; прочие причины свера (расхождения с справочником) остаются ошибками.
- `src/TransactionJournal/Components/Pages/Sync.razor` — показ неразрешённых символов и непокрытых активов рядом с результатом запуска.
- Read-модели (`InboxReadModel` и прочие над `TradeMaterializer`) — получают деградацию транзитивно через материализатор, собственный контракт не меняется.
- Тесты: `tests/TransactionJournal.Tests/Sync`, `tests/TransactionJournal.Tests/Materialization`, `tests/TransactionJournal.Tests/Ui`.
- Схема БД и конфигурация: без изменений; восстановление реального журнала — эксплуатационный шаг (конфигурация `Sync:ExtraOptionBaseCoins` со значением ETH и сброс состояния категории option), кода не требует.
