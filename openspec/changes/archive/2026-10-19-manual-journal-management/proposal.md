# Proposal

## Why

Журнал невозможно вести без синхронизации с Bybit: сделки попадают в него только через sync, и без API-ключей журнал пуст — нельзя внести ни одной сделки. Нужен полноценный ручной режим: добавление, правка и удаление сделок вручную, включая ручное управление синтетическими связками (сейчас есть только автораспознавание и оспаривание). Решение зафиксировано в ADR-0018; закрывающие записи и внешние корректировки PnL сохраняются — их назначение не покрывается ручными сделками.

## What Changes

- Ручной ввод сделок: создание, правка и удаление пользователем с признаком источника «ручной ввод»; ручная сделка полноправна — те же остатки, FIFO, метрики и сборка, что у биржевых.
- Журнал работоспособен без настройки Bybit-ключей и без единой синхронизации (ручной режим).
- Синхронизированные сделки неизменяемы; sync не трогает ручные сделки; дубликат одного исполнения, внесённого вручную и пришедшего синхронизацией, не дедуплицируется автоматически — его разрешает пользователь.
- Символ инструмента при ручном вводе проверяется и обогащается публичным эндпоинтом `instruments-info` без API-ключей; разбор строки символа источником метаданных не становится.
- Ручное создание синтетической связки из двух сделок одной конструкции с инструментальной валидацией (совпадение страйка/экспирации, согласованность количеств), без 60-минутного окна; свободное удаление, редактирование — пересозданием.
- Ручная пометка закрытия становится штатным способом закрытия в ручном режиме (не только fallback при делистинге) и получает опциональное количество (null = весь остаток).
- UI: создание сделки из «Входящих» (в общий пул) и из карточки конструкции (сразу с привязкой), бейдж источника у записей, подсказка внутренней стоимости для ITM-экспираций при закрытии пометкой.
- Валидация ручной сделки: дата не в будущем, количество > 0, цена > 0, комиссия ≥ 0.

## Capabilities

### New Capabilities

- `domain/manual-trades`: ручной ввод сделок журнала — CRUD, признак источника, валидация, точки входа («Входящие» и карточка конструкции), сосуществование с синхронизацией, переживание пересбора.

### Modified Capabilities

- `domain/constructions`: ручная пометка закрытия повышается с fallback до штатного способа ручного режима, добавляется опциональное количество (requirement-position-close-lifecycle).
- `domain/synthetic-close`: добавляется требование ручного создания связки поверх автораспознавания и оспаривания.
- `sync/bybit-history`: справочник инструментов пополняется также символом, введённым вручную, тем же публичным эндпоинтом (requirement-instrument-reference).
- `ui/screens`: действия ручного ввода на экранах «Входящие» и «Детали конструкции», бейдж источника записи, форма ручной связки, количество в пометке закрытия.

## Impact

- Backend: `TransactionJournal.Domain` (источник у сделки, количество у ManualCloseMark), Application (сервис ручных сделок, переиспользование пополнения справочника), API (CRUD-endpoints сделок и ручных связок), Infrastructure (маппинг EF).
- Design: макеты новых UI-элементов (формы ручной сделки и связки, бейдж источника, пометка с количеством) сначала вносятся в `design.pen` (ADR-0011).
- Frontend: формы создания/правки ручной сделки, бейдж источника, количество в пометке, форма ручной синтетической связки — переносятся по обновлённому макету со скриншот-сверкой.
- Документация: ADR-0018, CONTEXT.md (уже обновлены в grill-сессии).
- Новых зависимостей нет: публичный эндпоинт спецификаций уже используется пополнением справочника.
