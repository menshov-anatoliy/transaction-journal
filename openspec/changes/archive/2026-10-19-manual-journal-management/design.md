# Design

## Context

См. proposal.md — Why. Сейчас сделки существуют только как материализация `RawExecutions` из синхронизации (`JournalMaterializer`/`TradeMaterializer`); признака источника у сделки нет. Справочник инструментов наполняет `InstrumentReferenceSync` через публичный эндпоинт `instruments-info` (`IBybitInstrumentSource` + `IInstrumentReferenceStore`). Синтетические связки — `SyntheticCloseRecognizer` + `SyntheticCloseDispute` (персистентное оспаривание, переживает инкрементную сборку, стирается пересбором). Ручная пометка — `ManualCloseMark` (цена опциональна, количества нет). Решение о ручном режиме — ADR-0018.

## Goals / Non-Goals

**Goals:**

- Ручные сделки как полноправное сырьё журнала: создание/правка/удаление без синхронизации.
- Единый конвейер расчётов: ручные и биржевые сделки неразличимы для позиций, FIFO, метрик, сборки.
- Ручное создание синтетических связок и частичные пометки закрытия.

**Non-Goals:**

- Оффлайн-ввод новых символов и разбор строки символа (ADR-0018).
- Автодедупликация ручных и биржевых записей одного исполнения.
- Правка/удаление синхронизированных сделок.
- Редактирование ручной связки иначе, чем пересозданием.

## Decisions

### D1. Ручная сделка — отдельное сырьё `ManualTrade`, а не расширение `RawExecution`

Ручная сделка хранится собственной таблицей сырья `ManualTrades` (ExecutedAt, Symbol, Side, Quantity, Price, FeeUsdt, ConstructionId nullable, CreatedAt/UpdatedAt) и материализуется в общий журнал наравне с `RawExecution`. Alternatives: расширить `RawExecutions` nullable-полями — отклонено: у биржевых записей execId и биржевые поля обязательны, смешение обязательностей ломает идемпотентность синхронизации; отдельная таблица сохраняет «переразбираемость» сырья без обращения к API и переживает пересбор по построению (пересбор стирает конструкции, не сырьё).

### D2. Признак источника живёт в сырье и показывается проекцией

Материализация помечает каждую сделку источником «биржа»/«ручной ввод» в read-модели карточки и «Входящих»; у ручных сделок execId отсутствует. Списки записей различаются бейджем источника.

### D3. Разрешение символа переиспользует публичный канал справочника

Сервис ручного ввода перед сохранением сверяет символ с `InstrumentCatalog`; отсутствующий символ запрашивается через `IBybitInstrumentSource` и сохраняется в `RawInstruments` тем же путём, что и `InstrumentReferenceSync` (без API-ключей). Отказ сети или биржи — отказ создания сделки с человекочитаемой причиной. Новая абстракция источника не вводится.

### D4. CRUD ручных сделок — отдельные endpoints рядом с «Входящими»

`POST /api/v1/manual-trades` (constructionId опционален: null → «Входящие»), `PUT /api/v1/manual-trades/{id}`, `DELETE /api/v1/manual-trades/{id}`. Валидация серверная: дата не в будущем, количество > 0, цена > 0, комиссия ≥ 0; попытка изменить несуществующую или биржевую запись — ошибка запроса. Привязка/перенос/возврат — существующими `bind`/`move`/`return-to-inbox` без изменений: инвариант единственной принадлежности уже обслуживает оба источника.

### D5. Ручная синтетическая связка — персистентная сущность рядом с оспариванием

`SyntheticCloseManualLinks` (ConstructionId, LinearTradeId, OptionTradeId, Quantity) создаётся валидацией: обе сделки одной конструкции, встречный опцион совпадает со страйком/экспирацией закрываемой ноги, количество не превышает ни одну из сделок; окно времени не проверяется. Действующие связки в логическом слое = распознанные − оспоренные + ручные; формула лока (`SyntheticCloseValuation`) не меняется. API: `POST /api/v1/constructions/{id}/synthetic-closes/manual-links`, `DELETE .../manual-links/{id}`. Инкрементная сборка сохраняет (ручные данные), полный пересбор стирает — связка принадлежит конструкции и умирает вместе с ней, симметрично оспариваниям.

### D6. Частичная пометка — nullable `Quantity` у `ManualCloseMark`

Незаданное количество означает весь остаток на `MarkedAt` (текущая семантика); заданное — клэмпится остатком. Производный слой `ExpiryMaterializer`/FIFO получает дополнительный вход без изменения формул: закрывающая запись просто получает количество.

### D7. Подсказка внутренней стоимости считается на клиенте из известных данных

Форма пометки показывает подсказку |расчётная цена − страйк| для опционной ноги, используя последний известный `predictedDeliveryPrice`/индекс из существующего канала котировок и страйк из справочника. Подсказка не блокирует ввод: пользователь волен задать свою цену; при недоступности данных подсказка скрыта.

### D8. Новые UI-элементы идут за макетом design.pen

design.pen — источник истины UI (ADR-0011): макеты формы ручной сделки, бейджа источника, формы ручной связки и дополнений формы пометки вносятся в design.pen через MCP Pen до frontend-реализации — цепочка «макет → перенос → сверка». Новые элементы собираются из существующих токенов и паттернов (бейдж источника — семантическая пара статуса, формы — действующие паттерны форм экранов), в макете отражаются заполненное и пустое состояния. Приёмка переноса — скриншот-сверка затронутых экранов («Входящие», детали конструкции) с обновлённым макетом.

## Risks / Trade-offs

- [Дубликат ручной и биржевой записи одного исполнения] → осознанно (ADR-0018): пользователь замечает по бейджу источника и удаляет копию.
- [Ручная сделка задним числом меняет FIFO уже закрытых позиций] → детерминированный пересчёт есть корректное поведение; метрики строятся из текущего сырья.
- [Сеть недоступна при вводе нового символа] → отказ с сообщением; символы, уже разрешённые справочником, вводятся без сети.
- [Смешение источников в одной таблице «Входящих»] → колонка execId у ручных пуста, бейдж источника различает записи; фильтры не меняются.

## Migration Plan

EF Core миграция (SQLite): новые таблицы `ManualTrades`, `SyntheticCloseManualLinks`, колонка `Quantity` у `ManualCloseMarks` — все изменения аддитивны, downgrade удаляет их. Отдельная политика бэкапа не требуется поверх существующей (`ops/db-backup`); перед применением действует стандартный бэкап-перед-миграцией, если настроен.
