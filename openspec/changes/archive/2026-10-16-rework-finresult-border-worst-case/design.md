# Design

## Context

Индикатор финрезультата (`frontend/src/components/finresult/fin-result-indicator.tsx`, геометрия `frontend/src/lib/finresult/geometry.ts`) строит границу как `realized − realRisk` на фронте, а подпись границы собирает из величины `realRisk` («риск есть · 150 USDT · 50%»). Реальный риск считает `RealRiskCalculator`: суммарный минимум платежа групп остатков `worst` клэмпится в `Math.Max(0, −worst)` (`RealRiskCalculator.cs:212`) и публикуется парой `realRiskUsdt` + `realRiskStatus` через `RealRiskContract` в контрактах списка (`ConstructionListRows`, `ConstructionsEndpoints`), превью и карточки (`ConstructionCardEndpoints`). Мотивация смены семантики — в proposal и ADR-0015.

## Goals / Non-Goals

**Goals:**

- Знаковая метрика `worstCaseUsdt` = реализованный результат + неклэмпированный суммарный минимум платежа групп остатков, с тем же статусом, что реальный риск, во всех контрактах, где есть `realRiskUsdt`.
- Граница индикатора ставится и подписывается значением худшего исхода; тон и база процента — по знаку значения; процент честный, включая > 100%.
- Зафиксировать тестами истинное (неприжатое) положение маркера.

**Non-Goals:**

- Не меняем `realRiskUsdt` (остаётся ≥ 0), метрик-стрип, таблицу списка и компактный индикатор.
- Не добавляем комиссии ликвидации в маркер и не вводим клэмп маркера (ADR-0015).
- Не пересчитываем индикатор логическим слоем синтетики (ADR-0014).

## Decisions

### D1. Контракт: аддитивное поле рядом с парой риска

`worstCaseUsdt` (decimal?, со знаком) добавляется во все контракты, где уже публикуется пара `realRiskUsdt` + `realRiskStatus`: строка списка, превью, метрики карточки. Правило то же, что у риска: число только при `finite`, при `unbounded`/`unavailable` — null со статусом. `RealRiskContract` расширяется сериализацией тройки.
_Альтернатива:_ знаковый `realRiskUsdt` — отвергнуто, ломает метрики риска в таблицах/стрипе (ADR-0015, Considered Options).

### D2. Расчёт: неклэмпированный минимум платежа в результате калькулятора

`RealRiskResult` расширяется значением худшего платежа остатков (то, что сегодня внутренняя переменная `worst` до `Math.Max(0, −worst)`). `ConstructionMetricsCalculator` собирает `WorstCaseUsdt = realized + worstPayoff`; при отсутствии остатков worstPayoff = 0 и худший исход равен реализованному. `RealRiskUsdt` продолжает клэмпиться нулём.
_Альтернатива:_ считать worstCase отдельным калькулятором — отвергнуто, дублирование группировки и консервативного суммирования групп.

### D3. Геометрия фронта: граница из worstCase, подпись — значение

`FinResultInput` получает `worstCase` (заменяет вычисление `realized − realRisk` для позиции границы; `realRisk` остаётся для титула «риска нет» и состояний). Подпись: титул «худший исход» (при `realRisk = 0` — «риска нет»), значение со знаком и процент с округлением до целого; база процента — `plannedRisk` при отрицательном значении, `plannedProfit` при неотрицательном; база не задана/нулевая или значение нулевое — без процента. Тон подписи границы — по знаку худшего исхода (сейчас — по знаку итога). Позиция маркера не прижимается к границе.
_Альтернатива:_ считать процент на бэке — отвергнуто, процент — представление индикатора, а не метрика.

### D4. Компактный вид не меняется

Бейджи «∞»/«?» и полоса компакта работают от `realRiskStatus`, числовых подписей нет — контрактное поле `worstCaseUsdt` игнорируется компактом.

## Risks / Trade-offs

- [Фронт до обновления не знает `worstCaseUsdt`] → поле аддитивное, старый фронт его игнорирует; обратной совместимости ничего не ломает.
- [Граница правее realized непривычна для чтения] → это осознанное решение (ADR-0015): гарантированная прибыль остатков — часть худшего исхода; сценарий `scenario-finresult-guaranteed-profit-border` фиксирует поведение.
- [Два поля риска/исхода могут путаться в API] → имена разведены (`realRiskUsdt` — потери ≥ 0, `worstCaseUsdt` — знаковый исход), термины зафиксированы в GLOSSARY.md.

## Migration Plan

Бэкенд (поле + расчёт) → контракты/тесты → фронт (вход геометрии, подпись, тон, тесты). Откат не требует миграций: аналитика вычисляется при чтении и не хранится (`requirement-analytics-computed-on-read`).
