# Proposal

## Why

Консультация жёстко привязана к одной конструкции и двухуровневой модели «консультация → диалоги один вопрос — один диалог», а концепция нового frontend (карта [#50](https://github.com/menshov-anatoliy/transaction-journal/issues/50)) требует чат агента без обязательной конструкции: с параметрами (ИИ-модель, опциональная конструкция, источники данных), жизненным циклом «активен → завершён» и историей всех чатов. Доменные решения приняты в [#53](https://github.com/menshov-anatoliy/transaction-journal/issues/53): единая сущность «Чат агента» заменяет консультацию; архитектура [ADR-0009](../../../docs/adr/0009-consultation-chat-architecture.md) сохраняется.

## What Changes

- Сущность «Чат агента» ([CONTEXT.md](../../../CONTEXT.md)): плоская полная история обмена, создаётся первым сообщением; термины «Консультация», «Диалог консультации» и «Сообщение диалога» уходят из глоссария.
- Привязка к конструкции опциональна и фиксируется при создании; перепривязки нет — сменить контекст значит начать новый чат.
- Жизненный цикл: «активен» → «завершён» ручной меткой владельца (скрывается в список завершённых), продолжение возвращает в активные; удаление — явное, целиком, без корзины.
- Источники данных — закрытый справочник из трёх категорий (журнал, корпус правил, рынок Bybit); набор — параметр чата, по умолчанию все три; всё строго read-only.
- ИИ-модель — параметр чата (дефолт GLM-5.3), сменяема владельцем на лету: новые сообщения уходят выбранной модели, история не переписывается.
- Снимок контекста без привязки — портфельный уровень журнала; с привязкой — как в консультации; пост-мортем закрытой конструкции сохраняется.
- След источников в ответе ИИ-помощника обобщает рыночный след: использованные инструменты, ссылки на карточки правил и данные журнала с as-of.
- Единое хранилище чатов вместо per-construction баз; пересбор стирает только чаты привязанных конструкций, непривязанные переживают; существующая история консультаций не мигрируется (чистый лист).
- Проект окружения переименуется `TransactionJournal.Consultations` → `TransactionJournal.Chats`; инструкции `consultation-prompt.md` → `agent-prompt.md`.

## Capabilities

### New Capabilities

- `chats/context`: снимок контекста чата и инструкции ИИ-помощника — детерминированная сборка с as-of (с конструкцией или портфельный уровень), исключение живых подсказок движка, редактируемый `agent-prompt.md`, ответы-сценарии «если/то» с цитированием корпуса, пост-мортем закрытой конструкции.
- `chats/history`: сущность и персистентность — плоский чат с параметрами, неизменяемая опциональная привязка, ручные завершение и удаление, сообщение со следом источников, запись окружения в едином SQLite-хранилище, стирание пересбором только привязанных, отсутствие компакции.
- `chats/sources`: источники данных и модель — закрытый справочник из трёх категорий как параметр чата, read-only реестр инструментов, один вызов = один биржевой запрос с потолком итераций, деградация рынка в кэш as-of, модель как сменяемый параметр чата.

### Removed Capabilities

- `consultations/context`, `consultations/history`, `consultations/tools`: домен переехал от «консультации в контексте конструкции» к «чату агента» с опциональной привязкой — все требования замещены возможностями `chats/*` с сохранением преемственности (миграция указана в каждой REMOVED-записи).

## Impact

- `src/TransactionJournal.Consultations` → `TransactionJournal.Chats` (переименование): порты `IConsultationContextReader`/`IConsultationStore` → `IChatContextReader`/`IChatStore`; агентный цикл ME.AI и read-only инструменты сохраняются.
- `TransactionJournal.Infrastructure`: единый адаптер SQLite-хранилища чатов (схема «чат + сообщения» с параметрами и статусом) вместо per-construction баз; адаптер контекста получает портфельную ветку.
- Composition root: параметры чата (модель, источники), дефолт GLM-5.3; конфигурация провайдера `config/llm-provider` без изменений.
- Без миграции: старые базы консультаций удаляются вместе с Blazor-панелью после паритета (решение [#53](https://github.com/menshov-anatoliy/transaction-journal/issues/53)).
- API нового SPA и UI чата — отдельные changes после фиксации API-контракта (карта [#50](https://github.com/menshov-anatoliy/transaction-journal/issues/50), координация с [#19](https://github.com/menshov-anatoliy/transaction-journal/issues/19)).
- Приёмка: детерминированные контракт-тесты (снимок, инструменты, хранение, жизненный цикл, пересбор) + живая приёмка владельцем.
