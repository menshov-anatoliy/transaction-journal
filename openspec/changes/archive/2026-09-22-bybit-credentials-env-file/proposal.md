# Proposal

## Why

Приложение читает ключ и секрет Bybit из переменных окружения процесса (`EnvironmentBybitCredentialsProvider`), но задавать их на машине разработчика неудобно: нужно настраивать пользовательские переменные Windows ради одного локального инструмента. Стандартная практика — файл `.env` в корне репозитория, который разработчик создаёт один раз и который не попадает в git (`.gitignore` уже игнорирует `.env`). Сейчас механизма загрузки `.env` в приложении нет.

## What Changes

- При запуске приложение загружает переменные из файла `.env` в переменные процесса (пакет `DotNetEnv` из NuGet — решение владельца).
- Системные переменные окружения имеют приоритет над значениями из `.env`: значение из файла применяется только если переменная ещё не задана (решение владельца).
- Файл `.env` ищется от текущего каталога вверх по дереву — работает и при `dotnet run` из каталога проекта, и при запуске из корня репозитория.
- Отсутствие `.env` — штатный путь, а не ошибка: без файла приложение продолжает работать на системных переменных (текущее поведение не меняется).
- В репозиторий добавляется шаблон `.env.example` с именами `BYBIT_API_KEY` и `BYBIT_API_SECRET` и заглушками значений (решение владельца); `.env` остаётся игнорируемым `.gitignore`.
- Поставщик `EnvironmentBybitCredentialsProvider` не меняется: значения из `.env` попадают в переменные процесса до его первого использования, контракт сохраняется.

Замечание о расхождении с [#4](https://github.com/menshov-anatoliy/transaction-journal/issues/4): тикет закрыт решением «пользовательские переменные окружения Windows с именами `Bybit__ApiKey`/`Bybit__ApiSecret`», но текущая dev-реализация читает `BYBIT_API_KEY`/`BYBIT_API_SECRET`. Этот change следует фактическим именам кода и запросу владельца (`BYBIT_API_KEY`/`BYBIT_API_SECRET`); загрузка из `.env` аддитивна и не отменяет работу системных переменных с любыми именами, которые код прочитает в будущем.

## Capabilities

### New Capabilities

- `config/env-file`: локальная конфигурация приложения через файл `.env` — загрузка значений в переменные процесса при запуске, приоритет системных переменных, шаблон `.env.example` в репозитории.

## Impact

- `src/TransactionJournal/Program.cs`: ранний вызов загрузки `.env` до регистрации сервисов — покрывает и будущий режим `--mcp` того же exe (change `add-mcp-server`), ветвление режимов произойдёт после загрузки.
- Новый класс-обёртка загрузки `.env` в `src/TransactionJournal/` с модульными тестами в `tests/TransactionJournal.Tests/`: проверка загрузки значений, приоритета системных переменных и отсутствия файла.
- Новая зависимость: NuGet-пакет `DotNetEnv`.
- Корень репозитория: новый файл `.env.example` (коммитится), `.env` уже покрыт паттерном `.env` в `.gitignore`.
- Секреты не попадают в репозиторий и не логируются; шаблон содержит только имена переменных и заглушки.
