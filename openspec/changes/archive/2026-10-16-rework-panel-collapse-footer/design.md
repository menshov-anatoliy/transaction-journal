# Design

## Context

Каркас SPA (D1–D3 из `rework-spa-shell-and-screens`) сегодня рендерит `PanelIconColumn` (w-9, у внутреннего края) в обоих состояниях обеих панелей: `frontend/src/components/layout/AppLayout.tsx`, `PanelIconColumn.tsx`, геометрия в `layout-geometry.ts` (`COLLAPSED_LEFT_WIDTH_REM = 6.5`). design.pen — источник визуальных решений (ADR-0011): рамка «Каркас» (g0z20) изображает «Иконочную колонку» (44 px, padding [14,4]) у внутреннего края обеих панелей; «Список разделов» — padding [16,8,16,12], «Контекст» — [14,12]; свёрнутое состояние фиксирует «Схема состояний панелей» (Yh0Wo). Контент правой панели во frontend прижат к границе (обёртка AppLayout не даёт отступов), страницы контекст не регистрируют — `iconActions` на практике пуст.

Решения сессии планирования (grill): развёрнутая панель = контент + футер; свёрнутая = рейка миниатюр 44 px над тем же футером; боковые отступы развёрнутого состояния 12 px, футера свёрнутого — 4 px; нативные `title`; бейдж «Входящих» в рейке скрыт; диапазоны ширин не меняются.

## Goals / Non-Goals

**Goals:**

- Единая структура обеих панелей: футер с кнопкой управления в обоих состояниях, рейка миниатюр над ним в свёрнутом.
- design.pen остаётся источником истины: сначала правки каркаса и схемы состояний, затем frontend.
- Единые боковые отступы контента развёрнутых панелей (12 px) с вертикалями из дизайна (16 px / 14 px); футер в узкой панели сохраняет кнопку внутри за счёт отступа 4 px.

**Non-Goals:**

- Мобильная механика (drawer-шторка) — не меняется.
- Персистентность геометрии, поведение «без контекста панель скрыта», API `useContextPanel` — не меняются.
- Диапазоны ширин панелей (4.25–20 / 20–40 rem) — не меняются.
- Тултип-библиотеки, подписи у кнопки сворачивания — только нативный `title` и `aria-label`.

## Decisions

- **D1 — Один футер вместо иконочной колонки (оба состояния).** Каждая панель: `flex-col` = контент (`flex-1 overflow-y-auto`) + футер `h-11` (44 px) с `border-t border-divider`. В футере одна ghost icon-кнопка: сворачивания в развёрнутом состоянии либо разворачивания в свёрнутом, у внутреннего края (`justify-end` у левой, `justify-start` у правой). Боковые отступы: `px-3` (12 px) в развёрнутой панели, `px-1` (4 px) в свёрнутой шириной 44 px, чтобы кнопка 30 px помещалась. Альтернатива — перенос действий контекста в футер — отклонена: футер держит только управление панелью, действия остаются прерогативой контента/рейки.
- **D2 — Рейка миниатюр (свёрнутое состояние).** Над футером — узкая вертикальная колонка 44 px (`w-11`, `flex-1`, прокрутка при переполнении): у левой панели существующие NavItem-иконки меню (клик = навигация), у правой — `iconActions` регистрации. В рейке нет кнопки разворачивания; она всегда находится в футере под рейкой, линия футера сохраняется. `COLLAPSED_LEFT_WIDTH_REM` 6.5 → 2.75. Альтернатива — сохранить отдельную колонку рядом с рейкой меню — отклонена: дублирует управление и съедает ширину.
- **D3 — Компонентная замена.** `PanelIconColumn` заменяется двумя примитивами каркаса: общий `PanelFooter` (кнопка сворачивания/разворачивания и отступ в зависимости от состояния, сторона задаёт выравнивание) и `PanelMiniatureRail` (только миниатюры). Навигационная рейка левой панели использует существующий `NavItem` с `justify-center`, чтобы сохранить активное состояние и примитив дизайн-системы.
- **D4 — Отступы контента.** Обёртка контента правой панели в AppLayout получает `px-3 pt-3.5 pb-3` (12 px бока, 14 px верх по «Контексту» дизайна); nav левой панели — `px-3 py-4` сохраняется (12/16 по «Списку разделов»). Прежний правый отступ 8 px к колонке исчезает вместе с колонкой: внутренний край тоже 12 px.
- **D5 — Доступность и подсказки.** `aria-label` у кнопок сворачивания/разворачивания сохраняется; нативный `title` добавляется на миниатюры рейки (название раздела) и на кнопки в футере. Бейдж «Входящих» в свёрнутой рейке скрыт — условие `collapsedDesktop == false` сохраняется.
- **D6 — design.pen и приёмка.** В рамке «Каркас» узлы «Иконочная колонка» заменяются футером (линия + кнопка у внутреннего края); «Список разделов» получает [16,12] вместо [16,8,16,12]; «Схема состояний панелей» перерисовывается: развёрнута = контент + футер, свёрнута = рейка 44 px над тем же футером с кнопкой внутри. Экран повторно экспортируется в `design.exports\rework-panel-collapse-footer\Каркас.png` для скриншот-сверки (`requirement-screenshot-acceptance`).

## Risks / Trade-offs

- [Узкая рейка 44 px уменьшает клик-зону свёрнутого меню] → миниатюры остаются полноразмерными NavItem-кнопками, активное состояние сохраняется; ширина выбрана по дизайну иконочной колонки.
- [Высокая рейка с множеством миниатюр может вытеснить футер] → рейка прокручивается в оставшейся высоте, футер не сжимается и остаётся внизу панели.
- [localStorage хранит свёрнутость от прежней версии] → геометрия нормализуется как раньше (`normalizeGeometry`), смена константы ширины не требует миграции: свёрнутость/ширина независимы.
- [Сценарная замена в спеках — BREAKING UI-контракта] → старые ссылки `scenario-frame-collapse-icon-in-panel-column`/`scenario-design-collapse-icon-in-column` в коде и тестах заменяются на новые ID в этой же правке; REMOVED-блоки дельт фиксируют причину и миграцию.

## Migration Plan

1. design.pen: дополнить каркас и схему состояний футером свёрнутой панели + повторно экспортировать PNG.
2. frontend: использовать общий футер в обоих состояниях, оставить в рейке только миниатюры, сохранить константу ширины, отступы и title.
3. Тесты: обновить `AppLayout.test.tsx`, `context-panel.test.tsx`, `layout-geometry.test.ts` для обоих состояний; прогнать точечно, затем витрину Related.
4. Скриншот-сверка с переэкспортированным «Каркасом».

Отката не требуется: изменение UI-структуры, данные и API не затронуты.
