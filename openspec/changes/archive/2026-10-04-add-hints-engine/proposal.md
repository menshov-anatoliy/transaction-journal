# Proposal

## Why

Корпус правил v1 уже в репозитории (`rules/`, 34 карточки, 11 машинных триггеров — карта [#27](https://github.com/menshov-anatoliy/transaction-journal/issues/27)), архитектура агента утверждена ([ADR-0007](../../../docs/adr/0007-hints-agent-architecture.md)), целевая структура — [ADR-0008](../../../docs/adr/0008-ddd-solution-structure.md). Не хватает самого агента: детерминированного движка, который на каждом проходе читает журнал, рыночные марки и снимок корпуса, порождает подсказки с дедупликацией, хранит их историей и показывает в UI ([#30](https://github.com/menshov-anatoliy/transaction-journal/issues/30), [#31](https://github.com/menshov-anatoliy/transaction-journal/issues/31)). Выполняется после `restructure-ddd-solution`.

## What Changes

- Новый проект `src/TransactionJournal.Hints` — окружение агента: загрузка корпуса, движок триггеров, жизненный цикл подсказок; зависит только от Domain ([ADR-0007](../../../docs/adr/0007-hints-agent-architecture.md)).
- Снимок корпуса за проход: каталог `rules/` (путь настраивается) читается целиком в начале каждого прохода; валидность корпуса — предусловие прохода: битая карточка или пустой/отсутствующий каталог ломают проход одной агрегированной ошибкой до любых чтений; хост приложения продолжает работать.
- Неизвестный движку ключ `trigger.implementation` и карточки без реализации — не подсказки, а статический чек-лист сводки и лог «непокрытых кодом»; проход продолжается.
- 11 машинных триггеров корпуса v1 (`risk-limit-period` … `synthetic-close-itm`); отбор подсказок делает код, не LLM; недоступность рыночных данных пропускает проход — подсказки на неполных данных не выпускаются.
- Подсказка — самоописательная запись окружения (rule id, субъект, характер, чёткость, теги источников, текст, факты триггера, as-of, статус, firstSeenAt), хранится всей историей в SQLite; домен её не видит.
- Жизненный цикл `new → applied | dismissed | expired`: applied/dismissed ставит только человек в UI; expired гасит агент (условие ушло, субъект закрыт, правило выведено); терминальные статусы без reopen. Дедуп: ключ «правило × субъект», подавляет любая запись текущего окна; смена периода периодного правила — новое окно.
- UI: индикатор живых подсказок у конструкции, панель «Подсказки» в деталях конструкции и на обзорном экране, общий read-only журнал подсказок, кнопки «Применено»/«Отклонено», кнопка ручного запуска прохода.

## Capabilities

### New Capabilities

- `hints/rules-corpus`: чтение корпуса движком — снимок за проход, fail-fast валидность, поведение неизвестных и нулевых ключей триггера.
- `hints/engine-pass`: проход движка — входы (журнал, марки, снимок), машинные триггеры, формулировка по чёткости, фиксация фактов и as-of, пропуск при недоступности рынка.
- `hints/hint-lifecycle`: модель подсказки, субъекты, статусы и переходы, дедуп «правило × субъект × окно», пограничные сценарии закрытия субъекта и вывода правила.

### Modified Capabilities

- `ui/screens`: новые элементы экранов — индикатор подсказок в списке конструкций, панель «Подсказки», общий журнал подсказок, кнопки «Применено»/«Отклонено» и ручной запуск прохода.

## Impact

- Новый проект `src/TransactionJournal.Hints` (net9.0) в solution; ссылка только на `TransactionJournal.Domain`.
- `TransactionJournal.Infrastructure`: EF-хранение подсказок (таблицы истории подсказок в той же SQLite), миграции; адаптеры портов движка (чтение журнала, источник марок).
- `TransactionJournal` (Web): composition root — регистрация движка и его портов, новые компоненты UI (индикатор, панель, журнал подсказок, кнопка запуска).
- `rules/` — потребляется как есть; формат карточек не меняется.
- Тесты: фикстурные e2e всех 11 триггеров (сработало/не сработало), дедуп-окно, fail-fast корпуса, панели UI.
- Каналы доставки (Telegram, LLM-изложение, расписание) — следующий change `add-summary-channels`; здесь только ручной запуск кнопкой UI.
