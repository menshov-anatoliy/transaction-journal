# Design

## Context

Связки синтетического закрытия уже сведены в чтении карточки: `ConstructionDetailReadModel` строит строки `SyntheticCloseRow` и параллельно `quantityByLinearSymbol` — сумму количеств действующих связок (неоспоренные распознанные + ручные) по символу линейной сделки. Эта сумма питает распад остатка линейной ноги (`SyntheticResidual`/`OtherResidual`). Для закрываемой опционной ноги аналогичной величины в строках позиций нет — см. proposal.md (Why).

## Goals / Non-Goals

**Goals:**
- Пара величин «закрыто синтетикой» / «открыто» в строке опционной ноги, считанная из того же набора действующих связок, что питает лок и сводную величину.
- Отображение признака в таблице позиций карточки деталей по образцу распада остатка линейной ноги, с тултипом.

**Non-Goals:**
- Изменения распознавания, валидации ручных связок, споров и пересбора — величины читают уже определённый набор действующих связок.
- Изменение инструментальных метрик, статуса, предупреждений, списка конструкций, сводной величины «с учётом зафиксированного синтетикой».
- Пометки встречного (короткого) опциона и метрики на списке конструкций.

## Decisions

### D1 — Величины считаются в том же прогоне чтения связок

`ConstructionDetailReadModel` при построении `SyntheticCloseRow` уже проходит действующие связки (логический ключ «неоспоренная распознанная» + все применимые ручные). В том же прогоне копится вторая карта — сумма количеств по `ClosedLegSymbol`. Источник один: расхождение признака с локом и сводной величиной исключено конструктивно.

Альтернатива: агрегировать на фронте из уже присылаемого списка `syntheticCloses` — отклонено: истина размазывается по двум местам, зеркальный паттерн `syntheticResidual` теряется, read model не покрывает значение тестами.

### D2 — Пара полей строки позиции, `null`/`null` без связок

`ConstructionPositionRow` дополняется парой `SyntheticClosedQuantity` (X) и `SyntheticOpenQuantity` (Y = `Residual` − X); DTO карточки — `syntheticClosedQuantity`/`syntheticOpenQuantity`. Пока по символу ноги нет действующих связок — оба `null`: отсутствие, а не ноль, как у распада линейной ноги. Клэмп не вводится: Y может быть отрицательным (спецификация, сценарий «Величины не клэмпятся остатком»).

Альтернатива: одно поле и вычитание на фронте — отклонено: зеркальность паре `SyntheticResidual`/`OtherResidual` и «фронт ничего не вычисляет».

### D3 — Отображение: переиспользование паттерна распада остатка

В ячейке «Остаток» строки опционной ноги с `syntheticClosedQuantity != null` — тот же двухстрочный рендер, что у `linear-leg-residual-split`: главная строка `formatAmount(residual)`, вторичная 9.5px `text-text-muted` «закрыто синтетикой X · открыто Y», слот `data-slot="option-leg-synthetic-split"`, тултип с формулировкой из спеки UI. Признак показывается независимо от `isOpen` — значение приходит из read model по факту связок.

### D4 — Макет прежде кода (ADR-0011)

Правка вносится в `design.pen` через MCP Pen до frontend-влияния: новый мастер-паттерн признака на опционной ноге по образцу распада остатка линейной ноги (токены Body #2: 7/6 кегль, вторичная строка 9.5px), оба состояния — есть действующие связки / нет. Критерий переноса — токенно-компонентное соответствие; приёмка — скриншот-сверка живой страницы с макетом.

### D5 — Термин «Признак закрытия синтетикой»

В `GLOSSARY.md` фиксируется термин, отделяющий отображаемую аннотацию от «ручной пометки закрытия» (`ManualCloseMark`): признак — вычисляемое при чтении отображение действующих связок, не пользовательские данные, инструментальные метрики не меняет.

## Risks / Trade-offs

- [Y «открыто» уходит в минус при превышении связками остатка] → принято владельцем: журнал показывает факт; тултип поясняет состав, спека фиксирует отказ от клэмпа сценариями.
- [Вторая карта сумм в чтении связок — дублирование ключей] → карта строится в том же foreach, что `quantityByLinearSymbol`; тесты read model фиксируют оба среза на одном наборе связок.

## Migration Plan

Поля вычисляются при чтении, миграций нет. Выкатка аддитивна: старые клиенты новые поля игнорируют. Откат — реверс коммитов без данных.

## Open Questions

Нет — все решения зафиксированы сессией проектирования.
