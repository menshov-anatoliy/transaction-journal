# Design

## Context

Запуск синхронизации сегодня строится цепочкой: движки категорий (`ExecutionCategorySync`, `DeliveryCategorySync`) → пополнение справочника (`InstrumentReferenceSync`) → материализация (`JournalMaterializer`). Guard-контур отказа 110023 покрывает только окна перебора историй; запрос спецификации инструмента фильтром по символу не защищён, а материализатор бросает `InstrumentResolveException` при первом символе опциона без спецификации — и через read-модели это роняет все экраны, не только синк. Прогон на живом API (глубина 730 дней, `ExtraOptionBaseCoins=ETH`) зафиксировал оба факта: падение запуска на 110023 именно в пополнении справочника (сырые записи к этому моменту сохранены), и безмолвную дыру — delivery-эндпоинт отдаёт записи делистнутой доски, а область перебора исполнений по живому справочнику доски не строится. Мотивация — в proposal.md; требования — в delta-spec.

## Goals / Non-Goals

**Goals:**

- Запуск переживает отказ 110023 на запросе спецификации: факт фиксируется, запуск успешен.
- Материализация и все read-модели деградируют одинаково: записи без спецификации откладываются, символы видны пользователю.
- Дыра покрытия доски становится видимой: актив с записями вне пройденных областей сообщается с подсказкой лечения.

**Non-Goals:**

- Никаких новых параметров синхронизации, стратегий сбора и выбора областей в UI — отклонены до тестового прогона и не пересматриваются.
- Фолбэк-разбор символа опциона с доверием строке при отсутствии спецификации — противоречит `requirement-instrument-reference`; если предупреждение окажется недостаточным, выносится в отдельное изменение.
- Автоматическое конфигурирование `Sync:ExtraOptionBaseCoins` и автоматический сброс состояния категории — лечение остаётся ручным эксплуатационным шагом.

## Decisions

### d1: Перехват отказа в пополнении справочника — повторное использование существующего хелпера

`InstrumentReferenceSync.SyncAsync` перехватывает `BybitApiException` с `IsContractUnavailableError` вокруг запроса спецификации одного символа: символ попадает в перечень неразрешённых, остальные символы обрабатываются. Возвращаемое значение меняется со счётчика `int` на результат `InstrumentSyncResult { InsertedCount, UnresolvedSymbols }`. Распознавание — только по коду 110023 тем же хелпером, что и в движках категорий: одна точка правды о коде отказа.

Альтернатива — типизированное исключение наверх с перехватом в оркестраторе — отклонена: теряется контекст конкретного символа, а управление потоком исключением размывает контракт «локальная ошибка обрабатывается на месте».

### d2: Деградация — в слое материализатора, фильтром по причине отказа

`InstrumentResolver` различает причины отказа (`InstrumentResolveFailureReason`); деградирует только `UnknownSymbol` — символ отсутствует в справочнике. `TradeMaterializer.Materialize` пропускает такие записи исполнения, собирая символы в множество; `ExpiryMaterializer` — то же для delivery-записей (закрывающая запись без канонических атрибутов не строится). Прочие причины — MalformedOptionSymbol, Category/BaseCoin/OptionsType/DeliveryTimeMismatch — остаются исключениями: это повреждение данных или конфликт справочника, их замалчивание опасно.

`JournalMaterializationResult` пополняется перечнем `UnresolvedInstruments`, `JournalSyncService` проводит его в `JournalSyncResult`. Деградация именно в материализаторе, а не в оркестраторе: read-модели («Входящие», позиции, аналитика) материализуют сырьё независимо от синка и обязаны деградировать идентично — им достаётся то же поведение транзитивно.

### d3: Непокрытые активы — сравнение снимка журнала с пройденными областями запуска

`ExecutionCategorySyncResult` пополняется перечнем фактически пройденных базовых активов доски (области option, включая пропущенные как недоступные). Оркестратор после материализации извлекает базовые активы из символов option-записей полного снимка сырья (префикс до первого дефиса, нормализация как в `OptionBaseCoinSource`) и вычитает пройденные области: разность — непокрытые активы. Снимок, а не только новые записи запуска: дыра существует и когда записи пришли раньше (кейс реального журнала — delivery-записи ETH при ни разу не пройденной области ETH). Расчёт advisory: ложное срабатывание худшего случая — лишняя строка предупреждения.

### d4: Повторный запуск повторяет запрос спецификации

Пропущенная спецификация не запоминается как «постоянно недоступная»: перечень неразрешённых — факт запуска, не состояние. Следующий запуск снова пробует запросить спецификации неизвестных символов (их по-прежнему нет в справочнике) — недоступность может быть снята биржей, симметрично сценарию пропущенных областей.

### d5: Видимость — по прецеденту пропущенных областей

Оба перечня (неразрешённые символы, непокрытые активы) показываются на странице синхронизации заметками рядом с результатом запуска — тем же паттерном, что уже принят для пропущенных областей. Для непокрытых активов заметка содержит подсказку лечения: `Sync:ExtraOptionBaseCoins` и сброс состояния категории.

## Risks / Trade-offs

- [Пропуск спецификации скрывает данные] → перечень неразрешённых символов виден на странице каждого запуска, записи сохранены в сыром виде, повторный запуск переспрашивает спецификацию.
- [Записи без спецификации не попадают во «Входящие» — остатки и результат неполны] → предупреждение называет символы явно; для перманентно делистнутых досок это осознанный предел — доверие строке символа отвергнуто доменным правилом.
- [Деградация UnknownSymbol маскирует регрессии справочника] → счётчик новых инструментов запуска сохраняется, расхождения остаются жёсткими ошибками сверки.
- [Разбор префикса символа для покрытия доски неточен на экзотических символах] → использование advisory: худший случай — лишняя строка предупреждения, не потеря данных.

## Migration Plan

Выкатка безопасна без миграций: схема БД и конфигурация не меняются. Восстановление реального журнала после выката — эксплуатационные шаги без кода: добавить `Sync:ExtraOptionBaseCoins=ETH`, сбросить состояние категории option штатной командой сброса, запустить синхронизацию — область ETH пройдёт первичным backfill'ом, исполнения сохранятся в сырьё; спецификации делистнутых ETH-опционов останутся неразрешёнными и будут видны предупреждением (ожидаемо и постоянно). Откат — возврат версии кода: поведение «падения на 110023 в справочнике» восстанавливается, данные не требуют отката.

## Open Questions

- Достаточно ли предупреждения о перманентно неразрешимых символах, или потребуется отдельное изменение с фолбэк-разбором символа для делистнутых досок — решается по опыту эксплуатации, не влияет на данные и контракт этого изменения.
