# Design

## Context

Действующая реализация маркеров (change `add-finresult-result-history-markers`) считает значение срезом журнала: `ValueAt = RealizedPnL(срез) − входная стоимость открытых остатков + Σ локов + корректировки`, события строит по каждой фьючерсной сделке, а перечень маркеров дублирует область описания под индикатором. Модель вкладов (ADR-0022, глоссарий: «Вклад операции», «Расшифровка маркера») переформулирует значение в сумму денежных потоков событий и требует публикации перечня операций в контрактах. Существующие переиспользуемые механизмы: `ResultMarkerJournalMaterial.BuildOptionWindows` (окна по правилам v5), классификация закрывающих/открывающих сделок по живому остатку в `ConstructionAssembler.FlushWindow`, `PositionClosingEntry.Price` (эффективная цена: внутренняя стоимость delivery, ноль OTM, цена пользователя/котировка у ручной пометки), интервалы связок `Since/Until` с локом `LockedValueUsdt`.

## Goals / Non-Goals

**Goals:**
- Значение маркера = Σ вкладов операций; каждый вклад выводится в контракт как строка расшифровки (вид, дата, сумма) — результат сверяется сложением.
- Бейдж метки подписан суммой самого изменения результата (тон — по знаку изменения); накопленный итог — в заголовке расшифровки, позиция бейджа — на накопленном итоге.
- Расшифровка детализирует операции компактными строками конкретных сделок: окно — сделки с индивидуальными суммами, фьючерсный цикл — сделки без индивидуальных сумм, связки — период действия.
- Фьючерсы: вклад только при нулевом остатке позиции, round-trip по FIFO с комиссиями.
- Расшифровка в подсказке бейджа (полный вид) и последнего маркера (средний/компактный виды); область описания удаляется.
- Цепочка «макет → перенос → сверка» (ADR-0011): design.pen правится первым через MCP Pen.

**Non-Goals:**
- Порог проявления, нумерация, безусловные первая/последняя метки и вычисление на лету не меняются.
- Маркер текущего результата, заливка, золотая зона, состояния риска, нейтральная полоса — без изменений.
- Модель связок и правила сборки не меняются: потребляем существующие интервалы и локи.
- Сводная «С учётом зафиксированного синтетикой» в метриках карточки остаётся как есть.

## Decisions

### D1. Накопление вкладов вместо срезов сводной формулы
Вычислитель строит хронологический список операций с вкладами: окно → Σ сделок окна; связка → ±лок по границам интервала; фьючерсный цикл до нуля → финрезультат цикла; закрывающая запись с ценой → количество × цена; корректировка → сумма. Значение маркера = префиксная сумма вкладов. Отвергнуто: оставить срезы и декомпозировать их в расшифровку постфактум — вклады фьючерсов и локов не сводятся к срезу без дублирования логики, а срез не проверяется сложением строк.

### D2. Фьючерсный цикл: вклад в момент обнуления остатка
Фьючерсный поток инструмента прогоняется через FIFO; момент, где остаток становится нулём после ненулевого состояния, образует событие «Закрытие фьючерса» со вкладом = прирост реализованного PnL потока от предыдущего нуля (комиссии входят в FIFO как сегодня). Открывающие сделки и частичные закрытия событий не создают; разворот через ноль — то же обнуление. Отвергнуто: событие на каждую закрывающую сделку с частичным финрезультатом — нарушает правило «нулевой остаток» и дробит результат незакрытой позиции.

### D3. Виды операций и классификация окон
Фиксированный набор видов: Открытие, Закрытие, Ролл, Синтетическое закрытие, Снятие синтетики, Закрытие фьючерса, Корректировка PnL, Поставка. Окно классифицируется составом сделок по живому остатку (переиспользуется правило `IsClosingTrade` сборщика): без закрывающих — Открытие (усреднение не выделяется), с закрывающими без открывающих — Закрытие, с закрывающими и открывающими — Ролл. Delivery и ручная пометка — вид «Поставка»/«Закрытие» по `PositionClosingKind` с вкладом количество × эффективная цена; OTM-экспирация (цена 0) и записи без цены событий не создают. Отвергнуто: отдельный вид «Усреднение» — для истории результата неразличимо с открытием.

### D4. Контракты: operations[] с детализацией сделками рядом с маркерами
`ResultMarker` дополняется `Operations[]` (вид, дата, сумма вклада); перечень маркера N охватывает все события после события маркера N−1, включая подавленные порогом — инвариант «Σ перечня = изменение», «итог N−1 + Σ = итог N» проверяется тестами. Детализация по видам: окна открытий, закрытий и роллов — сделки окна (инструмент, сторона, количество × цена, сумма вклада сделки; Σ сделок = вклад операции); закрытие фьючерса — сделки цикла без индивидуальных сумм (вклад принадлежит round-trip целиком); поставка и ручное закрытие — инструмент и количество × эффективная цена; связки — период действия (`Since`–`Until`); корректировки — без детализации. `lastResultMarker` в списках/превью публикует тот же перечень последнего маркера с той же детализацией. Сервер формирует перечни и детализацию: UI не реконструирует вклады и не знает о suppressed-событиях вне перечня. Отвергнуто: публикация всех операций маркера от нуля — перечни длинных историй не «краткие»; отвергнуты индивидуальные суммы сделок фьючерсного цикла — FIFO round-trip не разлагается на сделки без произвольных допущений.

### D5. UI: бейдж изменения и подсказка-расшифровка вместо области описания
`MarkerDescriptionArea` удаляется; бейдж маркера подписывается суммой самого изменения (тон — по знаку изменения) и остаётся стоять на накопленном итоге; накопленный итог метки выводится в заголовке расшифровки. Бейдж оборачивается в существующий паттерн подсказки (`MetricHint`): заголовок с накопленным итогом, подстрока изменения, построчно «вид · дата · сумма» и под строкой операции — компактные строки конкретных сделок, без группировки, со скроллом при переполнении. Средний/компактный виды: последний маркер без номера/суммы над полосой, с той же подсказкой. Попап «Как читать индикатор» и `METRIC_TOOLTIPS` переписываются по ADR-0022. Отвергнуто: сохранить область описания с расшифровками — дублирует подсказку и занимает карточку; отвергнуто оставление накопленного итога на бейдже — подпись изменением отвечает на вопрос «что дала эта метка», а итог восстанавливается из расшифровки и позиции бейджа.

### D6. Сначала design.pen, потом код (ADR-0011)
Первая задача UI-блока — правка `design.pen` строго через MCP Pen: удалить область описания (оба состояния), изобразить подсказку-расшифровку бейджа (перечень операций), обновить текст попапа. Приёмка переноса — токенно-компонентное соответствие + скриншот-сверка живой карточки с макетом.

### D7. Последовательность с предыдущим change
`add-finresult-result-history-markers` архивируется как есть до применения этого change: дельты MODIFIED рассчитаны на пост-архивное состояние основных спек (заголовки и сценарии совпадают с заархивированными версиями). Внутри change порядок: вычислитель → контракты → макет → фронтенд → сверка.

## Risks / Trade-offs

- [Расхождение последнего маркера и сводной при открытой фьючерсной позиции] → намеренно: незакрытая позиция не зафиксированный результат; различие закреплено `scenario-futures-open-position-not-counted` и текстом попапа.
- [Ручная пометка без известной цены (null)] → события не создаёт; при появлении цены (котировка) история пересчитывается — вычисление на лету уже гарантирует согласованность.
- [Накопленный итог ушёл с подписи бейджа] → итог виден в заголовке расшифровки метки, позиция бейджа остаётся на итоге, история восстанавливается сложением изменений.
- [Длинные перечни и детализации расшифровки у роботных серий] → подавленные порогом операции сворачиваются в один следующий маркер, строки сделок компактны, перечень прокручивается; компактные виды показывают только последний.
- [Переименование сценариев (`scenario-futures-trade-marker` → `scenario-futures-closed-trade-marker` и т.п.)] → traceability-ссылки в тестах обновляются в тех же задачах, что меняют поведение; grep-аудит старых id включён в задачи.

## Migration Plan

Миграция данных не нужна: маркеры вычисляемые. Развёртывание обычное (монорепо, единый деплой): контракты и UI меняются в одном change. Откат — revert коммитов change. Предусловие: архив `add-finresult-result-history-markers`.
