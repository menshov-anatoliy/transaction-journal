# Proposal

## Why

Синхронизация теряет сделки по опционам: эндпоинт `execution/list` для `category=option` без явного `baseCoin` отдаёт только BTC-опционы (документированное поведение Bybit), поэтому сделки ETH/SOL и прочих не-BTC досок в журнал не попадают никогда. Дополнительно backfill останавливается на первом пустом окне (7 дней без сделок для исполнений, 30 дней для delivery), хотя биржа хранит историю порядка двух лет — любой перерыв в торговле обрезает всю более старую историю. Водяной знак при этом фиксируется, и инкрементальные запуски пропущенное не возвращают.

## What Changes

- Перебор базовых активов опционной доски: перед проходом категории `option` система определяет список базовых активов из публичного эндпоинта спецификаций инструментов и выполняет проходы окон исполнения по каждому активу (`baseCoin` в запросе `execution/list`); дедупликация по `execId` сохраняется.
- Конфигурируемый список дополнительных базовых активов: активы, чьи опционные доски делистнуты и отсутствуют в текущем справочнике биржи, но по которым есть торговая история, задаются в конфигурации приложения.
- Остановка backfill по полу глубины: проход назад продолжается до фиксированной границы глубины (по умолчанию два года — порядок глубины хранения истории Bybit), а не до первого пустого окна; правило применяется к исполнениям и delivery-записям. Граница `BackfillBoundaryMs` остаётся фиксируемым фактом «самая ранняя увиденная запись», но перестаёт ограничивать перебор.
- Ручной сброс состояния категории: команда на странице «Синхронизация» удаляет водяные знаки выбранной категории; следующий запуск выполняет полный backfill этой категории. Идемпотентность хранения (`execId`, `symbol + deliveryTime`) исключает дубли при перечитывании.
- Категория `linear` и delivery-записи фильтрацию по инструментам не меняют: `execution/list` для linear и `delivery-record` возвращают все символы категории без ограничений.

## Capabilities

### New Capabilities

_Нет._

### Modified Capabilities

- `sync/bybit-history`: изменяется требование `requirement-backfill-full-history` (перебор по базовым активам для option; остановка по глубине вместо пустого окна; граница — только факт, не ограничитель). Добавляются требования: полное покрытие инструментов категории option (перебор базовых активов) и ручной сброс состояния синхронизации категории с повторным backfill.

## Impact

- `src/TransactionJournal/Sync`: `ExecutionWindow`/`ExecutionWindowPass` (передача `baseCoin` в запрос), `ExecutionCategorySync` (итерация базовых активов, пол глубины), `DeliveryCategorySync` (пол глубины), новый компонент определения списка базовых активов, `JournalSyncService` (оркестрация).
- `src/TransactionJournal/Bybit`: `BybitExecutionListQuery` уже поддерживает `baseCoin` — изменений клиента не ожидается; `BybitInstrumentInfoQuery` используется для перечисления активов доски.
- `src/TransactionJournal/Data`: `IExecutionSyncStateStore`/`JournalSyncStore` — операция сброса состояния категории; схема `SyncState` не меняется.
- UI: `Components/Pages/Sync.razor` — команда сброса состояния категории с подтверждением.
- Конфигурация: максимальная глубина backfill и список дополнительных базовых активов опционов.
- Тесты: `tests/TransactionJournal.Tests/Sync` и UI-тесты страницы Sync.
