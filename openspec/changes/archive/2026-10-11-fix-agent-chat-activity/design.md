# Design

## Context

Архитектура чата агента (change `add-agent-chat`, ADR-0009/0010): `POST /api/v1/chats/{id}/messages/stream` отдаёт SSE (`start` / `token` / `done` / `error`, ровно один терминальный кадр), фронтенд (`use-agent-chat-runtime` поверх assistant-ui + TanStack Query) парсит кадры инкрементально и показывает баннер ошибки. Приёмка владельцем выявила: чат «не отвечает» (молчание без видимой причины), активности инструментов в протоколе нет, композер и объекты чата не сверены с design.pen, панель чатов карточки фиксирована. LLM-провайдер настраивается секцией `Llm` (`appsettings.Local.json`); при пустом ключе клиент подменяется `UnconfiguredChatClient`, чей отказ прилетает error-кадром.

## Goals / Non-Goals

**Goals:**

- Диагностировать и устранить молчание чата; любая ошибка генерации видна в UI с причиной и логируется на бэкенде.
- События активности инструментов в SSE и живые пилюли ToolStatus в UI.
- Переезд чатов карточки в контекстную панель каркаса; композер по практикам ввода; скриншот-сверка чата с design.pen.

**Non-Goals:**

- Изменение доменной модели чата (плоская история, привязка, жизненный цикл — capability `chats` без изменений).
- Настройка LLM-провайдера в UI (остаётся `appsettings.Local.json`, концепция §8).
- Новые инструменты или права (реестр read-only инструментов не меняется).

## Decisions

- **D1 — Диагностика.** Чек-лист причин: пустой `Llm:ApiKey` (отказ `UnconfiguredChatClient`), недоступный/неверный `BaseUrl` (для провайдеров ≠ z.ai обязателен), несуществующее имя модели, исключения генерации. Воспроизведение — прямым POST к stream-эндпоинту с чтением SSE; причина каждого отказа пишется в лог exe с chatId и типом. Критерий приёмки: при любой причине UI показывает баннер с текстом ошибки из error-кадра (текст бэкенд делает человекочитаемым: «API-ключ модели не настроен…», «провайдер недоступен…»).
- **D2 — События `tool`.** Между `start` и терминальным кадром стрим дополняется кадрами `event: tool` с payload `{ name, phase: "start" | "end", detail? }`; имя — из реестра инструментов (`read_rule_card`, `get_market_snapshot`, `get_option_board`). Терминальность не меняется: ровно один `done` или `error`; события `tool` на них не влияют. Обратная совместимость: клиент, не знающий `tool`, игнорирует неизвестные имена событий (SSE-спецификация) — контракт не ломается.
- **D3 — Активность в UI.** Runtime хранит текущий список активных инструментов из `tool`-кадров; тред рендерит пилюли ToolStatus (компонент существует) «источник — фаза» над потоком токенов; по `end` пилюля гаснет. Статичная надпись «источники — собираю данные…» удаляется.
- **D4 — Чаты в контекстной панели.** `ConstructionChatsPanel` монтируется в слот контекстной панели (`useContextPanel`) страницы карточки: вся высота контента, ширина/свёрнутость — геометрия каркаса; на карточке панель развёрнута по умолчанию (у карточки контекст есть всегда), состояние переживает перезагрузку. URL-параметры `?chats=*` упраздняются; выбор чата остаётся в URL (`?chat=`).
- **D5 — Композер.** Textarea с авторостом (min 1 строка, max ~8), Enter — отправка, Shift+Enter — перенос строки, кнопка отправки disabled при пустом тексте и во время генерации (в генерации на её месте Stop — отмена стрима), чипы привязки/модели/источников — тулбар под полем (по design.pen из change'а `revise-design-screens`).
- **D6 — Сверка дизайна.** Сообщения (Message/User), tool-статусы, след источников, пункты сессий — скриншот-сверка с design.pen; приёмка по `requirement-screenshot-acceptance`.

## Risks / Trade-offs

- Расширение протокола событием `tool` — обратно совместимое (неизвестные SSE-события игнорируются), но требует синхронной правки бэкенда и фронтенда в рамках одного change'а.
- Перевод чатов на геометрию каркаса убирает `?chats=open` из URL: раскладка перестаёт переноситься ссылкой — решение сессии Q2 (геометрия локальна).

## Migration Plan

_none_ — изменений схемы нет; хранилище чатов и DTO не меняются.
