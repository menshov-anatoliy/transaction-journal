# Proposal

## Why

Концепция каркаса **К1 «Контекстный топбар»** выбрана на стенде концепций design.pen («Стенд/Концепции каркаса», WufvO; легенда состава контекстного заголовка) и уже синхронизирована на мастер-каркас (g0z20) и все экраны. Frontend остаётся на предыдущей концепции (тонкий топбар 54 px только с брендом и итогом; панельные футеры) и расходится с источником истины (ADR-0011): контекст страницы не виден в каркасе, панели теряют полезную высоту под футеры, статус синхронизации не отображается.

## What Changes

- Топбар высотой 64 px делится на три сегмента, выровненные по колонкам каркаса: **над навигацией** — лого-глиф, бренд и кнопка сворачивания панели; **над центром** — крошка раздела, бейдж числа непривязанных «Входящих», заголовок страницы и её ключевые чипы/действия, итог журнала с разбивкой, статус синхронизации; **над контекстом** — кнопка сворачивания и чип открытого содержимого.
- Ширины сегментов навигации и контекста жёстко равны текущим ширинам соответствующих панелей (свёрнутая панель → сегмент 44 px); сегмент страницы заполняет центр.
- **Футеры панелей удаляются**: управление свёрнутостью/разворачиванием — кнопками в сегментах топбара; свёрнутая панель — вертикальная рейка миниатюр на всю высоту панели.
- Страницы регистрируют контент сегмента «страница» через Outlet-контекст (по аналогии с `useContextPanel`); без регистрации — крошка и заголовок раздела из конфигурации разделов.
- Чип сегмента контекста показывает короткое название из регистрации контекста (без клика); без контекста правая панель и сегмент контекста скрыты.
- Статус синхронизации «Обновлено HH:MM» — время последнего успешного запуска из журнала синхронизаций; пустой журнал или сбой загрузки — статус скрыт.
- Бейдж «Входящих» остаётся у пункта меню панели навигации и добавляется у крошки сегмента страницы.
- Поэтапный перенос всех форм design.pen в этом каркасе: Каркас → Конструкции → Карточка конструкции → Входящие → Подсказки → Агент · Чаты → Агент · Чат активный → Агент · Правила → Синхронизация → Mobile-экраны. Перед каждой формой — раунд-сверка состава её сегмента «страница»; после каждой формы — скриншот-сверка через MCP pen (ADR-0011), зелёные тесты, обновлённые traceability-метки.

## Capabilities

### New Capabilities

_Нет — изменения укладываются в существующие возможности._

### Modified Capabilities

- `ui/screens`: `requirement-app-frame-navigation` — каркас переходит на контекстный топбар из трёх сегментов; сценарий «кнопка в футере» заменяется сценарием «кнопка в сегменте топбара»; рейка миниатюр становится на всю высоту без футера; добавляются сценарии выравнивания сегментов по колонкам, регистрации шапки страницы, статуса синхронизации и чипа контекста; бейдж «Входящих» дублируется у крошки.
- `ui/design-system`: `requirement-design-frame-resizable-panels` — каркас design.pen изображает К1: сегментный топбар 64 px, кнопки управления в сегментах, свёрнутая панель — рейка на всю высоту без футера.

## Impact

- **frontend**: `components/layout/AppLayout.tsx`, `PanelFooter.tsx` (удаляется), `PanelMiniatureRail.tsx`, `layout-geometry.ts`, `context-panel.ts` (расширение регистрации чипом), новая регистрация шапки страницы; страницы-потребители; тесты `AppLayout.test.tsx`, `context-panel.test.tsx`, `layout-geometry.test.ts` и тесты страниц.
- **GLOSSARY.md**: термин «Сегмент топбара» (новый), ревизия «Рейка миниатюр» и «Контекстный заголовок»; удаление «Футер панели».
- **docs/adr/0016** — фиксация выбора К1.
- **design.pen**: уже обновлён (источник истины); в рамках change правится только по результатам раундов-сверок форм, если всплывут нестыковки.
- Не меняются: мобильная механика до стадии Mobile, персистентность геометрии панелей, диапазоны ширин, поведение «без контекста панель скрыта».
