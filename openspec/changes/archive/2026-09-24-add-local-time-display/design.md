# Design

## Решения

### Конвертация только на слое отображения

Мгновения (`DateTimeOffset` с offset +00:00) остаются единственной формой хранения и
передачи: SQLite, материализаторы, read-модели, MCP-режим не меняются. Локальная зона
появляется исключительно при форматировании строк для экранов. Это исключает расползание
конвертации по слоям и повторную конвертацию (двойной сдвиг) при прохождении данных
через несколько read-моделей.

### `ToLocalTime()` на сервере корректен для этого приложения

Приложение — локальный персональный инструмент одного пользователя (ADR-0003): exe с
Blazor Server запускается на машине трейдера, серверная локальная зона совпадает с зоной
пользователя. Отдельная передача клиентской зоны (JS-interop, cookie, заголовок) не
оправдана и усложняет MVP; при переносе на удалённый хост решение пересматривается.

### Общий хелпер вместо копий форматтеров

Правило локального отображения — единое для всех экранов, поэтому конвертация и константы
форматов живут в одном статическом хелпере (`TransactionJournal.Components.DisplayTime`),
а страницы вызывают его из своих тонких `FormatDate`/`FormatTime`/`FormatDay`.
`_Imports.razor` уже подключает пространство `TransactionJournal.Components`.

### Формат предупреждений сверки: `"u"` → `"yyyy-MM-dd HH:mm"`

Стандартный спецификатор `"u"` для `DateTimeOffset` всегда печатает UTC-эквивалент с
суффиксом `Z` — после конвертации в локальную зону он показал бы локальную стеночную
часть с ложной меткой `Z`. Замена на явный пользовательский формат убирает и суффикс.

### Round-trip форм правки

Поле времени закрывающей записи предзаполняется `FormatDate(entry.ClosedAt)`, поле даты
корректировки — `FormatDay(adjustment.Date)`; разбор ввода (`TryParseMarkTime`,
`TryParseAdjustmentDate`) трактует строку без offset как локальную. После перевода
отображения в локальную зону предзаполнение и разбор работают в одной зоне, и сохранение
без правки времени сохраняет мгновение — отдельного изменения разбора не требуется.

## Последствия

- Тесты, сверяющие рендер дат, вычисляют ожидаемую строку через ту же локальную
  конвертацию; проверка «UTC-строки нет, локальная есть» осмысленна при ненулевом
  смещении зоны машины, на которой идёт прогон.
- MCP-партнёры продолжают читать UTC — контракт программного доступа не меняется.
