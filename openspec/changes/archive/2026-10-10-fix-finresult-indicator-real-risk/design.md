# Design — fix-finresult-indicator-real-risk

Решения grill-сессии ([#75](https://github.com/menshov-anatoliy/transaction-journal/issues/75)). Термины — GLOSSARY.md («Плановый риск», «Реальный риск», «Граница реального риска», «Маркер итога», «Сверхприбыль»).

## D1. Метрика реального риска — чистый расчёт в Application

Расчёт живёт в `TransactionJournal.Application/Analytics` рядом с `ConstructionMetricsCalculator` и вызывается из него: позиции уже несут всё необходимое (`Symbol`, знаковый `Residual`, `AverageOpenPrice`). Марки не нужны — метрика не деградирует при сбое котировок.

Алгоритм по конструкции:

1. Открытые остатки (`Residual != 0`) группируются по `(BaseCoin, ExpiryDate)` из `OptionSymbolParser` (Domain). Неразобранный символ → величина `null` целиком.
2. В группе строится кусочно-линейный платеж `f(S) = Σ payoff ноги(S)` на `S ≥ 0`; payoff ноги = `±(внутренняя стоимость(S, страйк, тип) − средняя цена остатка)` со знаком остатка. Единицы — те же, что у `MarkValue` («цена × количество»), без нового множителя контракта.
3. Проверка неограниченности: если суммарная нетто-позиция по коллам группы отрицательна (наклон `f` на `+∞` меньше нуля) → `null`.
4. Минимум ищется в узлах ломаной: `S = 0` и страйки группы (включая `+∞`-хвост через проверку наклона).
5. Группы суммируются консервативно: `worst = Σ min групп`. Реальный риск = `−worst` (неотрицательная величина).
6. Нет открытых остатков → `0`.

`ConstructionMetrics` получает `RealRiskUsdt` (`decimal?`).

## D2. Правила null и заглушки

- `null` (неограниченный случай, неразобранный символ) — на фронте заглушка `plannedRisk`, затем `plannedProfit`, затем `0`: насечка «всегда присутствует» в режимах с зонами.
- `realized == null` → насечка скрыта: нет данных о позиции.
- Нейтральная полоса (оба плановых параметра не заданы) — без насечки и маркера, как сегодня.

## D3. API-контракты

`realRiskUsdt` добавляется позиционным полем в: `ConstructionListItem` (список), контракт превью, `ConstructionMetrics` (карточка) — и в соответствующие DTO endpoints (`ConstructionsEndpoints`, `ConstructionCardEndpoints`) + типы `frontend/src/lib/api/*`. Контракт OpenAPI обновляется автоматически из DTO.

## D4. Геометрия индикатора

Вход `FinResultInput` получает `realRisk: number | null`.

- `borderValue = realized − realRiskEff`, где `realRiskEff = realRisk ?? plannedRisk ?? plannedProfit ?? 0`. Спец-случай «свежая позиция → −plановойРиск» (#62) упраздняется: при `realized = 0` формула даёт `−realRiskEff` естественно.
- `borderAt` клипуется слева по `scale.min` (`clamp01`), в подписи — истинное число.
- Шкала: `scale.max = plannedProfit`, если `max(total, borderValue) > plannedProfit` — золотая надбавка до `max(total, borderValue)` без капа. Правило «половины превышения» и кап `baseWidth` удаляются. `superEnd`-подпись упраздняется.
- Маркер: позиция и тон без изменений (`total`, зелёный при `> 0`); подпись — итог (`formatFinAmount(total)`), свежая позиция — «≈ 0», сбой котировок — без числа.
- Подпись границы: заголовок «риск есть» при `realRiskEff > 0`, иначе «риска нет»; значение — `{realRiskEff} USDT · {pct}%` (`pct = realRiskEff / plannedRisk`, только при заданном плановом риске).
- `fillUnreal` (бледная заливка между границей и итогом) сохраняется как визуальный мост, semantic изменений нет.

## D5. Разнос и прижатие меток

Калькулятор геометрии назначает каждой метке размещение: `{side: above | below, level: 0 | 1 | …, align: center | start | end}`.

- Оценка ширины: `символы × ширина символа пресета` (табличные цифры, метки короткие) — детерминированно и тестируемо без DOM.
- Приоритет размещения: сначала предпочитаемая сторона (деления шкалы — над полосой, граница и маркер — под), при коллизии — противоположная сторона, затем следующий вертикальный уровень на предпочитаемой стороне.
- Порядок обработки: маркер итога → граница → профит → ноль → риск (главное число выигрывает место).
- Прижатие: если центр метки с половиной ширины выходит за `0` или `1` — `align: start/end` с прижатием к краю изнутри; габариты индикатора не растут.
- Компактный вид меток не имеет — затрагиваются только полный и средний.

## D6. Контраст зон

Значения токенов `riskZone` / `profitZone` / `superZone` усиливаются в design.pen через MCP pen (ADR 0011: design.pen — единственный источник), затем переносятся в `frontend/src/index.css`. Числовые подписи границ сохраняются; линии-разделители зон не вводятся. Приёмка — скриншот-сверка трёх видов индикатора.
