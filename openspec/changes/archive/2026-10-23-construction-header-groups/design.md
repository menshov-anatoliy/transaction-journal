# Design

## Context

Сводка метрик карточки конструкции сегодня — плоский flex-wrap список в `metric-strip.tsx` (12 показателей) плюс мета-строка плановых значений в `construction-card-page.tsx` (`headerMeta`). Индикатор финрезультата (`finresult/geometry.ts`) уже вычисляет и публикует плановые величины, реальный риск со статусом и `worstCaseUsdt`; саммари времени жизни (`analytics/option-lifetime`) даёт остаток до экспирации, распад и временную стоимость. Мотивация и состав групп — в `proposal.md`; поведенческий контракт — в дельтах `ui/screens` и `analytics/option-lifetime`. Форма принята владельцем на стенде design.pen «Заголовок конструкции · графические варианты», ячейка Г1 (id `Bvd1Z`): тонированные подложки `$surface2` (radius 8, padding [10,14]), капс-метки 9.5px/ls 0.6/w500/`$textMuted`, модульная сетка «блок 350 + ПОЗИЦИЯ до края / три равных блока», линия `h-px $divider` перед зоной синтетики, техстрока «котировки на» справа под группами.

## Goals / Non-Goals

Goals:
- Мастер design.pen «Карточка конструкции» (`QbFRE`) отражает заголовок конструкции по принятой ячейке Г1; мета-строка шапки упразднена.
- Frontend переносит форму по макету с токенно-компонентным соответствием; подсказки метрик сохраняются.
- Контракт карточки расширяется суммарной внутренней стоимостью открытых опционных остатков.

Non-Goals:
- Адаптив заголовка (средний индикатор, перестройка сетки на узких экранах) — отдельное изменение.
- Краткая карточка контекстной панели и строка списка конструкций — отдельные будущие задачи (принцип группировки переиспользуемо сформулирован, но не реализуется).
- Изменение мастера индикатора `onchD` и геометрии `finresult/geometry.ts`.

## Decisions

### D1. Цепочка «макет → перенос → сверка»

Сначала правка мастера `design.pen` через MCP Pen: в экране `QbFRE` заменить блок «Сводка и индикатор» (`e96333` = сводка `h69OG` + индикатор `v47Xn`) на заголовок конструкции по ячейке Г1 стенда `Bvd1Z`; удалить Meta (`tKUF6`) из шапки `Uw04r`. Мастера-примитивы не ломать: группы собираются из существующего примитива «Метрика» (`jtDmV`) и токенов. Затем frontend по обновлённому мастеру; приёмка UI-задачи — скриншот-сверка живой страницы (localhost) с мастером через MCP Pen. Альтернатива «править сразу frontend» отклонена: ADR-0011 объявляет design.pen источником визуальных решений.

### D2. Структура групп во frontend

`metric-strip.tsx` получает локальный компонент `MetricGroup` (капс + строка метрик, фон `bg-surface2`, radius 8) и статичную конфигурацию групп: ПЛАН, ПОЗИЦИЯ, РИСК, ВРЕМЯ, СТОИМОСТЬ. Ряды — CSS grid: ряд 1 `grid-cols-[minmax(350px,auto)_1fr]`, ряд 2 `grid-cols-3`, gap 12px; ряды всегда растянуты на полную ширину карточки (модульная сетка макета). Существующие `Metric`/`MetricHint` переиспользуются без изменений — триггером подсказки остаётся значение, капсы групп триггерами не становятся. Альтернатива «один flex-wrap со словарём групп» отклонена: она теряет модульное выравнивание блоков, принятое владельцем.

### D3. Данные новых показателей

- Плановый риск/профит, реальный риск со статусом, `worstCaseUsdt`, `allocatedCapitalUsdt` — уже в контракте карточки; переиспользуются без изменений API.
- Суммарная внутренняя стоимость — новое вычисляемое поле read-модели: сумма `intrinsicValueUsdt` открытых опционных ног; публикуется в саммари времени жизни как `totalIntrinsicValueUsdt` (nullable, пара к `totalTimeValueUsdt`), деградация прочерком при недоступности тикеров. Контракт только расширяется — обратно совместимо.
- Подсказки: `METRIC_TOOLTIPS` уже содержит `plannedRisk` и `worstCase`; недостающие тексты (plannedProfit, realRisk, intrinsic, выделенный капитал в группе) добавляются по образцу справочника.

### D4. Упразднение мета-строки

`headerMeta` и её рендер удаляются из `construction-card-page.tsx`; значение «дата открытия» уже присутствует в показателе «период». Тексты плановых значений переезжают в группы без дублирования где-либо ещё.

### D5. Техстрока котировок и зона синтетики

«Котировки на» покидает строку метрик и становится обособленной техстрокой (11px, `$textMuted`/`$textSecondary`, выравнивание вправо) между группами и линией синтетики. Линия `h-px bg-divider` и строки «зафиксировано синтетикой» / «с учётом зафиксированного» не меняются.

## Risks / Trade-offs

- [Модульная сетка на узких экранах ломает равные блоки] → осознанный non-goal: адаптив вынесен в отдельное изменение; до него grid деградирует переносом колонок без потери данных.
- [Скрытие «стоимости»/«занятости» снижает обзорность] → величины остаются в таблице позиций; сценарий `scenario-detail-header-hides-service-metrics` фиксирует контракт.
- [Новое агрегатное поле требует backend-правок] → вычисление на лету из уже собираемых данных ноги, без миграции схемы; поле nullable.

## Migration Plan

1. Backend: агрегат `totalIntrinsicValueUsdt` в саммари + контракт (список и карточка).
2. design.pen: мастер карточки по Г1, упразднение Meta.
3. Frontend: группы в `metric-strip.tsx`, удаление `headerMeta`, тесты.
4. Скриншот-сверка; откат — покомпонентный revert, контракт обратно совместим.

## Open Questions

- Финальные тексты подсказок для новых показателей (plannedProfit, realRisk, intrinsic) — решаются при переносе по образцу существующего справочника, на контракт не влияют.
