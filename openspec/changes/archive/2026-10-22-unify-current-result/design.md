# Design

## Context

Маркер индикатора финрезультата считается на frontend из `realizedPnL + unrealizedPnL`, метрика сводки «общий P&L» (поле `totalPnL`) — backend'ом как `realizedPnL + unrealizedPnL + adjustmentsPnL`. Попап чтения называет маркер «оценкой итога», глоссарий определяет «Маркер итога» без корректировок, а performance-спека — «Итог конструкции» с корректировками: термин «итог» имеет две формулы, и пользователь видит два числа с похожими именами. Все слагаемые уже публикуются в API карточки и строки списка (`adjustmentsPnL` включительно), поэтому унификация значения — frontend-правка. Мотивация — см. proposal.md; контракты величин — `openspec/specs/analytics/performance`, `openspec/specs/ui/screens`.

## Goals / Non-Goals

**Goals:**

- Одно число «текущий результат» на всех поверхностях: маркер индикатора, метрика сводки карточки, колонки списка и позиций.
- Один термин в глоссарии и спеках; устаревшие имена — в Avoid.
- Тексты подсказки чтения индикатора: горизонт «к экспирации» у насечки и причина расхождения насечки и маркера при полной синтетической фиксации.

**Non-Goals:**

- Сводная величина «с учётом зафиксированного синтетикой» и её подсказка не меняются вовсе (решение проработки: величина — третья линза, равенство маркеру не предполагается).
- Журнальная сводка экрана «Конструкции» («итог журнала») и тексты подсказок/чатов агента сохраняют нынешние формулировки.
- Имена полей API-контрактов (`totalPnL`, `TotalPnL`, `worstCaseUsdt`, `syntheticAdjustedTotalUsdt`) и backend-расчёты не меняются; XML-doc описания контрактов остаются.
- Имя насечки «худший исход» сохраняется (уточняется только пояснение в подсказке); ADR-0015 не пересматривается — клэмп «маркер не левее насечки» по-прежнему отсутствует.

## Decisions

- **D1 — Единое значение: маркер включает внешние корректировки.** «Текущий результат» = реализованный + нереализованный + внешние корректировки PnL; маркер результата ставит это значение на шкалу. Альтернативы: оставить две величины с разными именами (маркер — «ликвидационная оценка», метрика — «итог с корректировками») — отвергнуто: дублирование имён при почти всегда равных числах воспроизводит исходную путаницу; включить корректировки только в метрику — отвергнуто по той же причине. Ярлык «заберу при ликвидации сейчас» остаётся в попапе описанием рыночной части (реализованный + нереализованный), рядом с явным упоминанием корректировок.
- **D2 — Имена по поверхностям.** Канон «текущий результат»: метрика сводки карточки — «текущий результат», колонка позиций — «Текущий результат», колонка списка — «Результат» (компакт-стиль колонок списка: «Реализованная», «Коррект.»). Avoid: «Итог» (как имя метрики/колонки), «Общий P&L», «оценка итога». У позиции корректировок нет, поэтому «текущий результат позиции» = реализованный + нереализованный — формула не меняется.
- **D3 — Геометрия принимает корректировки отдельным входом.** `FinResultInput` дополняется полем суммы внешних корректировок; итог индикатора = реализованный + нереализованный + корректировки. Деградация при сбое котировок прежняя по духу: недоступная нереализованная часть скрывается, маркер подписывается доступной частью (реализованный + корректировки), индикатор помечается неполным. Три места вызова — карточка, превью, строка списка — передают `adjustmentsPnL` из уже существующих полей контракта. Backend не меняется.
- **D4 — Насечка: имя сохранено, горизонт добавлен в пояснение.** Титул подписи «худший исход» не переименовывается (термин точен: наихудший исход конструкции, а не «результат на экспирацию»); попап чтения поясняет насечку как «худший исход конструкции к экспирации».
- **D5 — Расхождение при полной синтетической фиксации объясняется, а не устраняется.** В попап добавляется одна фраза: маркер — рыночная оценка «сейчас» (временная стоимость встречного опциона, спред, свежесть котировок), насечка — значение к экспирации; к экспирации значения сходятся. Клэмп по-прежнему запрещён (ADR-0015).
- **D6 — Глоссарий.** Новые/переименованные термины: «Текущий результат», «Маркер результата» (бывший «Маркер итога»), «Заливка результата» (бывшая «Заливка итога»); формулировки «Сверхприбыли» переводятся на «текущий результат». При правке раздела «Подсказка чтения индикатора» обновляется её устаревшая ссылка на active change (термин уже синхронизирован в живую спецификацию). ADR не создаётся: решение обратимо силами frontend и спек, стоимость смены низка; обоснование живёт здесь и в спеках.

## Risks / Trade-offs

- [У конструкций с корректировками значение маркера сдвинется — может читаться как регрессия] → сдвиг помечен **BREAKING** в proposal, поведение закреплено сценариями «Маркер результата включает внешние корректировки» и «Сбой котировок оставляет результат по доступной части», попап объясняет состав.
- [Две формулы «текущего результата»: у позиции — без корректировок, у конструкции — с ними] → корректировки существуют только на уровне конструкции; подсказки метрик называют состав явно.
- [Слово «итог» остаётся в журнальной сводке и текстах агентов] → вне scope осознанно; Avoid в глоссарии относится к имени метрики конструкции, а не к слову в пролозе.
- [Переименование колонок ломает тесты, сверяющие заголовки] → тесты обновляются в одном блоке с переносом; скриншот-сверка по макету закрывает расхождения с design.pen.
