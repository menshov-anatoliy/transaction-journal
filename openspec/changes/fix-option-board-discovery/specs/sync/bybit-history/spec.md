# Spec Delta

## MODIFIED Requirements

### Requirement: Опционы синхронизируются по всем базовым активам
Синхронизация категории option SHALL охватывать все базовые активы, по которым у аккаунта есть история исполнения. Перед проходом категории система SHALL строить перечень областей перебора как объединение независимых источников: один безфильтровый проход истории исполнения категории, который загружает записи всех активов аккаунта и обнаруживает активы, невидимые перечислению справочника; базовые активы записей исполнения и delivery-записей сырьевого хранилища; базовые активы живого перечисления публичного справочника инструментов — безфильтровый ответ покрывает только доску по умолчанию и полным перечнем доски не является; базовые активы из конфигурации приложения для досок, отсутствующих в остальных источниках. По каждому активу перечня история исполнения SHALL запрашиваться отдельной областью с фильтром по активу — это гарантирует полноту истории актива независимо от поведения безфильтрового запроса. Перечень SHALL определяться при каждом запуске синхронизации. История исполнения категории linear и delivery-записи SHALL запрашиваться без фильтрации по инструментам.

Traceability ID: requirement-option-base-coin-coverage

#### Scenario: Сделки не-BTC опционов попадают в журнал
Traceability ID: scenario-non-btc-option-trades-loaded
- **WHEN** на бирже исполнены сделки опционов нескольких базовых активов, в том числе активов, отсутствующих в безфильтровом перечислении справочника
- **THEN** после синхронизации все эти сделки находятся в журнале
- **AND** атрибуты каждой сделки соответствуют биржевой записи исполнения

#### Scenario: Новый базовый актив доски подхватывается следующим синком
Traceability ID: scenario-new-base-coin-picked-up
- **WHEN** по базовому активу, отсутствующему в перечне областей текущего запуска, исполняются сделки
- **THEN** безфильтровый проход этого запуска загружает эти записи в сырьевое хранилище
- **AND** очередной запуск определяет актив в перечне источников и проходит его историю отдельной областью

#### Scenario: Делистнутый актив загружается из конфигурации
Traceability ID: scenario-delisted-base-coin-from-config
- **WHEN** торговая история есть по базовому активу, чья доска отсутствует в текущем перечислении справочника и в сырьевом хранилище, и актив указан в конфигурации приложения
- **THEN** синхронизация запрашивает историю исполнения и по этому активу

#### Scenario: Повторные проходы активов не создают дублей
Traceability ID: scenario-base-coin-passes-no-duplicates
- **WHEN** безфильтровый проход и проходы отдельных активов возвращают уже известные журналу записи
- **THEN** система пропускает известные записи по биржевому идентификатору исполнения

### Requirement: Отказ биржи по глубине хранения завершает перебор без сбоя
Отказ биржи со ссылкой на глубину хранения истории при запросе окна перебора SHALL NOT прерывать запуск синхронизации и SHALL NOT оставлять запуск неуспешным. Система SHALL распознавать такой отказ по коду и сообщению ошибки биржи, один раз повторить окно с временем начала, зажатым до границы хранения истории биржи, и при повторном отказе считать перебор истории области исчерпанным: завершить проход этой области перебора, зафиксировать водяной знак успешного запуска и продолжить перебор остальных областей категории; для категории с единственной областью перебора исчерпание области завершает проход категории. Правило SHALL применяться и в первичном backfill, и в инкрементальной догрузке.

Traceability ID: requirement-history-boundary-guard

#### Scenario: Окно у границы повторяется с зажатым началом
Traceability ID: scenario-boundary-window-retried-clamped
- **WHEN** окно перебора пересекает границу хранения истории и биржа отвергает запрос как выходящий за глубину хранения
- **THEN** система один раз повторяет запрос этого окна с временем начала, зажатым до границы хранения
- **AND** записи в зажатом диапазоне загружаются и сохраняются

#### Scenario: Повторный отказ у границы исчерпывает историю
Traceability ID: scenario-boundary-refusal-ends-walk
- **WHEN** повторный запрос окна с зажатым временем начала тоже отвергнут биржей по причине глубины хранения
- **THEN** перебор области считается исчерпанным, её оставшиеся окна не запрашиваются
- **AND** уже полученные записи сохранены, водяной знак фиксируется и запуск не помечается неуспешным

#### Scenario: Пограничное исчерпание одной области не останавливает остальные
Traceability ID: scenario-boundary-exhaustion-scoped-to-area
- **WHEN** пограничное исчерпание возникло в области одного базового актива многобластной категории
- **THEN** обход этой области прекращается
- **AND** области остальных базовых активов категории запрашиваются штатно

#### Scenario: Инкрементальная догрузка зажимает нижнюю границу
Traceability ID: scenario-incremental-boundary-clamped
- **WHEN** инкрементальная догрузка после долгого перерыва вычисляет нижнюю границу перебора старше границы хранения истории биржи
- **THEN** нижняя граница зажимается до границы хранения
- **AND** догрузка выполняется до конца без пограничного отказа биржи

## ADDED Requirements

### Requirement: Предупреждения запуска сохраняются с записью запуска
Предупреждения завершённого запуска синхронизации — перечень пропущенных областей перебора, неразрешённых инструментов и непокрытых базовых активов опционной доски — SHALL сохраняться с записью запуска. Страница синхронизации SHALL показывать предупреждения последнего завершённого запуска при открытии страницы, без повторного запуска синхронизации. Предупреждения SHALL показываться только для запусков, у которых они есть; запуск без предупреждений SHALL NOT отображать предупреждающих заметок.

Traceability ID: requirement-run-warnings-persisted

#### Scenario: Предупреждения запуска видны при открытии страницы
Traceability ID: scenario-run-warnings-shown-on-page-load
- **WHEN** последний завершённый запуск имеет непустые перечни предупреждений и страница синхронизации открыта заново
- **THEN** предупреждения показываются рядом с данными этого запуска в том же виде, как сразу после его завершения

#### Scenario: Чистый запуск не показывает предупреждений
Traceability ID: scenario-clean-run-no-persisted-warnings
- **WHEN** последний завершённый запуск не имеет предупреждений
- **THEN** страница синхронизации не отображает предупреждающих заметок
