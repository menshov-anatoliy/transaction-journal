# Design

## Context

Метрики позиции и конструкции вычисляются при чтении: чистый `PositionMetricsCalculator` (FIFO), затем `UnrealizedPnlMarkEvaluator` подставляет открытым остаткам марку, нереализованный PnL и общий PnL; `ConstructionMetricsCalculator` сводит позиции и корректировки и относит результат к выделенному капиталу. Слой марок уже несёт семантику деградации: позиция без марки оставляет нереализованный PnL и общий PnL как null, остальные метрики не трогает. Строки таблицы позиций собирает `ConstructionDetailReadModel.ReadPositionsAsync`: сортировка по символу, проценты от капитала считаются здесь же локальной функцией `PercentOfCapital`. Тип и экспирация опциона доступны через `OptionSymbolParser.TryParse` (`OptionSymbolParts.Type`, `ExpiryDate`). Мотивация изменения — в `proposal.md`.

## Goals / Non-Goals

**Goals:**

- Стоимость позиции и конструкции по текущим маркам как метрики чтения с деградацией по образцу нереализованного PnL.
- Производные проценты: «% общего P&L от стоимости позиции» и «занято капитала, %».
- Детерминированный порядок строк таблицы позиций: статус → тип инструмента → тикер → экспирация.

**Non-Goals:**

- Пользовательская сортировка кликом по заголовкам.
- Изменение сводки (kstrip) списка конструкций и агрегатов журнала.
- Учёт гарантийного обеспечения (margin) и «вложено по сделкам» (FIFO-база) — другие semantics стоимости, отвергнутые при проработке.
- Изменения схемы БД и доменных данных.

## Decisions

### D1. Стоимость позиции считается слоем марок

`MarkValue = MarkPrice × Residual` вычисляется в `UnrealizedPnlMarkEvaluator.EvaluatePosition` тем же жестом, что `MarkPrice`/`UnrealizedPnL`/`TotalPnL`: закрытая позиция (`Residual == 0`) и позиция без марки остаются без стоимости (`MarkValue == null`), остальные метрики не меняются. Поле добавляется в `PositionMetrics`.

Альтернатива — считать в read model из `MarkPrice` — отвергнута: деградация «сбой марок» задаётся слоем марок, дублирование правил в двух местах разошлось бы при первой же правке.

### D2. Стоимость конструкции и занятость капитала — в `ConstructionMetricsCalculator`

`ConstructionMetrics.MarkValue`: null, когда открытых остатков нет или хоть один открытый остаток не оценен марками (тот же флаг, что для нереализованного PnL); иначе сумма стоимостей открытых позиций. `CapitalUsagePercent` — существующей локальной функцией `Percent(MarkValue)`: незаданный/нулевой капитал или отсутствующая стоимость дают null, знак сохраняется. Правка капитала меняет только проценты — инвариант не нарушается.

### D3. «% P&L от стоимости» — в строке таблицы позиций

`ConstructionPositionRow` получает `MarkValue` и `TotalPnLPercentOfValue`, вычисляемые в `ReadPositionsAsync` рядом с `PercentOfCapital` по прецеденту «проценты строк живут в read model». Условие вычисления: стоимость и общий PnL доступны и стоимость строго положительна; иначе null.

Альтернатива — поле в `PositionMetrics` — отвергнута: метрики позиции не владеют форматными правилами производных процентов, а консистентность с процентами от капитала важнее.

### D4. Сортировка позиций — в read model по рангам

В `ReadPositionsAsync` заменяется `OrderBy(Symbol)` на композицию: открытые раньше закрытых → ранг типа (CALL = 0, PUT = 1, прочие = 2, из `OptionSymbolParser.TryParse`; непарсимый символ — прочий) → тикер `StringComparer.Ordinal` → `ExpiryDate` по возрастанию. Read model уже ссылается на Domain, новая зависимость не вводится.

### D5. Отображение — по образцу существующих величин

Стоимость: USDT, 2 знака, со знаком; null → «—»; сбой марок → признак «сбой марок» (единый с нереализованным PnL). Проценты: 1 знак, со знаком; null → «—». В списке конструкций колонки «Стоимость» (рядом с «Капитал») и «Занято капитала, %» (рядом с «% капитала»); в деталях — значения в kstrip рядом с «% капитала» и колонки «Стоимость», «% P&L от стоимости» после «Общий P&L». Повторно используются существующие хелперы форматирования страниц.

## Risks / Trade-offs

- [Отрицательная стоимость кредитовых конструкций непривычна] → знак сохраняется и в стоимости, и в занятости — это смысловой сигнал «кредит»; лишь «% P&L от стоимости» гасится в «—» при неположительной базе.
- [Список конструкций теперь показывает ещё одну марочнозависимую величину] → деградация переиспользует существующий признак сбоя марок строки, новых запросов к провайдеру не добавляется: марки уже запрашиваются для нереализованного PnL.
- [Ранг «прочие» для непарсимых символов может скрыть странный инструмент в хвосте] → прогнозируемо и оговорено спекой; прочие идут после PUT внутри группы открытых.

## Migration Plan

Не требуется: величины производные, считаются при чтении, хранение и схема не меняются. Откат — простой откат коммита.

## Open Questions

Нет — семантика и граничные случаи зафиксированы в спеках изменения по итогам проработки с пользователем.
