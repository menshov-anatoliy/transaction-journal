# Proposal

## Why

Индикатор финрезультата и метрики конструкции называют одну величину разными именами («маркер — оценка итога „заберу при ликвидации сейчас“», «общий P&L», колонка «Итог»), а значения при этом расходятся: маркер считается без внешних корректировок, «общий P&L» — с ними. Читатель видит два числа с похожими именами и не может понять, какое из них «настоящий» результат конструкции.

## What Changes

- Единое имя и единое значение: канон — «текущий результат» = реализованный + нереализованный + внешние корректировки PnL. Маркер индикатора отныне ставит на шкалу это полное значение (сейчас корректировки не учитывает) — **BREAKING** для чтения значения маркера при конструкциях с корректировками.
- «Маркер итога» переименован в «маркер результата»; строка попапа чтения индикатора объясняет: «маркер — текущий результат: реализованный результат, оценка остатков „заберу при ликвидации сейчас“ и внешние корректировки».
- Метрика сводки карточки «общий P&L» → «текущий результат»; колонка таблицы позиций «Общий P&L» → «Текущий результат»; колонка списка конструкций «Итог» → «Результат» (компакт-стиль колонок списка).
- Подсказка чтения индикатора: насечка поясняется как «худший исход конструкции к экспирации»; добавлена фраза, почему при полной синтетической фиксации маркер может стоять левее насечки (временная стоимость встречного опциона, спред, свежесть котировок; к экспирации значения сходятся).
- Глоссарий: новые канонические термины «Текущий результат», «Маркер результата», «Заливка результата»; «Итог», «Общий P&L», «оценка итога» выводятся из употребления (Avoid).
- Не меняется: сводная величина «с учётом зафиксированного синтетикой» и её подсказка (решение проработки — оставить как есть), имена полей API-контрактов (`totalPnL`, `worstCaseUsdt` и др.), журнальная сводка экрана «Конструкции», тексты подсказок и чатов агента.

## Capabilities

### New Capabilities

(нет — изменение развивает существующие capabilities)

### Modified Capabilities

- `ui/screens`: маркер индикатора ставится на текущий результат с внешними корректировками; переименованы метрика сводки, колонки списка и позиций; обновлены тексты подсказки чтения индикатора (насечка к экспирации, маркер результата, расхождение при полной синтетической фиксации).
- `analytics/performance`: термин «итог конструкции» заменён каноническим «текущий результат конструкции» в требовании метрик конструкции (формула неизменна — сумма позиций и корректировок); единый термин нужен, чтобы подсказки метрик опирались на зафиксированную формулировку.

## Impact

- `design.pen`: мастера «Сводка метрик» (метрика «текущий результат»), таблица списка (колонка «Результат»), таблица позиций («Текущий результат»), подсказка «Чтение индикатора» (строки насечки, маркера и примечание), визуальная подсказка «риск — результат — профит». Правка раньше frontend, приёмка — скриншот-сверка.
- `frontend`: `finresult/geometry.ts` (вход корректировок, подпись маркера), `metric-strip.tsx` (метка, вход индикатора, попап), `constructions-table.tsx` (колонка, вход индикатора), `construction-preview.tsx` (вход индикатора), `positions-table.tsx` (колонка), `metric-tooltips.ts` (totalPnl, listTotal, totalMarker, positionTotalPnl), тесты геометрии и компонентов.
- `src` (backend): контракты и расчёты не меняются — все слагаемые текущего результата уже публикуются (`realizedPnL`, `unrealizedPnL`, `adjustmentsPnL` в карточке и строке списка).
- `GLOSSARY.md`: термины «Текущий результат», «Маркер результата», «Заливка результата», Avoid-записи, обновление устаревшей ссылки термина «Подсказка чтения индикатора» на живую спецификацию.
- Зависимостей от активных changes нет.
