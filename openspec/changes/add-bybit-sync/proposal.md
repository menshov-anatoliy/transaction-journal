# Proposal

## Why

Журнал сделок Bybit не может работать без исходных данных: сделки и закрывающие записи должны попадать в журнал из биржи воспроизводимым и безопасным способом. Решения карты (тикет [#8](https://github.com/menshov-anatoliy/transaction-journal/issues/8)) фиксируют режим — ручная синхронизация по кнопке с первичным backfill всей доступной истории — а исследование Bybit V5 API (`docs/research/bybit-api.md`, ветка `research/bybit-api`) даёт фактическую основу: эндпоинты, окна, пагинацию, лимиты.

## What Changes

- Добавляется capability загрузки истории исполнения из Bybit V5 API: первичный backfill всей доступной истории и последующие инкрементальные догрузки, оба запускаются вручную одной кнопкой «Синхронизировать».
- Необработанные записи биржи (execution, delivery, справочник инструментов) сохраняются в собственном хранилище журнала как источник для переразбора; повторные синки идемпотентны по биржевым идентификаторам (`execId`; `symbol + deliveryTime` для delivery).
- Delivery-записи экспирации опционов тянутся отдельным эндпоинтом и становятся основой закрывающих записей по правилам ADR-0002; OTM-экспирации без биржевой записи закрываются автоматически по нулевой цене в deliveryTime инструмента.
- Новые сделки после синка попадают во «Входящие» — привязка к конструкциям остаётся ручной и в этом change не задаётся.
- Клиент Bybit соблюдает лимиты API (учёт заголовков `X-Bapi-Limit-*`, пауза на `retCode 10006` и HTTP 403), обрабатывает ошибки с ретраями и не выполняет торговых операций: ключи только на чтение.
- Curiosity-каналы не затрагиваются: funding в результат не входит, websocket-стримы не используются.

## Capabilities

### New Capabilities

- `sync/bybit-history`: ручная синхронизация истории исполнения и экспираций из Bybit в журнал — backfill, инкрементальные догрузки, идемпотентность, сырые записи, обработка ошибок и лимитов.

## Impact

- Новая подсистема доступа к Bybit V5 API: HttpClient-клиент с HMAC-SHA256-авторизацией без SDK, read-only API-ключ (место хранения секрета решается тикетом [#4](https://github.com/menshov-anatoliy/transaction-journal/issues/4)).
- Новые таблицы SQLite/EF Core: сырые записи исполнения, сырые delivery-записи, справочник инструментов, курсор/водяной знак синхронизации.
- Точка входа UI (кнопка «Синхронизировать» и индикация результата) — контракт с будущей capability экранов; для MVP достаточно минимальной страницы запуска.
- Внешние зависимости не добавляются: публичные и приватные REST-эндпоинты Bybit, лимиты 50 req/s (execution/delivery) и IP-лимит 600 req/5с избыточны для ручного режима.
- Затрагивает глоссарий CONTEXT.md («Синхронизация», «Сделка», «Закрывающая запись») и ADR-0001/ADR-0002, на которые опираются правила преобразования записей.
