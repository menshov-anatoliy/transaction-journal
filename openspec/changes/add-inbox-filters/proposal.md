# Proposal

## Why

«Входящие» показывают все непривязанные сделки одним списком без возможности отсечь лишнее. С ростом истории синхронизации найти в списке нужные сделки (по периоду, инструменту, направлению) становится трудно: пользователь просматривает сотни строк вручную. Блок фильтров решает эту задачу чтения, не затрагивая доменные правила привязки.

## What Changes

- На экране «Входящие» появляется блок фильтров над таблицей непривязанных сделок.
- Фильтр диапазона дат: поля «с» и «по»; по умолчанию выбран скользящий последний месяц — от (сегодня − 1 месяц) до сегодня.
- Фильтр инструмента: список доступных инструментов «Входящих» с чекбоксами; по умолчанию выбраны все.
- Фильтр направления: чекбоксы «покупка» и «продажа»; по умолчанию выбраны оба.
- Таблица показывает только сделки, удовлетворяющие всем трём фильтрам одновременно.
- «Выбрать всё» выбирает все отфильтрованные (видимые) сделки.
- Бейдж вкладки «Входящие» считает все непривязанные сделки и от фильтров не зависит.
- Фильтры не меняют привязку и разбор сделок: команды разбора работают с выбранными видимыми строками как раньше.

### Modified Capabilities

- `ui/screens`: требование «Экран "Входящие" — выбор и привязка сделок» расширяется блоком фильтров списка (диапазон дат, инструмент, направление) с состоянием по умолчанию «последний месяц / все инструменты / оба направления» и семантикой «Выбрать всё» по видимым строкам.

## Impact

- `src/TransactionJournal/Components/Pages/Inbox.razor` — разметка блока фильтров, состояние фильтров в circuit-состоянии компонента, фильтрация прочитанного списка перед отрисовкой.
- `src/TransactionJournal/Components/Pages/Inbox.razor.css` (при необходимости) или `wwwroot` стили — оформление блока фильтров.
- `tests/TransactionJournal.Tests/Ui/InboxScreenTests.cs` — проверки фильтров и «Выбрать всё» по видимым строкам.
- Новых доменных правил, изменений API и схемы базы данных нет: фильтрация — представление read-модели `InboxReadModel`, чей контракт не меняется.
