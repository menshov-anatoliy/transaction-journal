# Design

## Context

Конвейер синхронизации уже работает: `ExecutionWindowPass` листает 7-дневные окна `execution/list` курсорной пагинацией, `DeliveryCategorySync` — 30-дневные окна `delivery-record`, `JournalSyncService` оркестрирует категории и перестраивает проекцию. Документированное поведение Bybit (подтверждено официальными docs): для `category=option` параметр `baseCoin` эндпоинта `execution/list` по умолчанию равен `BTC` — без явного перебора активов не-BTC сделки не возвращаются; `delivery-record` фильтра `baseCoin` не имеет и отдаёт все символы категории. Глубина хранения истории биржей — порядка двух лет. Мотивация — в proposal.md.

## Goals / Non-Goals

**Goals:**

- Полное покрытие инструментов: все базовые активы опционной доски, вся линейка linear, все delivery-записи.
- Глубина backfill, не зависящая от пауз в торговле: остановка по фиксированному полу глубины, а не по пустому окну.
- Пользовательский путь догрузки пропущенной истории: сброс состояния категории и повторный синк без дублей.
- Минимальная поверхность изменений: переиспользовать существующие `baseCoin`-поля запросов, дедуп и resilience.

**Non-Goals:**

- Websocket/realtime, синк по расписанию — как и раньше, только REST по кнопке.
- Исправление сортировки `execution/list` при равных `execTime` (существующее ограничение инкрементальной ранней остановки; смягчается перекрытием окна).
- Изменение схемы БД: новые параметры — конфигурация кода, `SyncState` не расширяется.
- Funding-записи, spot/inverse категории.

## Decisions

### D1. Список базовых активов — из публичного instruments-info при каждом запуске

Новый компонент `IOptionBaseCoinSource` (реализация поверх существующего `IBybitInstrumentSource`): листает `instruments-info?category=option` страницами по 1000 с курсором, собирает distinct `baseCoin`, объединяет с конфигурируемым списком дополнительных активов и в детерминированном порядке. Список строится заново при каждом запуске синхронизации категории option — новая доска биржи подхватывается очередным синком без правок кода.

Альтернативы: хардкод списка активов — устаревает при заведении новой доски; перебор по `symbol` — тысячи запросов вместо десятков; `settleCoin`-фильтр — не отменяет дефолт `baseCoin=BTC`.

### D2. baseCoin проходит через окно прохода, состояние остаётся на категорию

`ExecutionWindow` получает nullable-поле `BaseCoin`; `ExecutionWindowPass` прокладывает его в `BybitExecutionListQuery.BaseCoin` (поле запроса уже существует, клиент не меняется). `ExecutionCategorySync` перед обходом строит список областей прохода: для linear — одна область без фильтра, для option — область на каждый актив из D1. Режим, водяной знак и граница backfill остаются на категорию: проходы активов пересекаются по времени, но дедуп по `execId` в хранилище исключает дубли, а водяной знак фиксируется только после успешного прохода всех активов категории.

Альтернатива: состояние `SyncState` на пару (категория, актив) — взрыв строк состояния и перетасовка схемы; отклонено, выгоды нет.

### D3. Остановка backfill по полу глубины

В опции движков категорий добавляется `MaxBackfillDepthMs` (исполнение и delivery), дефолт — 730 дней. Backfill-цикл листает окна назад от момента запуска, нижняя граница `floorMs = startedAtMs − MaxBackfillDepthMs`; последнее окно усекается до пола, после него проход категории завершён. Остановка по пустому окну и кламп окна по `BackfillBoundaryMs` удаляются: `BackfillBoundaryMs` продолжает записываться как факт «самая ранняя увиденная запись», но глубину проходов не ограничивает — граница, вычисленная по неполному набору активов, не должна резать историю других активов.

Альтернативы: «N пустых окон подряд» — эвристика без гарантий покрытия; отсутствие пола — неограниченный перебор вглубь.

### D4. Сброс состояния категории — операция хранилища с подтверждением в UI

`IExecutionSyncStateStore` расширяется методом `ResetAsync(category)`: `JournalSyncStore` удаляет строку `SyncStates` категории (локальная операция, к бирже не обращается). На странице «Синхронизация» появляется блок обслуживания с командой сброса по категории и подтверждением; команда блокируется на время выполнения синка. Следующий запуск видит отсутствие водяного знака и выполняет backfill категории существующей логикой выбора режима — новых режимов не появляется.

Альтернативы: ручной SQL — не пользовательский путь и не восстанавливаемо по кнопке; сброс всех категорий одной командой — грубее, сектор сброса полезен точечно (например, только option).

### D5. Конфигурация с дефолтами в коде

`Sync:MaxBackfillDepthDays` (дефолт 730) и `Sync:ExtraOptionBaseCoins` (список, дефолт пуст) читаются при сборке опций движков в `Program.cs`. Приложение работает без секции — дефолты зашиты в код, конфигурация нужна только для нестандартной глубины или делистнутых досок.

## Risks / Trade-offs

- [Разовый backfill стал длиннее: ~десятки активов × ~105 окон × страницы] → разовая операция после сброса; троттлинг и resilience уже соблюдают лимиты; прерывание безопасно (пачки сохраняются, состояние не фиксируется, повтор продолжает с места остановки).
- [Делистнутые доски отсутствуют в текущем `instruments-info`] → закрывается конфигурационным списком дополнительных активов (D5); выявляются по факту пропусков.
- [Сброс в момент выполнения синка] → команда сброса в UI блокируется на время синка; гонка исключена на уровне экрана.
- [Граница `BackfillBoundaryMs` теряет роль оптимизации] → повторные полные проходы дороже на ~сотню пустых запросов на актив; цена приемлема против потери истории.
- [Дефолт 730 дней — оценка глубины хранения биржи] → параметр конфигурации; при смене политики биржи правится без кода.

## Migration Plan

Изменений схемы БД нет — выкат безопасен без миграций. После выката пользователь сбрасывает состояние категории option (linear — по желанию) и запускает синхронизацию: backfill до пола глубины догружает пропущенные сделки не-BTC досок и историю старее пауз торговли, дедуп по `execId` и `symbol + deliveryTime` исключает дубли. Откат — возврат кода: сырые записи и домен от новых параметров не зависят, состояние категорий пересоздаётся обычным синком.
