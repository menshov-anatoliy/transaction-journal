# Design

## Context

Сверка `reconcile-frontend-with-design` завершена и заархивирована; её design.md (D1: hex-токены в `index.css`, семантика shadcn поверх) и ADR 0011 действуют без изменений. Токен-слой frontend содержит 24 переменные design.pen 1:1 + блок `--fin-*`, наследующий токены. Аудит (`.wf-research/design-audit/report.md` §3.10) зафиксировал: подпись сверхприбыли — точный цвет мастера `#8a6a1f` без токена; минор-заливка нереализованного убытка — дизайнерская пара riskZone `#EFB6AE`, прежний frontend-цвет `#f6cbc7` был изобретён и на сверке заменён. design.pen редактируется только через MCP pen; его машиночитаемое отражение — экстракт `.wf-research/design-audit/design-extract.json`.

## Goals / Non-Goals

**Goals:**

- Закрыть оба исключения Q12 в самой дизайн-системе: два новых семантических токена в design.pen.
- Полностью токенизировать фининдикатор без визуальных изменений: значения цветов не меняются, меняется только их источник.
- Выполнить обязательную по ADR 0011 повторную сверку затронутых видов индикатора.

**Non-Goals:**

- Любые другие правки design.pen (состав фреймов, компоненты, прочие цвета) и новые токены сверх двух.
- Изменение геометрии/типографики индикатора и остальных экранов — сверка здесь регрессионная, не редизайн.

## Decisions

### D1. Имена и значения токенов

`superLabel: #8a6a1f` (подпись сверхприбыли — тёмный текстовый цвет зоны superZone из мастера onchD) и `unrealLoss: #EFB6AE` (минор-заливка нереализованного убытка — пара к `mint`, которой соответствует нереализованная прибыль). Значения берутся из мастера: подпись — точный цвет фреймов индикатора, заливка — дизайн-пара из аудита §3.10; перед записью значения подтверждаются `Get` по узлам мастера onchD через MCP pen. Альтернатива «оставить `--fin-unreal-negative` на riskZone без токена» отклонена: заимствование чужого по смыслу токена не даёт дизайнеру независимого управления парой нереализованного PnL; `#f6cbc7` не возвращается — цвет был изобретён frontend.

### D2. Правка design.pen и экстракта — только через MCP pen

Переменные добавляются в design.pen инструментом execute MCP pen (прямой парсинг/правка JSON запрещены, ADR 0011). Затем экстракт `.wf-research/design-audit/design-extract.json` перегенерируется тем же способом, что и исходный (через execute MCP pen), с обновлением `extractedAt`; контроль — дифф экстракта содержит ровно две новые переменные.

### D3. Маппинг frontend — по конвенции D1 сверки

`index.css`: `--super-label: #8a6a1f` и `--unreal-loss: #EFB6AE` в блок дизайн-токенов (hex, без oklch); утилиты `@theme inline` (`--color-super-label`, `--color-unreal-loss`); в блоке `--fin-*` — `--fin-super-label: var(--super-label)` и перенаправление `--fin-unreal-negative: var(--unreal-loss)`; временные комментарии со ссылкой на backlog #73 удаляются. В `fin-result-indicator.tsx` хардкод `text-[#8a6a1f]` заменяется на `text-[color:var(--fin-super-label)]`, комментарий-исключение и метка `Traceability: issue:#73` замещаются ссылкой на требование дизайн-системы. Потребление через `--fin-*` сохраняется — компонент не адресует базовые токены напрямую (как и остальные вхождения индикатора).

### D4. Повторная сверка — регрессионная, три вида индикатора

Изменение design.pen после сверки влечёт повторную сверку затронутых экранов (ADR 0011). Затронуты только носители индикатора: карточка конструкции (полный и средний вид), таблица конструкций (компактный вид). Пары «макет/страница» снимаются методом D3 сверки (MCP pen: load-page живой страницы + экспорт макета) в `.wf-research/design-audit/screenshots/09-finresult-tokens/`. Ожидание — попиксельная неизменность: значения цветов не меняются, меняется лишь их источник.

## Risks / Trade-offs

- [Правка design.pen через execute задевает лишнее] → контроль диффом перегенерированного экстракта (ровно +2 переменные) и git-диффом файла; откат — revert коммита design.pen.
- [Имя токена не совпадёт с будущей конвенцией дизайнера] → имена следуют действующим паттернам camelCase design.pen (зоны/пары); переименование при желании дизайнера — отдельная механическая правка.
- [Сверка покажет расхождение] → это дефект прошлой сверки, а не этого change: фиксируется отдельной находкой и правится в рамках затронутого вида индикатора.

## Migration Plan

Одноступенчато: правка design.pen → перегенерация экстракта → токен-слой и индикатор → прогон `npm run build`/`npm test` в `frontend/` → регрессионная сверка. Откат — git revert (визуального эффекта нет, риск отката нулевой).
