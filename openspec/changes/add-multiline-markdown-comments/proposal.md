# Proposal

## Why

Комментарии на сделках, позициях и конструкциях сейчас вводятся однострочным полем и отображаются как плоский текст: переносы строк теряются, а структурировать заметку о торговой цели (списки, выделения, фрагменты кода) невозможно. Комментарий как инструмент самодокументации журнала обесценен — особенно для конструкций, где описывается замысел и ход торговли.

## What Changes

- Однострочный `<input>` при inline-редактировании комментария заменяется на многострочный `<textarea>` на всех трёх уровнях: сделка, позиция, конструкция.
- Сохранение комментария выполняется по нажатию Ctrl+Enter в поле редактирования; кнопки «Сохранить»/«Отмена» остаются, Enter без Ctrl по-прежнему вставляет перенос строки.
- Отображение комментария рендерится из Markdown: поддерживаются заголовки, списки, выделение, код и переносы строк.
- Сырой HTML в пользовательском Markdown экранируется: рендеринг безопасен для единственного пользователя-трейдера без разноса привилегий.
- Хранение не меняется: комментарий остаётся свободным текстом, внутренние переносы строк сохраняются, инерция комментариев относительно расчётов не нарушается.
- Новая зависимость приложения: пакет Markdig для преобразования Markdown в HTML.

### Modified Capabilities

## Impact

- `Components/Pages/ConstructionDetail.razor` — поля редактирования комментариев и места их отображения (шапка деталей, таблицы позиций и сделок).
- Новый небольшой рендерер Markdown в UI-слое приложения.
- `wwwroot/app.css` — стили отображения отрендеренного комментария.
- `TransactionJournal.csproj` — новая зависимость Markdig.
- Тесты UI (bUnit) — проверки многострочного ввода и рендеринга Markdown.
