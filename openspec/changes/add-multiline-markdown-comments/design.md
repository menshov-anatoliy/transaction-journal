# Design

## Context

Комментарии трёх уровней (сделка, позиция, конструкция) редактируются в `ConstructionDetail.razor` однострочным `<input class="cell-input">` и отображаются плоским текстом (`@(_data.Comment ?? "—")`, `@(trade.Comment ?? "—")`). Хранение — свободный текст в TEXT-колонках (`Construction.Comment`, `TradeUserdata.Comment`, `PositionComment.Text`); `CommentService.NormalizeText` тримит только края строки, внутренние переносы не трогает. Мотивация — в proposal.md, требования — в specs/ui/screens.

UI-слой уже имеет паттерн «чистая функция отображения» без DI — статический класс `DisplayTime` в `TransactionJournal.Components`.

## Goals / Non-Goals

**Goals:**

- Многострочный ввод комментария на всех трёх уровнях без изменения мест редактирования и порядка сохранения.
- Отображение комментария, отрендеренного из Markdown, безопасное для пользовательского контента.
- Минимальный дифф: замена контрола и способа вывода, без изменений домена и хранилища.

**Non-Goals:**

- WYSIWYG-редактор Markdown, предпросмотр при вводе.
- Ограничение длины комментария или белые/чёрные списки MD-элементов.
- Изменения доменных правил: инерция комментариев и нормализация текста не меняются.
- Комментарии вне `ConstructionDetail.razor` (в «Входящих» и списке конструкций их нет).

## Decisions

### D1. Рендеринг — Markdig с усечённым пайплайном

Пакет Markdig (последняя стабильная) в `TransactionJournal.csproj`. Пайплайн: базовый CommonMark + `UseSoftlineBreakAsHardlineBreak()` (одиночный Enter = разрыв строки, как ждут от поля комментария) + `UseAutoLinks()`; `DisableHtml()` — сырой HTML парсится как текст и экранируется на выходе.

Альтернативы: полный HTML-пайплайн + HtmlSanitizer — вторая зависимость и большее поле атаки ради функции, которой нет; собственный конвертер — хрупко и долго. Markdig — де-факто стандарт .NET, без транзитивных зависимостей.

### D2. Рендерер — статический хелпер рядом с `DisplayTime`

Новый статический класс `CommentMarkdown` в `TransactionJournal.Components`: метод принимает `string?` и возвращает HTML-строку (`null`/пустой вход — `null`). Razor-места вывода оборачивают результат в `MarkupString`. Без DI и состояний — тот же стиль, что `DisplayTime`; тривиально тестируется unit-тестом без bUnit.

Альтернатива: компонент `CommentMarkdown.razor` — инкапсулирует `MarkupString`, но усложняет таблицы и не даёт преимуществ для одного метода.

### D3. Ввод — `<textarea>` с `@bind`

В трёх местах `ConstructionDetail.razor` (шапка, строка позиции, строка сделки) `<input class="cell-input">` заменяется на `<textarea class="cell-input" rows="4" placeholder="…"></textarea>` с тем же `@bind="_commentDraft"`; логика `BeginCommentEdit`/`Save*CommentAsync` не меняется. Кнопки сохранения/отмены остаются; дополнительно textarea обрабатывает `onkeydown`: Ctrl+Enter вызывает `Save*CommentAsync`, Enter без Ctrl вставляет перенос строки (поведение textarea по умолчанию). Чтобы Ctrl+Enter сохранял ещё не «закоммиченный» в `@bind` текст (привязка по умолчанию срабатывает на change/blur и отдала бы устаревший черновик), `@bind:event` переключается на `oninput`: черновик — локальное поле компонента, посимвольная привязка безопасна.

### D4. Хранилище и нормализация — без изменений

`NormalizeText` сохраняет внутренние переносы (тримит только края), TEXT-колонки принимают многострочный текст, миграции не нужны. Сценарий «комментарий переживает пересчёт» и инерция комментариев не затрагиваются.

### D5. Стили отображения — класс `comment-md` в `app.css`

Места вывода получают обёртку `comment-md`; стили ограничивают ширину и высоту (max-height с прокруткой в ячейках таблиц), оформляют списки, код и заголовки в тёмной теме приложения.

## Risks / Trade-offs

- [XSS через пользовательский Markdown] → `DisableHtml()` экранирует сырой HTML; unit-тест проверяет отсутствие исполняемых тегов в выходном HTML.
- [Длинный/высокий MD раздувает ячейку таблицы] → CSS-ограничение высоты с прокруткой в ячейках, полная высота — только в шапке деталей.
- [Старые комментарии с символами разметки начинают рендериться иначе] → принимается: это желаемое поведение; текст без разметки Markdown отображается практически как раньше, переносы сохраняются.
- [`@bind` на `textarea` срабатывает на blur — потеря правки при уходе без сохранения] → поведение совпадает с текущим `<input>`; не регрессия. Устаревший черновик при Ctrl+Enter исключён привязкой `@bind:event="oninput"`.

## Migration Plan

Добавить пакет Markdig, заменить контролы и места вывода, дополнить `app.css`. Миграций БД нет; откат — revert коммита. Развертывание — обычный запуск приложения.
