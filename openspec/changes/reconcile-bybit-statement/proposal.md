# Proposal

## Why

Синхронизация истории торговли из Bybit V5 API — единственный источник данных журнала, но её полнота и точность пока не подтверждены независимо от биржи. Официальная выгрузка транзакций аккаунта (AssetChangeDetails со страницы `https://www.bybit.com/ru-RU/user/assets/exportStatment`) за диапазон UTC `2026-01-01 – 2026-09-22` уже лежит в `examples\2026-01-01 до 2026-09-22` и является независимым эталоном. Нужен разовый диагностический прогон, который выявит ошибки текущего функционала синхронизации: потерянные исполнения, пропущенные delivery-записи и расхождения атрибутов загруженных записей.

## What Changes

- Добавляется диагностический тест сверки в тестовом проекте: он читает живую локальную `journal.db` (`src\TransactionJournal\App_Data`) и CSV-выгрузки из `examples\2026-01-01 до 2026-09-22`, не изменяя ни то, ни другое.
- В тестовом проекте появляется парсер CSV выгрузки AssetChangeDetails (UTA-файл) с профилем типов строк: TRADE, SETTLEMENT, DELIVERY, TRANSFER_IN/OUT и прочие.
- Сверка сопоставляет в границах диапазона дат выгрузки: строки TRADE ↔ сырые записи исполнения (`RawExecution`, категории linear и option), строки DELIVERY ↔ сырые delivery-записи (`RawDelivery`).
- Расхождения классифицируются: строка выгрузки без записи журнала (потеря синхронизации), запись журнала без строки выгрузки (лишняя запись), расхождение атрибутов сопоставленной пары (количество, цена, комиссия, сторона, время).
- Строки вне области синхронизации — SETTLEMENT (фандинг), TRANSFER_IN/OUT, операции fund-аккаунта (Earn, Deposit, Withdraw, Transfer) — попадают в сводку «вне области журнала» без отметки ошибки: журнал их не загружает по действующей спецификации `sync/bybit-history`.
- Тест пропускается, когда живая база или файлы выгрузки на машине отсутствуют (признак разового диагностического прогона), и падает с детальным отчётом по каждой классификации при наличии расхождений.
- Продуктовый код приложения не меняется: сверка — read-only инструмент тестового проекта.

## Capabilities

### New Capabilities

- `sync/bybit-statement-reconciliation`: диагностическая сверка сырых данных журнала, загруженных синхронизацией Bybit V5 API, с официальной CSV-выгрузкой транзакций Bybit AssetChangeDetails; правила сопоставления, классификация расхождений и условия запуска разового прогона.

### Modified Capabilities

- (нет: действующие требования `sync/bybit-history` не меняются — сверка только проверяет их результат)

## Impact

- `tests\TransactionJournal.Tests` — новый код: парсер выгрузки, движок сопоставления, MSTest-тест диагностического прогона; возможно фикстуры мини-фрагментов CSV для юнит-проверок парсера и сопоставления.
- `examples\2026-01-01 до 2026-09-22` — эталонные CSV используются как есть, только чтение.
- `src\TransactionJournal\App_Data\journal.db` — только чтение (SQLite открывается в read-only режиме, WAL журнала не затрагивается).
- Продуктовый код `src`, публичные API, схема БД и зависимости — без изменений.
