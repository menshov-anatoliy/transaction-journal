# Proposal

## Why

Иконочная колонка у внутреннего края панелей занимает постоянное место в развёрнутом состоянии и не несёт контента, а управление сворачиванием «последней иконкой колонки» неочевидно. Одновременно контент правой панели прижат к границе без отступов — геометрия расходится с design.pen, где контент обеих панелей вписан с отступом 12 px к краям.

## What Changes

- Развёрнутое состояние обеих панелей: иконочная колонка у внутреннего края удаляется; контент занимает всю ширину панели.
- Внизу каждой панели появляется футер, отделённый тонкой горизонтальной линией (`$divider`): единственная иконка сворачивания, выровненная по внутреннему краю (правому у левой панели, левому у правой), высота футера 44 px.
- Схлопнутое состояние обеих панелей: узкая вертикальная рейка миниатюр шириной 44 px — у левой панели миниатюры разделов меню (клик = навигация), у правой — иконочные действия контекста; кнопка разворачивания стоит строго под миниатюрами в том же потоке, без линии футера. Ширина схлопнутой левой панели: 6.5 rem → 2.75 rem.
- Иконочные действия контекста (`iconActions`) показываются только в свёрнутой рейке; API регистрации контекста не меняется.
- Единые отступы контента: 12 px по горизонтали к обоим краям обеих панелей (включая футер); вертикальные отступы — 16 px у левой панели, 14 px у правой, по design.pen. Исправление: контент правой панели во frontend получает отступы (сейчас прижат к границе).
- Нативные `title`-подсказки на миниатюрах свёрнутой рейки и кнопках сворачивания/разворачивания.
- Бейдж «Входящих» в свёрнутой рейке скрыт (как сейчас); диапазоны ширин панелей (4.25–20 / 20–40 rem) не меняются.
- design.pen обновляется как источник истины: рамка «Каркас» (футер вместо иконочных колонок) и «Схема состояний панелей» (свёрнута = рейка миниатюр); переэкспорт экрана в `design.exports\rework-panel-collapse-footer\Каркас.png`.
- **BREAKING** (UI-контракт): сценарий «сворачивание — последняя иконка иконочной колонки» заменяется на «сворачивание — кнопка в футере панели»; термин глоссария «Иконочная колонка панели» заменён терминами «Футер панели» и «Рейка миниатюр».

## Capabilities

### New Capabilities

_Нет — изменения укладываются в существующие возможности._

### Modified Capabilities

- `ui/screens`: `requirement-app-frame-navigation` — управление сворачиванием переезжает из иконочной колонки в футер панели; свёрнутое состояние описывается как рейка миниатюр с кнопкой разворачивания строго под миниатюрами; фиксируются единые отступы контента панелей (12 px к боковым краям).
- `ui/design-system`: `requirement-design-frame-resizable-panels` — каркас в design.pen изображает футер с кнопкой сворачивания у внутреннего края и рейку миниатюр в свёрнутом состоянии вместо иконочной колонки у внутреннего края.

## Impact

- **design.pen**: рамка «Каркас» (g0z20: Панель/Навигация, Панель/Контекст, узлы «Иконочная колонка»), «Схема состояний панелей» (Yh0Wo); переэкспорт `Каркас.png`.
- **frontend**: `components/layout/AppLayout.tsx`, `PanelIconColumn.tsx` (заменяется на футер и рейку миниатюр), `layout-geometry.ts` (`COLLAPSED_LEFT_WIDTH_REM`); тесты `AppLayout.test.tsx`, `context-panel.test.tsx`, `layout-geometry.test.ts`.
- **Правая панель**: контент страниц (`constructions-page`, `construction-card-page`) получает единые отступы через обёртку каркаса — регистрация страниц не меняется.
- **GLOSSARY.md**: уже обновлён («Футер панели», «Рейка миниатюр»).
- Не меняются: мобильная механика (Non-Goals), персистентность геометрии, поведение «без контекста панель скрыта», диапазоны ширин, API `useContextPanel`.
