# env-file Specification

## Purpose

Локальная конфигурация приложения через файл `.env`: значения (прежде всего учётные данные Bybit `BYBIT_API_KEY`/`BYBIT_API_SECRET`) попадают в переменные окружения процесса при запуске, не требуя настройки системных переменных машины.

## Requirements

### Requirement: Приложение загружает .env при запуске
При запуске приложение SHALL искать файл `.env`, начиная от текущего каталога и поднимаясь вверх по дереву каталогов, и SHALL загружать значения найденного файла в переменные окружения процесса до первого обращения к ним. Отсутствие файла `.env` SHALL быть штатной ситуацией: приложение продолжает работать с теми переменными, что заданы в окружении, и не сообщает об отсутствии файла как об ошибке.

Traceability ID: requirement-env-file-loaded-on-startup

#### Scenario: Значения из .env становятся переменными процесса
Traceability ID: scenario-env-values-become-process-vars
- **WHEN** файл `.env` содержит `BYBIT_API_KEY` и `BYBIT_API_SECRET`, а в окружении процесса эти переменные не заданы
- **THEN** после запуска приложения поставщик учётных данных Bybit получает ключ и секрет из `.env`
- **AND** синхронизация работает без предварительной настройки системных переменных

#### Scenario: Запуск без .env не является ошибкой
Traceability ID: scenario-missing-env-file-is-normal
- **WHEN** файла `.env` нет нигде вверх по дереву от текущего каталога
- **THEN** приложение запускается без сообщений об ошибке, связанных с отсутствием файла
- **AND** переменные окружения процесса остаются такими, какими их задала система

### Requirement: Системные переменные имеют приоритет над .env
Значение из `.env` SHALL применяться только к переменным, не заданным в окружении процесса на момент запуска приложения. Переменные, уже определённые в окружении, SHALL сохранять системное значение; `.env` SHALL их не перезаписывать.

Traceability ID: requirement-system-vars-take-precedence

#### Scenario: Системное значение не перезаписывается значением из .env
Traceability ID: scenario-system-var-wins-over-env-file
- **WHEN** переменная `BYBIT_API_KEY` задана в окружении процесса и одновременно присутствует в `.env` с другим значением
- **THEN** приложение использует системное значение переменной
- **AND** значение из `.env` игнорируется

### Requirement: Секреты остаются вне репозитория
Репозиторий SHALL содержать шаблон `.env.example` с именами переменных `BYBIT_API_KEY` и `BYBIT_API_SECRET` и заглушками вместо реальных значений. Файл `.env` с реальными значениями SHALL игнорироваться системой контроля версий и не попадать в репозиторий.

Traceability ID: requirement-env-file-stays-local

#### Scenario: Разработчик создаёт .env из шаблона
Traceability ID: scenario-env-created-from-template
- **WHEN** разработчик копирует `.env.example` в `.env` и вписывает реальный ключ и секрет
- **THEN** система контроля версий не отслеживает `.env`
- **AND** шаблон `.env.example` с заглушками остаётся в репозитории
