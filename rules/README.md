# Корпус правил: ПИ + Инструкции (v1), Опционный клуб (v2), Жупин и Базовая теория (v3)

Каноническое собрание правил торговли (см. «Правило торговли», «Корпус правил» в CONTEXT.md): декларативные YAML-данные, один файл — одна карточка AC из карты характеров базы знаний (#23), id = имени файла. Схема полей утверждена в тикете «Схема и размещение корпуса правил» (#19/#26):

- `character` — один из десяти характеров действия (закрытый справочник таксономии, #19/#24);
- `technique` — техника исполнения (например `synthetic-close`), необязательный признак;
- `clarity` — чёткость: `crisp` (прямое действие) / `fuzzy` (к решению человека);
- `scope` — область правила: `open-constructions` для открытых конструкций (#19/#25), `portfolio` для структуры личного портфеля;
- `trigger.implementation` — ключ реализации триггера в коде движка; `null` — правило не порождает подсказок и попадает в статический чек-лист сводки;
- `sources` — атрибуция происхождения: тег источника, путь файла от корня вольта Obsidian, цитаты-доказательства. Репозиторий — канон, база знаний — источник происхождения; обратной синхронизации нет.
- `conflicts_with` — необязательный список id правил, не могущих быть активными одновременно с карточкой; объявление симметрично, два активных члена пары делают корпус невалидным (см. «Политика конфликтов», #19/#36);
- `retired.reason` / `superseded_by` — при `status: retired`: причина снятия с канона (например `superseded`) и замещающая карточка, если есть.

Каталог читается движком агента при каждом проходе; замена файлов (git pull / копирование) действует со следующего прохода без пересборки и перезапуска приложения (#26).

## Политика конфликтов

<!-- Конфликт правил — ошибка дистилляции, не рантайма: движок не разрешает противоречий.
Traceability: openspec:hints/rules-corpus#requirement-corpus-declared-conflicts-validated
Traceability: openspec:hints/engine-pass#requirement-engine-no-runtime-conflict-resolution
Traceability: issue:#36
-->
Конфликт разрешает куратор (владелец) при дистилляции: в валидном корпусе нет двух активных карточек объявленной конфликтной пары. Движок ничего не разрешает и не маркирует: сработавшие на одном субъекте подсказки входят в сводку как есть.

Приоритет источников — лестница-руководство куратора (не код):

1. **ЛИЧ** — актуальный синтез владельца; высший приоритет.
2. **Профильность области правила**: интрадей → ПИ, опционные конструкции → ОК.
3. **Свежесть курса** того же источника: новый курс вытесняет старый.
4. **Частное над общим**: правило с более узким условием предпочтительнее общего.

Вытеснение версий одного источника — двумя механизмами:

- значение, никогда не бывшее каноном, в корпус не включается; оно остаётся цитатой в `sources` карточки с комментарием (пример — ac-01: старые лимиты 20/40%);
- правило, бывшее каноном и порождавшее подсказки, переводится в `status: retired` с `retired.reason: superseded` и, при наличии замены, `superseded_by`; retired-карточка не исполняется, но гасит живые записи.

Объявление конфликтной пары — необязательное поле `conflicts_with`: список id карточек, не могущих быть активными одновременно с данной. Объявление трактуется симметрично; корпус с двумя активными членами пары невалиден и останавливает проход агрегированной ошибкой; пара с retired-карточкой валидна и документирует известное напряжение источников для будущих дистилляций.
