# openspec-apply-all

Линейный конвейер исполнения задач одного OpenSpec change. В отличие от `implement-spec` здесь нет графа тикетов, worktree и integration-ветки: задачи идут строго по списку `tasks.md`, по одной, через саб-агентов; каждая завершённая задача — один коммит в **текущей ветке**, в которой запущен основной агент. Архивация change не выполняется. Пуш и PR не выполняются.

## Префлайт

1. Определи change: аргумент запуска; если не задан и активный change ровно один — берёшь его; если несколько — перечисли и спроси. Активные change — каталоги в `openspec\changes\` с файлом `tasks.md`, кроме `archive`.
2. Убедись, что репозиторий в git-ветке и worktree чист (`git status --porcelain` пуст). Грязный worktree — остановись и перечисли изменённые файлы: незакоммиченные правки не должны утекать в задачные коммиты.
3. Прочитай `tasks.md`: задачи — только строки `- [ ]` в порядке следования в файле (порядок секций и пометки «(после N)» уже учтены автором файла). Уже отмеченные `[x]` пропускаются — это возобновление прерванного прогона. Незакрытых задач нет — сообщи и завершись.
4. Напечатай план: change, ветка, число незакрытых задач, режим «швы тестов выбирают саб-агенты по артефактам change» — и **стартуй немедленно**, без подтверждающего вопроса: запуск скилла и есть согласие.

## Цикл: одна задача — один саб-агент — один коммит

Для каждой задачи по порядку:

1. Выведи `▶ <change> <номер задачи>`.

2. Запусти **одного** саб-агента (general-purpose, синхронно; следующая задача — только после завершения предыдущей). Контекст передавай **указателями**, без пересказа содержания:

   - путь change: `openspec/changes/<change>/` — `proposal.md`, `design.md`, `tasks.md`, `specs/`;
   - номер и текст конкретной задачи;
   - `AGENTS.md`, `.github/prompts/formatting.prompt.md`, `.github/prompts/unittests.prompt.md`;
   - хэши коммитов прогона (список ведёт оркестратор).

   Требования к саб-агенту:

   - реализовать задачу целиком; не коммитить и не менять `tasks.md` — это делает оркестратор;
   - вызвать Skill `tdd`, если у задачи есть кодовые швы; не-кодовая задача (CI, docs, конфигурация) — отработать без tdd и обосновать пропуск в отчёте;
   - швы тестов выбрать самостоятельно по артефактам change (design/specs) и зафиксировать выбор в отчёте — отдельное согласование швов с пользователем в конвейере не выполняется;
   - выполнить traceability-разметку по «Проверить:»-ссылкам строки задачи: строки `Traceability: <target>` (по одной цели на строку) плюс человекочитаемый русский комментарий у размеченного блока;
   - перед отчётом «готово» собрать решение и прогнать затронутые тесты; красные тесты или ошибки сборки — сообщить о провале, а не о готовности.

3. Провал саб-агента (сборка или тесты красные, задача невыполнима или непонятна) — **останови конвейер** и доложи: задача, причина, список уже сделанных коммитов. Без авто-ретраев и без пропуска задач: скип ломает зависимости «(после N)».

4. Успех — пометь задачу `[x]` в `tasks.md` и сделай **один коммит**: изменения кода плюс обновлённый `tasks.md`. Сообщение:

   - subject — Conventional Commits по сути задачи; язык — по сути задачи, жёсткого правила нет;
   - body — строка `Task: <change>#<номер задачи>` и выбранные саб-агентом швы тестов;
   - trailer `refs #N`, если в имени текущей ветки есть номер задачи;
   - trailer `Co-authored-by: Copilot <223556219+Copilot@users.noreply.github.com>`.

5. Выведи `✔ <номер задачи> → <hash>` и переходи к следующей задаче.

## Хвост прогона — после последней задачи

1. Полный прогон тест-suite. Красный — стоп с отчётом, как у провала задачи.
2. Вызови Skill `code-review` по диффу прогона (от первого коммита конвейера до текущего состояния).
3. Один fix-саб-агент устраняет все findings ревью; правки — одним коммитом `refactor:` (формат сообщения — как у задачных, без строки `Task:`).
4. Финальный отчёт: change, список задачных коммитов, итоги code-review. На этом конвейер останавливается. Архивацию change не выполняй.

## Статусы

Минимум шума: строка на старт задачи, строка на её коммит, финальный отчёт. Промежуточные подробности живут в отчётах саб-агентов, коммитах и финальном отчёте.
